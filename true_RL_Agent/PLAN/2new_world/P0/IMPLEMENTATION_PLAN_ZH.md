## 执行顺序

1. **记录基线。** 保存源码/配置/当前文档摘要、既有修改、活动格子与实际入口、正式会话及 reference/current-best 的位置与哈希。运行本地完整 unittest 基线；记录生产 Python 与录像 Python 的包/源码可执行性，不启动仿真或 provider。
2. **形成具体清单。** 逐目录统计文件数、字节数及 checkpoint；从产品代码、测试、协议、报告和实际 receipt 检查引用。分为删除、必要保留、后续结构变更后删除、范围外四类。55 项遗留问题只记录编号、当前处置与承接 Phase，不复制背景。
3. **第一批删除。** 清理未引用的本地审计/干运行副本、缓存、失效占位物和明确无消费者的一次性脚本。若必要合同测试仍依赖旧入口，先明确它保护的行为；不为降低失败数而删测试，也不增加兼容包装层。复核中发现的 4 处测试输出改用自动清理的临时目录，避免测试再次污染项目输出树；保持原断言和产品语义。
4. **第二批删除。** 对服务器已结束实验删除未被权威 receipt、保留文档或诊断引用的中间模型。默认保留 `best.pt`、被引用的末态/比较模型和真实失败证据；正式 15 代输出涉及冻结 cost/resource accounting，先验证其删除兼容性，不能因文件名是中间模型就删除。一次性候选清单审核后执行，不新增产品 retention 框架。
5. **收敛入口与验收。** README 提供当前系统的简明导航；保留旧语义/入口的历史说明与当前生产路径明确区分。运行清理后全量测试、必要环境定向测试、引用/哈希闭包校验、正式产物只读检查以及改动审查。记录实际删除数量与字节、剩余边界及后续预算分池。
