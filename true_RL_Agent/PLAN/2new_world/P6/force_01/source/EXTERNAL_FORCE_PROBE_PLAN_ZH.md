# F：两机器人现有 reference 的外力推搡诊断

2026-09-22。用户授权“改成外力推搡看看reference成功率，包括Go2和G1，优先Go2，reference ckpt无需重新训练”。本次先 Go2 D checkpoint，再 G1 已资格 checkpoint；只做公开开发评测，不改变旧训练、协议或资格。

## 固定条件

- 每个机器人仅一个外力 arm，沿用各自原公开 dev 的三个种子、每种子64环境及 low/medium/high/repeated 分层，合计384 episode。Go2 使用10042/10043/10044；G1使用1000010000/1000010001/1000010002。无额外幅值、方向、作用点或时序网格。
- 沿用各自原速度扰动幅值、方向、原不重叠双推时刻及恢复/跌倒/越界标准。Go2来源是D的×2协议，G1来源是新资格×1.5协议；两机器人绝对成功率不当作等难度排名。
- 改为水平矩形外力脉冲：T=sqrt(L/g)，持续时间τ=ceil(T/control_dt)×control_dt；每env实际机器人全部link质量之和为M，F=M×原Δv/τ。方向在世界系固定，名义外加冲量为M×原Δv。这不保证实测速度增量相同，接触/关节反力及有限时长会改变响应。
- 作用在原binding的base角色所指躯干link的质心：Go2为base，G1为torso_link。采用已有语义角色，不引入机器人名称分支来解释施力。该link质心不是整机质心；不额外指定偏心位置或扭矩，不宣称无整体转动效应。
- 每个物理子步通过当前后端的instantaneous wrench composer写入力，positions=None、is_global=True，再由原write_data_to_sim提交到PhysX。关闭原速度扰动事件。保存PhysX调用接收到的力/力矩、实际子步、躯干位姿和施力结束后的零输入；不以root Δv相等作为外力注入判据。
- 第一推从原scheduled control step之后的物理区间开始；停止后的下一control状态样本才可累计恢复。每次脉冲独立要求完整连续驻留、原恢复窗口、全程无跌倒/越界且episode末态稳定。提前跌倒保留分母，允许未开始或部分完成的后续脉冲；真实坏注入仍使工程证据无效。

## 实施与验收

仅增加PLAN内诊断入口与小型评分器，复用原环境、角色绑定、策略加载、物理后端和owned process；原manifest只证明训练来源及策略ABI，新外力定义单独冻结身份。恢复位置/xyzw姿态/速度逐control步在reset前保存；每物理子步保存送入PhysX的力，以独立离线复算结果和积分冲量。

目标CPU预检通过后冻结实际参数、入口及checkpoint/环境hash，再按Go2→G1顺序执行；各一次作业，单作业上限1800秒，无训练/holdout/provider，无根据成功率追加运行。技术错误保留产物、定位修正后另记执行身份，不能把失败回执覆写为通过。

报告每机器人三seed计数、四层计数、失败原因、实际质量/牛顿/持续时间/冲量，与旧速度扰动成绩分开比较。少量CPU测试覆盖评分关键边界；审阅实际目标API，验证物理子步注入和清零，检查原始轨迹有限、首episode闭合以及既有checkpoint/完整15rounds保护。固定checkpoint的新机制诊断不替代随机初始化的新reference资格；本次不自动把P6标GO。
