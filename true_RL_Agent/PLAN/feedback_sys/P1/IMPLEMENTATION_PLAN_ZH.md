同一训练/评估证据经过公开投影、ledger重放、记忆及作者输入后，身份、分母、缺失状态和数值保持一致。绑定的runner回执是来源，任务adapter解释任务含义，共享层负责身份和生命周期。生产代码和测试均位于src/tests，不能读取PLAN。

保留现有receipt、phase adapter、PublicContextBuilder和journal，不另建证据服务、数据库、第二套事件日志或通用任务词表。success、接受gate、奖励ABI及训练条件不变。行为词表、时序recorder、查询和视觉属于后续Phase。

## 已确认问题与实施顺序

1. **先收敛P0七项遗留。** 删除旧token估算派生副本与孤儿报告；修正移动后的链接；采集器停止生成冗余tar；source目录统一仓库相对路径；人工评注改为数据fixture；补实际parent的回执/权重证据及训练manifest差异。原始receipt和source_baseline保持历史事实，P0校验不再要求后续生产源码永不变化。
2. **phase投影回到绑定回执。** 核对live构建与replay消费入口；从已绑定的phase result调用同一task-owned公开投影。ledger中的public_summary是派生表示，不能成为可独立修改的真值。成功、失败、未选中与混合sibling都走同一来源。
3. **缺测不再补零。** 当前RuntimeActivationEvidence把None与实测零转成同一字典，已用最小反例复现。统一保留未知计数/未知贡献；生产者补已知的执行步数和声明term数量，以区分缺runtime、无term、零执行与执行后的零值。裁剪遗漏沿用既有omission回执。任务投影与记忆消费相同含义，机制gate不因信息更丰富而改接受规则。
4. **投影不污染真值。** task projector只拿自己的输入副本，身份校验与源码/探索历史仍使用调用前的已验证记录。检查最终序列化、修复帧及最小投影是否保留身份/缺失含义；已有正确路径通过回归保留。
5. **非Stair/Push验证。** 用测试内最小任务adapter携带不含两任务公式的公开证据，经现有生产投影/上下文/provider请求序列化，证明共享接口可以承载后续T证据，不新增生产玩具任务。

本地Codex源码只作为架构参考：借鉴权威事件/记录与派生视图分离、可重放上下文和明确裁剪状态；具体适用文件与取舍记录在开发日志。不会复制其平台、工具体系或多层防御。

- 对真实绑定receipt改public_summary或串用另一trial时，作者不获得伪事实；正常live与重放公开输出一致，重复投影不累积改写。
- 首次reference、accepted、rejected、未训练、未选择、混合sibling的来源和分母闭合。公开dev与accept/sealed保持既有权限；用现有回归加与本次改动直接相关的反例，不扩建泛化攻击集。
- 缺runtime/缺字段与实测0、无term与未执行、执行后的0与预算省略可区分，在task反馈、public history和记忆压缩后保持；声明加载不冒充已经执行。
- adapter不能修改已验证历史的身份/决策或影响随后源码解析；最小第三任务走相同接口，共享层无Stair/Push指标公式。
- 原有相关CPU回归通过；新增测试必须验证真实失败模式或端到端不变量。生产src不依赖PLAN，P0脚本从原件可重跑，改动范围及实际测试命令可复核。
