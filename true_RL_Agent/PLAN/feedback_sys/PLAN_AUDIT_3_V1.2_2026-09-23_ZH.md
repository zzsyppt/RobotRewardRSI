# v1.2 计划审计：反馈系统是否可行、高效，配套模块是否合理

日期：2026-09-23。对象：[FEEDBACK_SYSTEM_UPGRADE_PLAN_ZH.md](FEEDBACK_SYSTEM_UPGRADE_PLAN_ZH.md) v1.2 与 [审计处理记录](AUDIT_RESPONSE_AND_PLAN_REVISION_2026-09-23_ZH.md)。
按用户要求，本文只看三件事：升级后的反馈系统能不能做出来并给作者有用的证据；价值信号来得够不够早、证据够不够密；顺带升级的模块是否该做、边界是否合理。工程细节、鲁棒性和成本只在影响这三件事时提及。依据是当前源码、15 代正式结果和本轮复核的事实（第 5 节）。没有改运行代码，没有启动实验。

## 0. 结论

1. **反馈系统本体可行，v1.2 的基础判断准确。** 四个合同、L0–L3 分层、三个 L2 对象、可操作性映射、事前预测与固定规则裁决，是这个循环缺的东西，且都能从现有采集和产物上做出来。v1.2 对现状的描述（原始步在内存、逐回合 facts 已落盘、Push 接触传感器关闭、奖励路径可读关节）经本轮核实全部成立。
2. **Stair 最小闭环的数据与案例已经齐备。** 首个问题"终局禁触前出现了哪些可测事件，成功组是否也出现"定义正确；c6 一场运行就有 22 个不同 checkpoint 的已训练候选加 reference 都带 public-dev 证据，足够 12–24 个离线案例。缺的只是持久化逐步数据、带符号姿态、逐脚事件起止，以及画像/差分投影。
3. **高效性的主要风险不在证据本身，而在从离线价值门到真实闭环之间的距离。** 早期路径 0→1→2-min→3-min 之后，要经过 4、5、8、9 才有第一次真实的"预测被裁决"。建议在 3-min 之后加一个 4 个候选规模的真实小探针，先看作者是否真的使用差分、预测能否被裁决，再建查询服务与完整记忆。
4. **3-min 价值门的测量设计要补两处。** 每案例每臂只生成一次会被作者采样噪声淹没；盲评的真值必须来自 L0/L1 的独立核查而不是 T 的文本。默认工作集的组成与去重也要在 Phase 3 卡里定死，否则"同预算"做不到。
5. **配套模块方向合理，但两个模块缺进入触发。** Phase 4 证据查询应以"被预算省略但盲评认为必需的证据比例"为触发；Phase 1 全量回归对离线研究不是必需，可缩到离线 payload 的身份与白名单检查。视觉、检索保持可选是对的。
6. **裁决层缺两条默认规则。** 预测未支持时应固定三分归因（奖励项未激活 / 激活但行为未变 / 行为变了但成功未变）；容差默认取 parent 在配对 seed 间的离散度。这两条决定"预测核对"能否产生可学习的经验，而不只是对错。

## 1. 反馈系统本体：可行性

### 1.1 Stair 最小闭环

| 需要什么 | 现状 | 判断 |
|---|---|---|
| 逐步时序 | `_execute_stair_seed_rollout` 已把原始步（含 joint_pos、逐支撑体位置/速度/接触力、逐禁触体力）和 transition 物化到 host，只是不落盘 | 可行，Phase 2-min 是写盘与 manifest |
| 逐回合事实 | 当前套卷即校准套卷，public-dev/accept summary 已含 primary、steps、progress、flags | 已有，首个问题的共现表今天可算 |
| 带符号姿态、逐脚起止、禁触层 | decoder 在 599–601 行取绝对值并把禁触折成布尔；原始步保留全部信息 | 可行，v1.2 要求加字段而非改 abs，正确 |
| 离线案例 | 15 代正式结果 CSV 中 generation 阶段 public-dev 有 23 行、22 个不同 checkpoint、23 个候选 id，加 reference | 足够；同一 session 内谱系相关，v1.2 已说明不能宣称独立泛化 |
| 首个问题的窗口对齐 | v1.2 说"按外部扰动或任务事件对齐" | 建议明确为按"base 跨越第 k 级立面"对齐：台阶几何已知，成功组与失败组在同一级的前 N 步可比 |

三个 L2 对象都是确定性投影，不引入新真值，这是对的。EpisodeTranscript 不必为 216 回合全部生成到提示词，画像与差分才是默认工作集；这点 v1.2 §3.1 说了"有限代表样本不代替总体统计"，但默认组成没有定（见 2.4）。

### 1.2 Push

`apply_physical_push_overlay` 把 `scene.contact_forces` 设为 None，plugin 的角色要求只有 base，评估运行时只读 root 位姿；奖励路径确实读 joint_pos/joint_vel。因此 v1.2 把逐脚 profile 推迟到"先具备有效接触/位置及 task binding"是对的，逐脚不是免费日志扩展。

缺一条：Stair 有首个问题，Push 没有。建议 Phase 2/3 为 Push 也登记一个只依赖已有或低成本字段的首个问题，例如"not_recovered 回合里 dwell 被哪个稳定子条件反复打断、打断发生在扰动后多久，与 success_recovered 对照"。这只需要逐步五个子条件布尔量，不需要脚部传感器。

### 1.3 预测核对的前提

BehaviorDiff 要求 parent 在同一 cohort 上有同版 recorder 产出的画像。已接受的 parent 往往在 Phase 2 之前评测过，没有逐步档案。v1.2 §7 提到"parent 复核"计入预算，但 Phase 5/8 应写明：parent 画像缺失或 recorder 版本不一致时裁决结果为 `not_tested`，且 parent 画像每个 head 只算一次并复用。否则第一批预测都会落在无对照状态。

## 2. 高效性：价值信号来得够不够早

### 2.1 早期路径的顺序

0→1→2-min→3-min 比 v1.1 的"到 Phase 9 才有信号"好得多。但 Phase 1 的完整回归矩阵（live/replay/memory/payload 四处一致、假 adapter、canary）是为证据进入真实作者准备的；3-min 是冻结案例上的离线盲评，结果不回流任何决策。建议 Phase 1 拆成两档：离线档只检查 T payload 的身份绑定与 public-dev 白名单；完整档在 Phase 8 之前完成。这样 3-min 的信号能提前几周，而安全边界并没有被绕过。

### 2.2 3-min 门的测量噪声

门的判据是"在至少两个过程类别上 T 减少 A 的关键误判或补足必要证据"。两点会让这个判据失真：

- 作者的生成本身有采样方差。同一案例同一证据，两次生成可能给出不同机制。建议每案例每臂生成 2–3 次，按多数或全部一致计分，或固定 provider seed 并记录可复现性。
- "关键误判"的真值不能来自 T 自己的文本。v1.2 已写"不能仅用投影器自己产生的阶段标签证明 LLM 有用"，应进一步要求盲评者用 L0/L1 的只读时间轴独立核对，再判断 A、T 输出。

### 2.3 从离线到真实闭环的距离

3-min 通过后，v1.2 的顺序是 4→5→8→9→10。第一次真实的"预测被裁决、作者下一代是否使用差分"要到 Phase 10，中间是查询服务、记忆扩展、状态机接入和一个盲评矩阵。反馈系统的核心价值恰恰在这个真实回路里，而不在离线阅读质量。

建议在 3-min 之后加一个真实小探针：1 对 session、2 代、2 lane，共 4 个候选，作者用 T 反馈并输出预测 sidecar，裁决先手工按冻结规则做。按 15 代结果，24 次训练加评测共 45.9 GPU 小时，4 个候选约 8 GPU 小时以内。它回答三个问题：作者是否引用差分、预测是否可裁决、第二代是否改变了行为而不只是分数。这三个答案决定 Phase 4/5 该建多大，比先建完再测便宜。它不是 Phase 10 的替代，结果不进入任何效应样本。

### 2.4 默认工作集的组成

v1.2 说 L2 是"作者默认工作集"，同时要求 A/T"同预算"。当前 `public_feedback_summary` 约 20 KB、历史约 23 KB，静态合同约 39 KB。不删冗余就加不进画像与差分。Phase 3 卡应写死：

- 默认给什么：按 stratum 的 BehaviorProfile（主失败组与成功组对照、分母、覆盖）、相对 parent 的 BehaviorDiff、2–4 条确定性选出的代表 transcript（最差、典型、成功、近成功）。
- 同时删什么：现有条目里与画像重复的 diagnostic_flag_rates、historical comparison 的展开形式。
- 上限多少：以 token 计，Phase 0 校准后的值。

这属于设计而非工程细节，因为它决定 T 臂到底比 A 臂多看了什么。

### 2.5 裁决的两条默认规则

预测核对若只输出支持/反驳，作者学到的只是对错。两条规则能让它产生可用经验：

- 三分归因：未支持时区分"奖励项在相关地形上未激活"（运行时激活摘要已有）、"激活但目标行为指标未变"（BehaviorDiff）、"行为指标变了但成功未变"（分数）。三种情况对应的下一步完全不同。
- 容差默认值：任务层需要给每个指标定"最小有意义变化"。默认取 parent 在配对 seed 间的离散度，低于它记 `inconclusive`。这避免任意阈值，也避免把噪声当支持。

## 3. 配套模块是否合理

| 模块 | 判断 | 建议 |
|---|---|---|
| Phase 1 契约回归 | 必要，但对离线研究过重 | 分离线档与完整档，见 2.1 |
| Phase 4 证据查询 | 方向合理，边界正确（只读 public-dev、不另起服务）；缺进入触发 | 触发定为：3-min 盲评中"证据存在于 L0/L1 但因预算未进入 T payload、且盲评者认为影响判断"的案例比例超过事前值。低于该值时用更好的默认选择代替查询接口 |
| Phase 5 预测记忆与预算 | 核心模块，不是顺带；session 内默认正确；"必需核心＋可变证据池"正确 | 补三分归因与容差默认规则；parent 画像复用与 `not_tested` 条件 |
| Phase 6 媒体 | 可选正确；派生图作为候选表达而非默认最优，接受；相机可辨性作为前置门正确 | DeepSeek 官方页现写明 `deepseek-flash` 支持图像、旧别名由 V4.1-Flash 服务，Visual Analyst 可与作者同 provider，选型问题变小；本地 provider 仍需实现 image block |
| Phase 7 视觉核对 | 可选正确；不执行模型生成规则正确 | 无 |
| Phase 8 作者闭环 | 答复预留取代独立 +1，合理 | 真实小探针可提前验证预留逻辑 |
| Phase 9 选型 | 矩阵按 R/V 触发缩小，合理 | A/T 必做；其余按触发 |
| Phase 10/11 | 探索性默认、主终点保留 current-best、次要指标承担信息，可接受 | 次要指标里"预测支持率"应按候选而非按 session 报分母 |

## 4. 建议修改（按优先级）

1. 3-min 之后加 4 个候选的真实小探针，手工裁决，结果只用于决定 Phase 4/5 规模。
2. Phase 3 卡写死默认工作集组成、删除项与 token 上限。
3. Phase 5 加三分归因与容差默认规则；写明 parent 画像复用与 `not_tested` 条件。
4. Phase 4 加进入触发；Phase 1 拆离线档与完整档。
5. 3-min 每案例每臂 2–3 次生成；盲评真值来自 L0/L1 独立核查。
6. Stair 首个问题按"跨越第 k 级"对齐窗口；Push 登记首个问题（dwell 打断原因对照）。
