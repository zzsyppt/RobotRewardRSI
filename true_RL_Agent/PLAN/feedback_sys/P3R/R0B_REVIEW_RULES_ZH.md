# R.0-b 模型评阅口径（生成前登记）

本轮用户明确授权 `model_review`。只评开发探针的机制对应与行动相关性，不授予 P3-R 正式价值 PASS。四变体各两次、所有终态纳入；不拿旧 P3 提案补空缺。

## 评阅材料与边界

评阅者使用打乱顺序的匿名提案、实际初次/最终输入、候选与父源码、事前登记的案例事实及可定位原始证据。变体映射单独保留；格式可能暴露输入条件，盲化有限。每案例作为一个小批次核对，避免逐条多模型投票。记录评阅者来源、可见范围与工具核对；如果后端模型版本没有回执，只写实际可知的模型身份，不补造版本。

先将提案拆为可测事实、代码效果陈述、机制假说和未来预测。随后核对该作者实际收到的材料，再对照完整档案。额外档案可以否定客观陈述，但不能倒算成作者已见依据。旧 rationale 仅表示旧提案。

数值引用、分母、事件/回合标识逐条定位；代码陈述核对原始常数、项权重、裁剪和步长，必要时用有限 CPU 输入计算。符号串/数字在输入中出现只证明可定位，不能证明命题成立。检查结果保留具体字段或代码式子；未核项目写未核，不能用空错误列表冒充零错误。原始数字与结构使用脚本核对，语义由明确标记的模型评阅完成。

## 只判断两项

**机制对应：是 / 否 / 不可判。** 判断“提议改变的控制/奖励机制是否针对已登记的可观察失败形态，并与现有证据相容”。“是”不代表已证明训练根因或修改有效。档案直接矛盾为“否”；缺乏对应关系或关键观测为“不可判”。已经会迈步不能否定“步幅或时机可能不够”；一次成功/失败视频不能证明未训练修改有效或无效。不能用“该奖励已有类似项”直接否定一个可检验的机制改动。

**行动相关性：0 / 1 / 2。**

- 0：没用到相关过程依据，或用错过程/分组/时窗；机制与改动无法建立对应。
- 1：引用了相关数字或结果，但修改主要依赖泛化先验；没有说明过程中的哪一变化/对照支持这项选择，或者代码没有兑现该选择。
- 2：明确引用正确且在实际输入中的过程关系（先后、持续、恢复后再失稳、相容正反证等），提出相容且待验证的解释，代码将该解释落在授权单机制改动上，并给出可检验的过程预测。无需长篇叙事或声称已证实因果。

短回答不会自动得高分；长回答也不因细节多而加分。同一规则对 A/T0/Tc-num/Tc-vis 使用。合理但无实验证明的假说保持待验证；把假说冒充观测、数字算错、代码与描述矛盾则单列可复核硬错误。

## 固定出口

一个变体有效：至少两个不同案例，各至少一次生成同时满足 **行动相关性 2、机制对应“是”、已完成事实与代码核对且硬错误 0**。同案两次不算两个案例。未核完不是零错误；无候选保留分母，不分配虚构语义分数。

A/T0 为同轮基线，Tc-num/Tc-vis 为开发参照。按 Phase 计划的预定分流表决定后续投入；本次结果不能宣布人类验收、正式价值门、真实训练收益或生产视觉已接入。后续正式 R.4 仍需新来源、独立冻结和原质量阈值。
