## 实施单元与源头边界

1. **Push自动过程报告。** 从现有档案产生本次扰动锚点、首帧/峰值及时间、相对该次注入的净位移、稳定条件变化、驻留确认与再失稳、最终稳定；未执行事件和观察截断单列。默认12KiB中优先保留主导失败及相容成功比较，完整分母不随展示变化。无逐脚观测就不输出步数、落脚、踝髋策略。
2. **Stair自动过程报告。** 增补已有测量可以支持的方向、姿态变化、前进/回退，以及带身体和持续时间的无载低运动事实；避免把代理量写成滑动、冻结或碰撞机制。修正仅按中位时长选例的代表性局限。默认8KiB保留主要过程和匹配成功反证；无法覆盖的部分明确标出。
3. **版本与消费者一并收敛。** 新完整派生、公共视图及差分使用一致版本/定义，旧版本不被静默补算。采集字段不足时明确missing，禁止补零或把未知说成未发生。成功规则、奖励ABI、资格和接受规则保持原定义。身体、事件、选择均归任务代码；通用层继续只管容量、必留和生命周期。
4. **新诊断cohort的最小入口。** 为独立确认准备公开诊断用途和任务拥有的seed namespace，复用现有runner、档案绑定与phase封存。保持既有资格及正式/pilot/final的历史cohort不变，不开放未承诺到hash的任意seed，不合并新公开诊断与旧sealed来伪造资格。生产不得引用PLAN或本阶段名。

任务实现先在原开发档案与少量明确反例上验证，再冻结最终代码。两任务并行，各自持有行为模块；诊断cohort改动与其分离。没有必要不增加服务、DSL、传感器、作者调用或新恢复机制。
