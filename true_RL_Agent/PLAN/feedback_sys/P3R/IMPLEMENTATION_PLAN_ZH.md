## 对 v1.1 的实施解释与必要校正

1. **R.0-a先固定一套设置，不进行隐式模型排名。** high、32768、原请求模型名称与相同输入上限；empty-final关闭thinking只影响重试，不能拿它提高首次完成率。8个首包是冻结的四个R.0-b焦点×A/T。未达门不追加调用刷完成率，先保留结果并处理必要的作者前提决策。
2. 首次完成指收到完整final并满足作者响应合同；合法source_request也是完整响应。另报直接候选产出、静态核验及repair数量，不能把正常源码查询、输出耗尽和候选代码错误混为一种失败。该门衡量可用运行状态，不证明推理质量。
3. R.0-b默认只执行32个机会，不启用更强作者模型、不提前3-live。v1.1中的“32+4强模型+重跑整套32”无法装入40机会，不能自动执行该组合；若结果确需改作者后复测，先明确新配置与剩余机会，超出本轮卡则停止扩展并提交具体分流结果。
4. Tc-num/Tc-vis可以超过生产8/12KiB视图，但总请求仍受同一个40k输入上限及统一输出/尝试/费用约束。Tc-vis是已核对视觉观察的文本补充，不是实际图像输入，更不能宣称已经接入生产视觉。
5. R.3允许分批发现问题，但最终PASS仍须有24个未参与该最终版本调整的确认回合。若首批12个用于修正，它们转开发集，剩余12个不足以完成原最低规模；须在预算内另冻结12个，不能把开发与确认各12个混成24个PASS。
6. 原v1.1关于“更大输入导致耗尽”“只有052证明可行”的陈述仅作待验证解释。现有回执支持两臂的耗尽/修复差异，不单独证明因果或唯一有效提案。新探针不以这些叙述作为真值。
