# 过程语义、未知情况与多模态：下一步设计建议

2026-09-29。供用户修订主计划；本文件不启动开发或实验。

## 建设决定与验收对象

建议明确采用“有证据支撑的过程反馈”作为产品能力，不再以追加作者 A/T 证明其存在价值作为建设前置条件。当前旧实验并未证明作者质量改善，更未证明训练收益，历史结论保持。以后若要公开声称收益，再用对应实验回答；目前投入用于把信息提供正确。

仍须验收四件事：描述忠实，重要过程未被漏掉，未知和来源冲突表达正确，作者实际收到的内容没有被裁剪/修复丢失。加入图像同样应验证时间与身份绑定、可见内容及请求投递。它们都是功能正确性，不需要再通过几十份提案比“谁更好”。

## 核心表达：测量与视觉观察共同描述过程

保留四个简单层次，不建立庞大的行为本体或强制阶段状态机：

1. **测量事实。** 时间、姿态、速度、部位、实际扰动、接触信号及原任务结局。注明单位、坐标系和有效范围。测量也是有定义的通道，例如脚参考点的运动不等于整条腿的关节构型。
2. **过程事实。** 从这些量得到上升/回退、持续、反复、同一部位上的变化、恢复后再失稳、先后或重叠。每个片段保留来源和时间窗；持续条件起始、确认时刻、观察结束分开。规则只声明它真正测到的条件。
3. **视觉观察与描述性名称。** 在可辨认画面中补充身体形态和空间关系，例如躯干翻转、腿明显弯曲、身体接近台阶。说明所见帧与不可见部分。已由足够测量支持的描述可成为任务内正式标签；仅由视觉支持的新说法保持视觉来源，不伪装成数值规则输出。
4. **解释与干预假说。** 作者据以上信息提出“可能为什么”和“改什么、预期什么变化”。与事实分开，不把合理推测变成诊断真值，也不要求反馈先推断训练根因才能有用。

“高层”指把有关联的事实组织成读得懂的行为过程，不等于更多专业术语。例如“完成驻留后，平移速度再次越界，终局未稳定”是可验证高层过程；“策略不懂恢复”没有足够定位信息。“低进展与同一脚无载低运动重叠”可被测量支持；“该腿冻结导致失败”增加了状态和因果断言，需要更多证据。

## 没见过的新语义如何描述

不以是否命中已有标签决定有没有内容可说，按三个情况处理：

- **量已有、组合未见：**直接表达时间片段及组合。比如前进减慢、躯干姿态持续改变、左右脚运动不对称同时出现；暂时没有行为名称也可提供有用证据。可用普通语言组合，但每个子句须能定位到量或帧。
- **数值难表达、画面可见：**保存限定时窗的开放视觉观察。允许“可见一侧腿比另一侧更伸展”这样的新描述；没有关节量或遮挡时，不自动升级为精确关节策略。新名称只是可撤回的描述，不自动进入判定规则。
- **两者都不足：**具体说出缺口，例如看不到脚与台阶的相对运动，无法区分摆动停止和视觉遮挡。保留已知部分，不能把整段压成 unknown，也不能写“没有异常”。

为减少规则看不见的过程被永远忽略，选取窗口时除了已触发事件，还需少量全程分散采样、规则阴性片段及成功对照。覆盖范围写清楚；有限抽样不是能发现所有新行为的检测器。暂不增加专用 OOD 网络、自动本体扩展、在线学规则或异常分数平台。

只有当某个新描述反复影响诊断，而且能给出稳定的测量定义及少量困难反例，才把它纳入对应任务代码。新规则有版本，旧记录不静默重命名。

## 多模态怎么接入

数值负责精确量、全回合覆盖和分组统计；画面负责难用现有通道表达的形态、空间关系以及发现遗漏。两者对齐到同一 episode、身体和时间窗后共同展示，而不是先把所有画面压成“翻倒/卡住”一个词。

最小可行流程建议如下：

1. 任务从全程资料选择少数有用窗口，保留前因、变化、后续，而非只选最后一帧；同时保留成功或规则阴性对照。按时间去重，避免同一动作堆很多近似帧。
2. 数值片段和对应帧/短片共享证据引用。身份、seed、checkpoint 一致不意味着重放逐步同轨；若不是同一次记录且没有轨迹对齐证明，明确作为另一次重放观察，不能把其帧与原数值逐步拼成一条事实。
3. 有视觉能力的模型实际接收少量图像，先输出可定位的视觉观察，再与数值对照。若作者仍是纯文本模型，可由独立视觉组件提供这些观察及引用；这属于视觉派生文本，不能声称作者直接看过视频。视觉组件能力不足或画面不可见时如实降级。
4. 一致之处可以压缩成过程描述；冲突处保留两边及范围，不进行“哪个模型更自信就选哪个”的融合。检查时间、坐标系、遮挡和信号定义通常比增加一轮模型投票更有用。

派生曲线也是可用的视觉输入，但它呈现的是已有测量，不是新的独立证据。原生画面不能凭视觉猜精确力、摩擦或训练因果。不要先建设多摄像头平台、开放视频检索服务或强制每次全视频理解；先把少数必要片段正确送到接收者。

## 粒度、上下文与记忆

作者默认先收到一份短工作集，固定包含：任务结果和分母、常见失败过程、一个主要过程的时间关系、相容成功反例、未覆盖或冲突。个体例子说明“怎么发生”，群体统计说明“是否常见”，两者同时存在。Stair/Push 已有 8/12 KiB 默认视图可作为起点，不把预算不足一律处理成扩窗。

详细轨迹、规则命中和媒体保留在外部证据文件；短报告带稳定引用与版本。后续确实需要回查时，再提供按 episode/window 的有限读取。记忆优先保留“曾提出的解释、依据、干预和后续结果是否支持”，不反复复制整份轨迹或上一轮长推理。

裁剪优先减少重复例子和细碎数值，保住会改变判断的转折、反证和范围；修复请求继续保留同一证据核心。若画面消耗占满上下文，应减少冗余帧、保留关键前后关系，并记录省略范围，不能靠删掉反例让报告显得更确定。

## 模块边界与建议顺序

任务模块拥有身体映射、测量定义、过程规则、事件对齐和例子选择；公用层只负责证据引用、访问边界、容量、投递、缓存及生命周期。视觉观察不能反向更改任务成功判定，模型生成的新术语不能直接改奖励或接受逻辑。

建议主计划围绕三个可分别验收的交付重排：

1. **语义主线收敛：**保留当前数值工程，统一事实、过程、视觉观察和假说边界；纠正已知描述错误并补主要遗漏。用原始数据、少量独立回合、成功/阴性反例验收真实性，不以作者 A/T 门判建设价值。
2. **未知与有界视觉：**实际送达少数已绑定窗口，验证未命名组合可以描述、画面不可见与来源冲突能保留、没有冒写接触或因果。包括原规则没有命中的片段；不要求“未知语义全部识别”。
3. **工作集与闭环使用：**确认作者在初稿、修复和下一轮中确实收到必要证据；保存有来源的解释和预测，后续结果能反驳它。先接最小路径，需求明确后再扩 P4 查询和 P5 记忆。

重要新词条、影响结论的解释分歧可以安排第二名独立评阅者，使用相同可见证据和事先规则；算术与定义能解决的先用它们解决。无法解决就保留分歧，不用多数票制造真值，也不对每句话重复评八遍。验收以描述是否正确、覆盖是否足够和证据是否送达为核心。

以上均为建议。用户修改计划后再确定下一批开发边界；本轮到必要审计收尾为止。
