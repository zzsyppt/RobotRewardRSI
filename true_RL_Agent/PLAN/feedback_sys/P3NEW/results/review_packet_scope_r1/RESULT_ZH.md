输出合同明确 `sealed_fact_id` 对应本人 `necessary_facts.fact_id`；负面或不可回答的判断也属于已完成评阅，实际未读才算未评。另明确原始观察、奖励权限、诊断自身定义这三类主张分别需要什么依据。旧答中 13 条负面判断直接指出奖励 ABI 或 kinematic-body 材料缺口，另 3 条把诊断定义声明当作需要任务终止协议授权；这些是要分别复核的问题，不能直接把所有负面票改为 supported。奖励 ABI 已在[合同修复](../review_task_contract_development_r2/RESULT_ZH.md)补齐。

`verify_scope.py` 核对当前 36 个数值逻辑包的材料绑定和八组条款抽取，并用已有 Push 媒体包的 12 张原始 PNG 构造两家评委请求；原图及其余媒体证据 SHA 未变，两家实际证据部分相同，facts 中没有报告或 inventory。结果见 `verification.json`。这只验收材料生成与角色分工，不证明模型读完、判断正确或 N.5 容量/语义门通过。

当前共享定义仍全部属于评阅范围，没有因旧答遗漏而移出分母或默认通过。若后续按任务单独评一次共享定义，须在新确认前冻结明确覆盖和实例引用关系；当前未启用这种新投递安排。
