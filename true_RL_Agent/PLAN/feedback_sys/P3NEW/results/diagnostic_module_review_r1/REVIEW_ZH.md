# 诊断模块开发验收：原图、仿真状态与实际短报告

日期：2026-09-30。评阅者：当前开发主代理（Codex）；**非盲、非独立评委**。这是一轮模块验收与问题定位，不是 N.5 判分，也不改动 r8 原答、机械检查或作者结果。

## 结论

**现有 r8 视觉描述整体不能宣布验收通过。** Stair 两条躯干方向描述在各自显示时刻基本准确，第二条重复；Push 状态句可作粗略画面描述，但两条时序句将较小且不同步的变化整理成反复“更蹲—变浅—再蹲”，证据不足。其中一条时序句虽通过机械检查且已进入作者报告，仍不通过此次语义复核。

这不是“过程描述不应该做”。有明显变化时，应准确描述转折；变化细小或不可辨时，允许写形态大致相似，过程主线由同回合的数值证据承担。

## 应达到的过程粒度示例

以下为本次开发评阅形成的**目标描述示例**，不是自动模块原产物，也没有回写作者历史输入。

**Stair r2.e282 失败：**在显示的 80、159、264 步，躯干前部抬高，身体沿台阶坡向展开；298 步明显发生侧转，317 步身体已翻转、多足朝上。完整数值记录：低前进区间253–317、倾斜区间289–317（298确认），304步向上轴首次为负，终止于317；234→317最大x回退约0.469m。两个区间重叠，不能改写为单一先后因果链。终止记录是 forbidden_contact，但这些图不足以确定哪个部位碰到哪个表面，更不能判定接触造成翻倒。

**Push r1.e19 失败：**69步执行扰动，70–88步平面速度超出稳定界，89–121步连续满足五项条件，109步达到恢复驻留要求；122步再次超出平面速度界，末步412仍超界（0.232153 m/s，阈值0.215546）。因此这是曾恢复、后来又失稳且最终未通过的回合。显示的图像中机器人仍站立、膝部弯曲，局部肢体和朝向有变化；外观站立不等于任务恢复成功。这里的时间和速度结论来自数值，图像只补形态。

**Stair r1.e282 成功：**起始较平，中间显示点前部抬高并跨越台阶，最后343步位于上部平面、躯干较平。新的选帧172/176/201/226也显示腿部配置变化，足以补充局部形态，但不宜只凭这些间隔点给出每条腿的完整摆动/承载周期。

## 发现的边界与已处理项

1. 当前视觉回合与数值代表例不同：Stair 图是 r1.e282、数值例 r1.e63；Push 图是 r1.e19、数值例 r1.e51。标识正确保留，可以并列，但不能跨回合佐证。当前系统尚不能声称每个高层段落都有同回合视觉。
2. 相机以 root 世界位置加固定世界偏移追踪，并不随 root 四元数旋转；画面居中不等于没有世界位移。不同视角不能简单互称前/侧视而忽略身体朝向变化。
3. 已在通用观察指令补充：变化不明确可写相似/不确定，不强分阶段；跨视角合并；保留左右/部位差异。未新建任务阈值或词语黑名单。提示修订后的实际效果尚需 r9 原答检查，38项单元测试仅证明工程未回归。
4. 未通过的旧句保留在原答与历史作者输入，不能静默替换成上面的目标描述。后续重新冻结的新报告才使用新版本。
5. 画质在本轮显示点足以辨认全身粗姿态和腿部轮廓；Stair 白色机器人/台阶低对比、远侧遮挡，Push 小幅姿态差异仍存在限制。不能认证未看原图、足底接触或精细关节角。
