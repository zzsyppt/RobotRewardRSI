## 逐项内容判断

### Stair 成功例：方向可读，接触不可越界

原文起始段的躯干大致水平、下肢向下可以作粗形态描述；“low”缺少明确比较参照。中段前部抬高及201步比226/343步更倾斜，与显示点基本相符。

但中段文字与 step1 比较，自己的证据引用只有172/201，漏掉了比较基线。末段的“all four feet rest on the flat top surface”把位置外观推进成四足接触/静置事实，现有稀疏图不能支持。原答自己也在 not_visible 中声明足地接触不可判。适当表述应止于“足端看起来接近上部平面”，接触是否成立交给具名、同轨的接触测量。

这些是对原始文字的开发阅读意见；没有修补原 JSON 后重新算通过。

### Stair 失败例：抓住翻转，但粗化错了一个关键姿态

第1条把 step1 和80合称为 `level/upright`。80步机器人并未翻倒，但前部已明显抬高，因此“未翻倒/向上”与“躯干水平”不能混为同一姿态。原始 S0 已给出80步前向轴世界 z 分量 **0.367229**、向上轴 z 分量 **0.925105**；这不是缺少方向输入，而是模型没有忠实利用已有信息。

159/264步前部抬高、298步明显侧转、317步腹部朝上，和原图相符。合适粒度是分别保留这些显示点状态，而不把1/80合成同一个平直阶段，更不填补稀疏点之间的连续动作。

第2条关于 `FL_calf` 从下向上，粗轮廓可见。额外同轨复核表明，具名 `FL_foot` 与 root 的世界高度差从 step1 的 **−0.286214 m** 变为317的 **+0.433207 m**。这支持足端相对 root 的上下关系，**不能代替 FL_calf 的方向、角度或在两个机位均完整可见的证明**；二者是不同 link。

第3条关于 `Head_upper` 随身体翻转大体可读，但 `downward from` 没有说清是世界向下、相对躯干还是图像方向。不能给这部分模糊方向声明认证。应在身体轴/世界轴明确的条件下陈述方向，或退回“头部随躯干翻转”的可见关系。

### Push 失败例：局部差异被错误整理成全身蹲起

第1条立姿、上身立起可以粗述；“both knees nearly straight”比画面能支持的程度更强，画面中膝部弯曲可见。

第2条称1→44步双膝一起弯曲，第3条称44→412步双膝都变浅、整体蹲姿减轻。双视角中的小幅变化不能可靠支持这个两阶段故事。复核额外读取的具名膝关节坐标如下：

| 步 | 左膝 / rad | 右膝 / rad |
|---|---:|---:|
| 1 | 0.485482 | 0.377601 |
| 44 | 0.531711 | 0.332921 |
| 412 | 0.563509 | 0.337705 |

1→44左右坐标变化方向不同，44→412均增加；这没有提供模型所述同步屈伸过程的证据。这里**不凭关节名推定正负号就是解剖屈伸方向，也不新设“蹲”阈值**。额外关节量并未提供给原观察者，不能假装它已读过；其价值是定位下一步可提供的具名测量。

第3条所附 `root_low_height_sample=false` 即使与任务数值一致，也仅证明该低高度谓词为假，不能证明“膝盖更直、蹲姿变浅”。root 高度、root 俯仰、左右膝坐标和全身姿态是不同的量，必须保持区别。

数值补核、原始快照/NPZ出处、坐标约定和渲染前后状态一致性见[numeric_followup.json](../diagnostic_module_probe_r9/numeric_followup.json)，SHA-256 `c54959606201c581d0537e1c86b2fdc43f42c6aafbbec33c5edbcacfe858500f`。数值四元数是 wxyz，原生快照是 xyzw；重排后核对，不混用。

## 本轮已经修好的工程问题

1. **合法长观察可能挤爆报告。** 字符数上限不能保证 UTF-8 字节预算；加入父差分也可能再次超限。现在只允许整条省略可选视觉原话，保留必需的数值、成功反例、残差、差分和视觉覆盖/冲突计数；明确记录省略，shown 按实际投递修正，不截断句子。正文和后续父差分复用同一容量规则。见[容量修复回执](../visual_projection_capacity_fix_r1/RECEIPT_ZH.md)。
2. **无效输出不能把报告拼接打断，也不能变成“零错误”。** r9 的无效 JSON 暴露了实验发送入口失败返回缺少标准 audit 字段的问题；当前入口与共享投影已修正。顶层失败只产生显式、必需的视觉缺口，保留数值报告与原答；无法枚举时条数记不可得，能枚举时只说已枚举，不能冒称语义通过。没有自动补 JSON、删除多余字段或重试。实际旧原答在新源码上的离线复投单独存档，原 r9 机械结果不覆盖。

主代理对最终当前源码重跑95项相关单元测试，全部通过；另有9个实验入口CPU场景及[三份真实原答的同源离线回放](../native_observer_failure_boundary_actual_r2/receipt.json)。三个报告分别为7334、7710、10490字节，数值回合/时序与全部非视觉报告段保持不变。正常的media-02仍可机械投递其原句，恰好说明该工程检查并未认证句子真实。最初一次离线回放误选了旧archive身份的full，绑定闸门正确拒绝；该记录保留，随后使用实际同源full重新核对，没有放宽或改写身份。

工程修复使错误被正确记录与投递，不使错误描述变真。仍未实现自由文字的自动逐句真值核对，当前模块不能宣布语义验收通过。

## 后续实现应收敛到什么边界

下一步优先在**任务/机器人适配器**补少量、有定义的部位变化事实，复用现有采样和 S0 输入。先选已有同轨状态、能解释当前真实错误的量，不建立全身动作词典或新的代理平台：

- 已有躯干轴、姿态和高度必须明确参考系及比较两端；可直接算出的变化交给代码，模型不重复猜。
- 膝部等局部姿态要先绑定具名关节、零位与正方向；定义不足时只给原坐标/变化，不擅自翻译为“更蹲”。复核用的快照量不自动扩张为整个数值 cohort 的已采字段。
- 模型主要补可见轮廓、环境相对关系、遮挡和未知形态；多个部位变化不同步时并列描述，不强拼阶段名。没见过的行为先组合已有事实，未分类部分明确留下。
- 核对者看同一工作集，逐句区分“支持、矛盾、缺证据/不清楚”；代码负责身份、算术、时序和容量。只让有证据的短结论进入作者，完整原答及驳回理由留在模块档案。开发时主代理可承担这一角色；自动化核对接入仍是待完成工作。

主作者仍接收有界过程报告和必要出处，不接收整个视频、全关节数组或观察者长推理。模块的独立上下文即可实现职责隔离，无需常驻多代理讨论。详细边界见[诊断模块设计](../../DIAGNOSTIC_MODULE_BOUNDARY_ZH.md)。

完成这些内容缺口后再冻结最终源码、处理剩余 N.5 评阅材料容量并正式确认。当前 **P3-NEW 仍为 IN_PROGRESS；N.5 新采集、正式评阅、3-live、P4和新训练均未开始**。
