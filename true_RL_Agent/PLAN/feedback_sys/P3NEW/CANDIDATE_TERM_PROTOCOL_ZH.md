# 候选词条登记、归并与离线晋升

2026-09-29。用于 Stair 与 Push 的开发记录；生产不读取本文件或台账。当前不增加任务公式、不执行模型生成的检测代码、不自动扩词。

## 记录合同

`results/n1n2_completion_r1/candidate_lexicon.json` 使用 `feedback.candidate_lexicon.dev.v1`，顶层 `automatic_promotion=false`，按任务保存 `entries` 和未登记原因。Push 暂无本次确认的候选，保留空表及说明；空表不表示没有未知行为。Stair 记录三种历史形态，均为 `visual_candidate`。

每条记录保存：稳定 id、task、原始名称与来源、规范显示名、身体/显示步、原观察及不确定范围、媒体和数值各自的路径与 hash、二者来源关系、唯一观察出现数、归并记录、当前可测词条的对应与不足、开发决定、晋升状态。观察出现数按唯一媒体来源和步窗计数，名称翻译、重复读取和同一视频的多张图不增加次数。

“规则阳性”必须注明口径：已有测量谓词命中，只说明该测量发生；P3-NEW 的三态残差还要求冻结签名、时间分箱和足量同域成功对照。v1没有这套三态分类器，不能把其任意事件命中事后改叫已通过区分判据。正式规则阴性、对照缺失、词表不能命名某种视觉形态分别记录；不得为了填台账把阳性或对照缺失改为阴性。

## 归并

开发者核对来源后才归并。记录操作人、原名、目标名、理由与保留的范围；模型相似措辞不能自行证明相同物理状态。此次将“后翻／腹部下沉／冻结跨立”改成有限的采样画面描述，记录为**范围收窄**，不是证明强名称与弱名称等价。原文、原范围和旧记录保留，观察发生次数不重复增加。

同名但身体、参考系或时间含义不同的项不强并；允许保持多个候选。已有 Stair `record_stair_candidate_term` 可登记任务内部建议，台账是此次跨任务开发交付形式，不另建公共物理规则或Push专用登记服务。

## 晋升

候选先保持“仅视觉／未晋升”。拟晋升时，任务开发者给出可重复测量的操作数、身体与坐标系、时窗、单位、阈值、缺测降级及适用域；缺所需观察时就保留候选，不用文字代理冒充测量。

在已登记开发池上独立重算，记录成功/失败同域两侧 n/N、区分力、成功组误报、困难反例与完整缺失分母。对能测但不区分的项，只授予描述性地位。然后在对应阶段冻结确认范围、语义验收和版本；通过后才将规则与卡片放入任务源码。旧档案保持原版本，不追改名称或原判分；不改 success、termination、reward ABI 或 acceptance。

本阶段只完成三例回溯与这份规程，三项晋升决定均为“继续保留视觉候选”。完整晋升验收按后续阶段合同执行；这不是提前宣布 P7 完成。

## 已知资料边界

旧录像为独立重放，虽然编号、checkpoint、cell、终局与时长可核对，却没有逐步同轨证明。数值 v1 与当前派生共享同一数值 archive，可作词表回溯；录像不能替该 archive 确认逐帧命题。旧拼图经过缩放和均衡化，本次只登记足够粗的可见形态，不授予正式视觉输入质量或 N.5 资格。
