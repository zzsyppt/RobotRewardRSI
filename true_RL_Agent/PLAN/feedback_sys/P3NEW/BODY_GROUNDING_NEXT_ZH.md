# r10后必须解决的部位身份与几何证据缺口

2026-09-30。依据[r10实际失败](./results/diagnostic_module_probe_r10/R10_REVIEW_ZH.md)进行源头实现。**采集、投影、任务几何及输入接线已实现，旧开发稀疏实采与12图部位定位验收通过**，详见[实际验收](./results/body_grounding_capture_r1/REVIEW_ZH.md)。这不代表原始观察者或N.5通过。后续r11单独登记，使用新增实际几何证据，不复用旧缺测图冒充新输入。

后续实测：完整r2密采已通过，r11已实际执行一次但观察输出不通过；点坐标算术没有形成形态增量，详见[r11记录](./results/body_grounding_observer_r11/R11_REVIEW_ZH.md)。下面保留该源头实现的依据，不把输入工程通过扩大成模型理解通过。

## 为什么root事实还不够

姿态轴、root高度正确，并不能回答画面中哪只手是left，也不能回答膝部从什么形状变成什么形状。当前模型只获得一个body名称列表，缺少名称到图像位置的对应。因此下一改进应把仿真已经知道的部位身份和局部几何提供出来，视觉只补它能看见的形态；继续堆叠“不要猜”的提示不能补足这些操作数。

## 已核实的源头

r10所用旧v3的`_selected_state()`只保存root位姿/速度、joint_pos/vel和时钟；snapshot另存body_names，但没有逐link世界位置/姿态。每view只有eye/lookat与offset，没有真实投影矩阵或内参。旧r10记录因此不能生成声称精确的具名部位二维标注，也不进行事后补造。

子代理只读核查了服务器当前IsaacLab安装源码：`body_pos_w`为`body_link_pos_w`别名，link字段是actor/link frame，而不是COM；`body_link_quat_w`使用xyzw。新采集应使用明确的link字段名，避免位置类型混淆。

子代理在CPU打开与当前G1 profile SHA一致的USD（`4f5e0600f24bed04d4c45b3921b6f3d7b6205463b0b1ac051cf2883dd3aaee67`），核实两侧hip_yaw、knee、ankle_pitch及palm固定关节的child localPos1均为0，默认姿态父子锚点的世界误差约3e-8至3e-7m。这里只证明这份资产的对应link原点可作为已声明的关节锚点；palm锚点不等于手掌中心。knee的localRot0非identity，COM也有明显偏移，不能把q或COM位置直接当作人体屈膝定义。语义依据参照[USD joint局部锚点定义](https://openusd.org/dev/api/class_usd_physics_joint.html)，实际机器人定义仍须绑定资产。

## 实现与验收单元

1. **采集保存实际对应关系。** 在同状态快照保存具名link位置，必要时姿态，沿用现有渲染前后状态不变检查与hash。公用采集层只负责名称、坐标、单位和来源，不解释膝、下蹲或失败。
2. **标定来自实际渲染相机。** 从同一个render product/camera取得真实view/projection或标定数据；先核查当前Kit/Replicator实际接口，不由eye/lookat猜内参。原图不变，少量编号的投影标注可作为附加定位证据。投影在画面内不代表可见，遮挡仍由画面判断；本工作不扩展整套分割/深度平台。
3. **机器人定义点，任务定义有用的量。** 外置小型资产绑定说明记录首批hip_yaw–knee–ankle_pitch及palm锚点。三点夹角先明确称为指定锚点连线的几何夹角，附初态、末态和参照，不自动套用人体阈值，也不单独推出整体下蹲。事实仍按需、少量进入观察工作集。
4. **用旧开发范围验接线与语义。** 最小稀疏采集检查身体名顺序、相机投影与原图落点、双视角同状态、坐标/单位及数值主线不受影响。此项已通过；后续[r11一次Push检查](./R11_REGISTRATION_ZH.md)已预登记，须先完成同源完整密采与正式输入核对，当前尚未发送。不得用缺字段的旧图冒充新证据。

## 当前代码边界

- 公用采集升级为`native_rgb_snapshots.v4`：具名`body_link_pos_w/body_link_quat_w`进入渲染前后状态和哈希；`camera_params`附着于实际RGB已有render product，每个view第二次render后读取。无第二套相机，不用lookat猜内参。
- 公用`evaluation/body_projection.py`仅计算link原点的像素位置，采用当前NVIDIA实际writer核实的行向量`world @ view @ projection`、左上像素原点和stage单位换算。画幅内、画幅外、相机后和投影平面分别保留；不判断可见性。
- Push的`body_geometry.py`及外置G1资产说明拥有H/K/A与palm原点含义。左右夹角独立；每幅图只定位每侧H/K/palm共六点。原始snapshot里的全部部位不进入观察上下文。
- 原运行resolved-cell manifest证明profile hash，当前同hash profile和资产说明再解释坐标。导出器显式携带原manifest并核对它与数值档案的绑定，不能用当前机器人名称补造历史依据。
- 观察工作集最多五条测量事实、每图六个具名点；原S0精度保留，模型只补图像形态。原有完整interval-1媒体准备与N.5门保持；本次稀疏工程图不冒充全时段确认材料。旧v3仍可读取，缺少的新量保持缺测。

133项相关单测通过；9个发送入口离线场景通过，回执见[离线结果](./results/body_grounding_sender_cpu_r1.json)。一次真实稀疏实采中192回合的12数值字段与所有终局保持；32原图机械验收通过，主代理实际查看目标回合全部12图，核对具名点与身体区域及遮挡。实际生产输入离线形成42个S0、5条测量事实、72点、12原图，29.39MB低于48MiB，未发送。几何角跨平台最大约2.84e-14度差异保留于回执；没有独立像素地标或亚像素误差界，不能扩称原始模型描述或N.5通过。

## 必须得到的结果

- 左右部位不再只凭模型猜；可从已绑定测量与画面对应处复核。
- 细微端点差仍是细微端点差；缺少几何定义则不生成屈伸结论。
- 有用且有依据的粗描述保留；不能靠拒绝所有视觉句达标，也不能把无关手臂动作说成失败机制。
- 原始观察质量、核对者质量与最后送达质量分别验收；运行核对者不能兼任正式N.5事实真值。
- 新证据不进入主作者长上下文，只有经过核对的必要描述及出处进入既有8/12KiB报告。原始轨迹、图像和核对理由留在档案。

这是一条小型测量与定位支线，不需要新姿态估计模型、完整FK平台或多代理辩论系统。代码完成、真实采集通过、原始描述通过三者分开登记。
