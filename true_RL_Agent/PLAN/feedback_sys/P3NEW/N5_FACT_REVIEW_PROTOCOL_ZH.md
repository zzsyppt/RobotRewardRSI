## 1. 先事实，后报告

1. **采集前冻结规则。** 冻结来源、选择算法、焦点、可评模态、字段定义、以下切分/匹配/裁决口径及材料拆分。24 回合最终成员只能在原始终局产生后按冻结规则选出，并在报告揭示前封存。不能假装运行前已知成功/失败。
2. **facts 阶段。** 两位评阅者分别阅读同字节、同顺序的匿名原始资料、任务测量定义与五束问题。允许原始终局；不含自动过程报告、生产规则的阳性/阴性标签、观察者答案、旧评分或另一评委答案。每人自行形成必要事实、可回答范围、主要形态与缺口清单；原答及材料 hash 分别封存。
3. **全包事实封存后再揭示。** 24 回合、12 焦点及媒体子集要求的 facts 材料均完成，双方原答封存，才进入任一 report 包。资料缺失或回答不完整保持未完成，不能将其排除后继续宣布本集 PASS。
4. **report 阶段。** 每位评阅者拿到相同的被评资料和原始验证操作数，以及仅属于自己的完整facts原答。回合单位仍提供本回合完整相关曲线；组级focus提供整份默认报告所需的全池计数操作数及全部被引用实例/反例的原始局部量，whole指标则给相应完整曲线，不以该focus所属scope裁掉报告其它声明的验证证据。该报告验证视图可按冻结规则解析证据引用定位，但不能回写已封存必要事实或缩小召回分母。完整派生、有界报告、最终请求和观察者过滤前输出分别标来源；不得用有界报告替完整派生，不得拿完整派生的正确句补偿最终请求的遗漏。
5. **双答封存后核对。** 开发者只可按冻结规则做材料绑定、算术、定义与匹配复算；不能凭知道实现意图替模型改票。保留双方原答、分歧与逐项裁决依据。任何据确认资料修改规则、选例、压缩、模板、提示或判分主规则，使整包转开发，原失败/INCONCLUSIVE 留档，另冻未用 cohort。

正式角色采用双评协议2026-09-30更新的混合分配：每单位两个独立上下文，A路全GPT-6.1-SOL；B路8个固定单位用DeepSeek，其余32个另开GPT-6.1-SOL。8个跨家族与32个同家族双上下文分别披露，不改全体分母。SOL 可以使用 `fork_turns=none` 的子 agent，或事前冻结的 Codex CLI 独立临时上下文；不能在看到正式答案后更换载体择优。CLI 只覆盖本次运行的上下文参数，关闭 memory 注入，不恢复历史，不改用户全局配置。DeepSeek 每阶段使用新请求；双方只使用指定材料，不能读开发线程、memory、映射表、其他评分或任意仓库文件。观察者与任一同家族评委的相关误差必须披露；两人一致不称为物理真值。

## 2. 两个事实分母，以及独立的视觉分母

<!-- JUDGE_BEGIN:responsibility -->
本版按[验收职责修订](./REVIEW_RESPONSIBILITY_REVISION_ZH.md)分开全量确定性核验与模型语义评阅。原始全程、完整派生对象和locator保留。形式化字段及集合由独立程序检查，须覆盖部位、类别、布尔/null、确认与起止、遗漏/多报和时间关系，不能只核数字；不得调用生产派生函数作为真值。采集前冻结每个字段的核验责任与操作数，未核字段留缺口，不得记自动通过。模型仍评全部实际文字、词条含义/限制、范围、引用映射和过程关系，并从原始资料独立建立必要事实。程序全量核验结果不是另一位模型的答案，只在report阶段作为单列机械记录提供，不进入facts材料。

facts 中的 `direct_arithmetic` 是原始量按固定定义得到的中立浏览索引：完整逐部位阈值区间（含空列表和未达到驻留的短段）、极值及其步号、回撤端点、原始事件窗口和五条件 AND 驻留。它不是生产诊断、必要事实清单或“已核通过”的票，不能以其字段数作为事实分母；完整相关原量仍同时供应。模型独立解释主要变化、并行/先后、重复、局部/整体与未知，也可指出索引未命名的关系，不必为每个标量重复算术判词。不同列的极值可能来自不同时刻，不能拼成同一步姿态；Push 的 stable 仅指已定义五条件同时成立，首次驻留不证明后续持续稳定。

输入保留原始终局及采集时 conditions/注入验证/驻留等判据记录，明确其记录来源；排除额外生产 `diagnostic_flags` 和与生产结果比较的一致性 PASS。原始终局名称不能代替过程或原因的证据。`raw_columns/raw_discrete/direct_columns` 是实际供应值；`reconstructible_direct_fields` 由列出的操作数和公式完整可重建，不是缺观测；`not_transmitted_direct_fields` 仅指直接表示未重复传输；`not_supplied_direct_fields` 才是本包未供且无法按列出关系重建的记录量。真正未录、未发送、范围外、已给但未分析分别说明；未完成分析不得改称测量未知。

相同形式化定义的重复实例可共用一次语义解释检查，但每个实例必须独立复算，实际自然语言、新关系及引用仍逐项评。模型不再为同一模板的数百个起止/确认标量重复生成长判词；不能用这个调整免评不相连区间被说成连续、未确认被说成已确认、局部被说成全身等含义差异。数值一致性、语义支持与必要过程覆盖分别出分，程序通过不进入模型支持分子。新方法改变了模型判分分母，不能直接与旧逐标量双评比较或回判旧轮次。
<!-- JUDGE_END -->

<!-- JUDGE_BEGIN:propositions -->
每个材料有稳定 `material_id`、文件 SHA；逐句/JSON 字段有 locator，原文引用保留。按**独立可证伪命题**拆分：身体、数值、范围、时间关系、频率比较、原因声明若可分别出错，应分别列项。一句含三个事实就有三个命题；假说与拟议干预单列，不因措辞合理而获得事实分。一个严格复合关系必须所有操作数和连接关系都成立。

同一计分单位内，含义、极性、身体、时窗、分母均相同的重复命题只合并成一项，保留全部出现位置；出现矛盾、范围变化或新数值的版本不能合并。此为待冻结的确定性去重规则，不能在看分数后只去掉错误重复。视觉观察句沿主计划保持**过滤前全部句子/返回项**，不能套用这条去重去掉重试、重复或违规观察。
<!-- JUDGE_END -->

| 评阅轴 | 固定单位和分母 | 不允许的替代 |
|---|---|---|
| 完整回合派生 | 24 个选中回合的完整派生记录及其必要共享定义；形式化对象全量独立复算，解释性主张全部双评并按回合宏平均 | 只抽默认报告引用的几个窗口，或只评好读的字段 |
| 有界报告 | 12 个焦点；每焦点接收本任务完整默认报告，支持率按其实际包含的事实，必要覆盖按该焦点五束原始清单；宏平均 | 手工截成只回答本题的好句；把 12 个例子代替组级全池分母 |
| 最终请求 | 同一 12 焦点，独立检查对应序列化请求中实际保留的事实和必要覆盖 | 把报告文件存在、外置路径或 hash 当作作者已经读到内容 |
| 观察者 | 同步媒体子集的过滤前全部观察句，包括不合 schema/被数值检查否决者 | 只评留在默认报告中的一句；只评数值 consistent 的句子 |

完整派生的每个被选回合保留完整语义字段，不把 27 MB 工件整体塞进一个请求。组级计数、比较域、代表性与覆盖等共享主张在对应焦点包完整核对；切片只是投递方式，不改变其全池原始分母。六个焦点重复接收同一任务报告不构成六份独立环境。

<!-- JUDGE_BEGIN:verdict -->
每个命题判 `supported / contradicted / unsupported / unanswerable`，附证据定位与原因：直接相反为 contradicted；证据不够支撑所作断言为 unsupported；问题本身因真实缺测无法回答为 unanswerable。后三者不进入事实支持分子，输出为事实的断言仍在总分母。明确且正确的“未测/不可判”范围说明可作为 supported 的范围事实，但不能代替可回答事实。

先分清命题在声称什么：身体实际发生的变化需要原始观测；作者输入和修改权限需要独立任务合同；诊断自己的术语、计算或显示规则则是待检查的定义声明，不自动等于任务成功条件。对定义声明，应核对含义是否清楚、实现/实例是否遵守、有没有扩大物理解释；独立算术只覆盖其实际列明的部分。不能要求任务终止协议授权每个诊断显示规则，也不能仅因报告这样定义就给其实际实例或物理含义判真。缺少实例或独立核验操作数时说明具体缺口，不把三类命题混判。
<!-- JUDGE_END -->

没有输出、分片未收齐、回答 `complete=false` 或零事实数，不赋满分，也不从宏平均样本数中删除；记录缺失，本轴不能 PASS。确实没有可评必要事实的单位须列原始理由，整体资格如何处理按采集前冻结规则执行，不能在分数出来后改为 NA。

## 3. 必要事实、匹配与极性

<!-- JUDGE_BEGIN:necessary_facts -->
facts 清单沿五束填写：①完整样本分母与结局；②失败中常见与不常见的测量过程；③相容成功反例及匹配级别；④可定位的主要过程关系或关键量；⑤缺观测与采样范围。无失败时写成功与缺失败证据，不虚构主导失败。完整回合还需保留主要阶段、重复/重叠过程与主要时段，不按每一帧增加必要事实。

每项必要事实记录：`fact_id, unit_id, question_bundle, statement, body, interval/event_anchor, modality, predicate, polarity, scope, numerator/denominator, evidence_refs, necessary_reason`。不适用字段显式为 null。`necessary_reason` 指明回答哪束问题、漏掉会丢失什么过程或限制；导出器的阈值查询和生产选择器输出不自动成为“必要事实”。评阅者可从完整轨迹识别词表没有命名的主要关系；不要求发明新行为标签。

v1.4.15 在新确认前明确必要性：采集有效性、逐列 mask、配置周期等不自动成为每回合短报告的必要叙述；只有影响本题过程或所作主张边界时才列为必要。共同限制可引用同一实际可见定义，不因没有重复逐列名就另造多项缺失。相同的返回事件等核心事实不能换几个共时搭配重复加权；确有不同、必要的关系仍分别列出并说明理由。该规则只作用后续事前事实协议，不修改已冻结的旧facts/评分，不按生产报告已有内容反定必要性。

召回/覆盖匹配必须同时满足身份、身体、观察含义、**谓词极性**、范围和定位；仅抄出相同数字或出现相同关键词不算。每个必要事实最多贡献一次命中；一个独立报告命题不能重复填满不同的必要事实，除非拆分后确有多个分别成立的命题。主要时段/部位定位使用预先标为 `location_required` 的必要过程事实为分母；完全遗漏同样不能取得定位命中，不只对已召回项计算。

完整派生轴允许匹配原结构对象的 `locator + 定义/极性 + 明确的时间关系`，不要求为该实例另造一条重复模型 claim。模型仍须判断该对象是否实际表达必要事实；CPU 只核对象是否与操作数一致。只有原始量存在、需要另行推导但派生没有表达，不能算覆盖。有界报告及最终请求只能匹配其中实际可见的内容，不能引用外置完整档案替缺句补分。这一调整不改变必要事实清单、每项只命中一次或遗漏的计分规则。

继承旧协议的容差，不提高阈值：

- 数值绝对误差 ≤ `max(1e-5, 明确显示精度的半个末位单位)`；分子、分母、单位和基准必须正确。
- 精确事件位置 ≤1 控制步；区间两端均 ≤1 步，或 IoU≥0.8。部位必须一致，重复/不相连区间不能拼成虚假连续段。不同锚点定义不能靠容差掩盖。
- 同帧不等于严格在前；两机位同 step 不构成时间变化。稀疏图只支持实际显示/引用的 step-view，不能把中间未显示区间视为持续可见。

极性检查至少保留原始不等号、是否取绝对值、阈值/单位、范围量词（曾出现/全程/存在一段）和否定。例：某稳定条件为真与“该条件违反”极性相反；“本窗口未出现”不等于“整回合不存在”；达到首次 dwell/latch 不等于后续一直稳定。原始元数据中的 conditions、事件/终止标记是所记录的测量/判据结果，不是更强物理机制的真值。

组级“常见/不常见”“更常见”必须落到同域 n/N 与既有定义；成功反例不能被解释为未出现过程。描述性共现可正确，但不能因失败组有出现就称为区分性证据，更不能直接写成因果。
<!-- JUDGE_END -->

## 4. 来源、unknown 与多模态冲突

<!-- JUDGE_BEGIN:provenance -->
逐项区分：`raw_numeric`（原始数组）、`direct_arithmetic`（公开公式复算）、`native_visual`（本 run 同步原图）、`replay_visual`、`hypothesis`、`not_recorded`。材料仍保留 material_id/SHA、JSON pointer 与原图 step/view；有截断时附实际覆盖范围。未来 `evidence_refs` 是所提供 `reference_catalog` 内完整 anchor_id 的 JSON 字符串数组，例如 `["a-...","a-..."]`；只逐字复制 ID，不构造对象包装、不输出 `within_anchor_pointer` 或手写 JSON 层级。程序维护材料身份和完整路径，不由模型重写三元组；身体、身份、时窗/事件和范围仍在原事实字段明确，整块引用不扩大事实范围。原始选择标明来自预登记媒体回合、数值专项、规则无关分散点或其重合，不将“目录选中/数值已核”记为“模型已看”。

证据以 `reference_material_block` 呈现时，每块紧邻给出 `anchor_id`、原始 locator 和完整 `value`；从实际使用的完整值选择并复制编号，不由模型追加块内路径。多个证据块分别列 ID 字符串，不用 `{a,b}`、分号、通配符或自造地址。只含 dtype/shape/hash 的来源元数据不含测量值，不能替代相应数值块。逗号时间列是字符串，步号/区间另行明确，由既有算术职责核对。`report_locator` 直接使用该项精确 `text-*` inventory_id 的 JSON 字符串，`report_locators` 使用这些精确 ID 的字符串数组；解析后仍须精确对应原文位置，不能以宽泛父块代替。报告阶段共享定义按实际字段/文字条款登记对应判断或未核原因；引用整个父对象及自报 `complete=true` 不代替覆盖记录。定义不是实例、合法编号不是事实支持；目录不是必要事实清单。算术清单中的字段范围标签不是可解引用证据，不能直接抄作引用。是否完成以实际范围和条款追踪核对，缺项保留未完成；不自动补票、不重试到通过。
<!-- JUDGE_END -->

通用上限仍为最多四回合/报告、24图、96子帧；本轮固定只取一个成功和一个失败回合，每回合最多6时刻×2视角，按报告累计两次请求，不重试。原始采集仍为六个回合。评委收到**观察者实际收到的完整原图工作集，以及相关回合的完整数值轨迹**；两家获得相同原图字节、逐图标签与测量定义，不用低清拼图替代。原始密采全窗另留档并列出未发送范围，本轮不要求把全部密采图送进评委，也不宣称它们已经获得视觉评阅。理由是观察者画面支持应相对于其实际证据判断，隐藏帧不能替错误推测补证；全回合数值必要过程仍在独立数值轴验收。显示帧主要形态提及率仅为报告项。

<!-- JUDGE_BEGIN:visual_boundaries -->
两视角用于核遮挡、视角身份和可见形态；S0 定义、参考系、步号与 numeric claim 的操作数必须匹配。数值核对只承诺该量化命题，不给整句视觉描述盖章。例如 up_z<0 不能单独证明完整翻滚过程；脚参考点离解析表面的距离不等于足底真实间隙或接触对。Push 未采脚/接触/全身关节不能由 root 曲线补造。

对同一可比较命题：来源支持一致则分别列证据；明确矛盾则并列两边、时间和字段，不择一删除；两边实际说的是不同部位/时刻/参考系，先说明不可直接比较。无映射、遮挡、缺测或采样不足保持 unknown/visual_only；“词表阴性”“对照不足”“没有观测”不可混为“什么都没有发生”。可判断却拒答按遗漏；真实未知不要求猜测，也不按未知率降低事实分母。

视觉越权沿主计划冻结清单逐句检查：接触、碰撞、受力、摩擦、扭矩、打滑、因果连接与终止原因。若证据仅为画面，不将这些未测量机制说成事实；若来自原始数值/终止记录，必须保留相应来源和判据限定，不能伪装成视觉直接观测。观察者无权从图像改写任务终局。

## 5. 两评者分歧与计量

facts 原答先分别封存。对两份清单做语义对齐，候选必要事实采用并集；只有相同含义/极性/范围的项可归并。按公开原始数值或定义可排除的错误项给出复算记录；**不能只取两人交集来缩小召回分母**。必要性或含义仍有争议者保留为 disputed，不冒充人工真值；采集卡须正式采纳“分歧项保守不计命中”的归并口径后才可使用。双方 report 请求仍只收到自己的原事实答案，不能互喂清单。

report 原答封存后，先检查两人是否在判断同一命题、极性和范围，再核算术/定义。若发现某类切分/定义错误，依据预登记类别检查全部同类项并保留修正前后，不只挑卡门槛的几项。无法按冻结规则消除的分歧保留双方理由，最终计不支持/不命中；系统错误导致的不支持与评阅分歧导致的不支持分别计数。开发者不能追加无证据“第三票”。

各单位的模型支持率为 supported/全部解释性主张（含文字中的数值、范围和关系，不含仅在结构字段中重复出现的纯形式化实例），确定性一致性另列已核对象/应核对象及错误清单；召回或覆盖为正确匹配的必要事实/原始先验必要清单，定位命中率按第3节分母。两个评阅者的原始结果、裁决后结果及分歧率都留档；不只公布较高一人的分数。观察者分母沿全部过滤前观察句，复合句须所有事实均由对应显示画面支持才算该句支持。

**阈值保留、责任分母显式修订**：形式化派生责任清单覆盖内100%一致，未核则本轴未完成；完整派生的解释性主张逐回合宏平均支持≥95%、关键过程召回≥90%、主要时段/部位定位≥90%；有界报告和最终请求分别按诊断问题宏平均支持≥95%、必要覆盖≥90%；视觉全部观察句画面支持≥90%、越权0；身份/来源/权限硬错误0。按 Stair/Push 与困难类别展开，任一任务未过不能写整体 PASS。同类语义错误在至少两个回合出现，或任一影响可操作性映射的事实被反转，按主计划触发系统性修正纪律，不能靠均值掩盖。

## 6. 最小材料与回答格式

沿现有 `run_confirmation_review.py`，不新增调度/评测平台。每个 logical unit 的 facts/report 使用同 `packet_id`；report 绑定其 facts manifest SHA 与该评委的 `p3new.confirmation_facts_seal.v1`。封存答案 envelope 为 `judge_id, packet_id, stage, complete, findings`；runner 核对外壳、封存身份、实际解释文本留痕、引用可解析性及本人必要事实 ID 覆盖。**这些机械检查不证明理解正确、复合命题切分完整，也不自动检查另一位或全包 facts 是否齐全**。全包 facts→report 屏障由 root 按冻结材料清单逐项核对后放行，不借此另建调度平台。

建议 `findings` 仅保留以下必要字段，枚举和必填项须随采集卡冻结：

<!-- JUDGE_BEGIN:answer_format -->
- 顶层另返回本包指令给出的 `reference_catalog_sha256`。所有新输出引用只用该目录的编号及可选块内 pointer；本人封存 facts 的原目录身份和原答保持，report 中相同原量编号不重新编号或改义。
- facts：`unit_id, materials_seen, coverage, necessary_facts[], major_visible_forms[], unknowns[], missing_materials[]`。每个事实采用第3节字段，证据内含 locator；没有媒体时形态数组为空并注明未采。
- report：`unit_id, materials_seen, claims[]`（实际解释性主张的claim_id、全部原文 locator/quote、标准化命题、极性/范围、verdict、evidence_refs、reason/error_category；同一形式化定义只评一次解释边界，不逐标量膨胀）；`fact_matches[]`（自己的 sealed_fact_id、对应 claim_id 或完整派生的结构对象 locator/定义/极性、matched/missing/disputed、定位结果及理由）；`unreviewed_locators[]`。未收齐/未评完时 `complete=false`，不靠总评一句“支持”代替明细。
- report 另含 `inventory_review[{inventory_id,status,claim_ids,reason}]`，对每项实际原文登记 reviewed 或 unreviewed；reviewed 引用覆盖该位置的 claims，unreviewed 保留未完成。inventory 只是原文目录，不是真值、原子主张清单或评分分母。复合句的所有可证伪命题仍由评阅者独立拆分。
- 输出引用只使用目录编号及可选块内 pointer。目录内部的 `{material_id,sha256,json_pointer}` 从原 envelope 起算，内容一般以 `/data` 开头；注册的 `decode_json_string_at` 由程序按目录处理，评阅者不另造定位或改写目录。输入可用性和权限必须引用独立 `task_definition` 原件，不能用被评报告或算术 PASS 自证；缺证据时仍完成判断并记 unsupported/unanswerable，不能补成 supported。
<!-- JUDGE_END -->
- 独立程序另留所有被核原对象/字段locator、操作数与脚本hash、expected/actual差异、漏报/多报及未核项；它不写两位模型的supported票。语义回答必须列出已评的文字/定义/关系位置和未评位置，程序覆盖不能填进模型阅读记录。
- 汇总另留两位原答 hash、对应关系、算术/定义裁决与分歧原因。它是可追溯归并表，不是第三位人工真值答案。

| 材料包 | facts 阶段必须收到 | report 阶段增加 |
|---|---|---|
| 24 episode 单位 | `episode.json`、其全部 `values_*.json`、测量定义/原始终局；媒体由独立子集包提供，不因重合而省略该包 | 该回合完整 full 切片和依赖定义，不能只给 public |
| 12 focus 单位 | 对应 `focus/*.json` 的全部 scope rows/全池成员；必要的任务定义、原始直接摘要和明确列出的补充原始量 | 整份任务有界报告、对应最终请求；相关组级 full 事实 |
| 媒体子集 | 预登记六原始回合中按结局/固定哈希入选的成功、失败各一回合/任务；观察者收到的全部原图、完整相关数值轨迹、step/view/相机与同 run 绑定；密采未发送清单 | 过滤前全部观察者输出、数值核对/冲突结果及其报告投影 |

媒体单位可与24回合重合或不重合，单独列出；不能称为新增独立确认回合，也不强求与 N.2 目录成员一致。facts 角色白名单仅 `review_protocol, focus_questions, task_definition, raw_numeric, raw_outcome, raw_media_metadata, raw_image`；report 才允许 `automatic_report, full_derivation, bounded_request, observer_output, arithmetic_audit`。`arithmetic_audit` 必须带原量/被核派生/核验脚本的hash、覆盖locator与未核项，标为程序检查记录，不冒充原始测量或另一模型答案，不替语义票；仍由现有材料hash绑定。只用 JSON 和原始 PNG；NPZ 留作来源审计，不能让 DeepSeek 只收到本地路径而 SOL 实际读到数值。

当前 `export_confirmation_raw.py` 已输出所选回合全量 JSON/NPZ、12 focus 全成员直接摘要、全池成员、字段/dtype/来源 hash。正式包另附由任务原始合同和采集 manifest 生成的 `task_definition`，保留 ABI 字段、权限、计时/身体/坐标定义及原件定位；当前源码和当时执行源码必须区分，不凭当前 hash 补造历史执行证明。现有摘要可建立五束事实：原始计数、已有过程区间频次/重叠、相容成功反例、有定位的主要关系及采样缺口；**未选回合没有全部曲线不构成整体阻碍**，也不要求扩全量关节。针对具体缺项，导出器现已对全scope成员增加：Stair 最大回退起止原始 world-x/步、既有阈值的 signed roll/pitch 与 up_z<0 直接算术区间；Push 全程五条件的无损编码，以及固定 anchor/anchor+1/实际 window_end/T 的原始 pose/planar_motion。它们保留原始事件、缺字段和实际覆盖，不能被当作新行为真值标签。字段对应与容量核查见[focus窄范围复核](./results/n5_focus_material_audit/RECOMMENDATION_ZH.md)，新旧导出分开保留。

采集前冻结上述补充的定义和字段；不按新报告阳性挑成员或改问题分母。确有其他特定过程关系需要尚未送达的操作数时，须具体指出量与时窗，不能把摘要包装成任意完整轨迹。NPZ已有但focus未发送的量记 `not_supplied`，不记 `not_recorded`；媒体仍由独立材料路径提供。

正式采用一单位一阶段一请求：24 episode、12 focus、4媒体，共40个逻辑单位；每位评者facts/report各40次，共80次。全部相关分片进入同一上下文，不新增跨请求拆分、摘要或共享定义另包。旧开发材料完成离线容量测量，旧模型完整执行失败仍保留；这不再作为新原始采集的串行前置。实际新包发送前重新核完整请求与该评者自己的facts长度；超限、不完整或压缩即保留未完成。不能临时删难段或更换载体继续算同一次确认；若需修改材料方案，整包按修正纪律转开发。

原图按实际显示工作集分包，图片原字节不缩放、不增强。每个实际 HTTP JSON body 含 base64、标签、文本后的大小须≤48 MiB，图像≤600；两者是当前 runner 硬检查，**不等于模型上下文足够**。50 MB 原图不能当作48 MiB body内可发。两位评阅者拿相同原始片段、定义和顺序；SOL 的文件访问便利不构成少给 API 数值的理由。

`bounded_request` 必须注明是已实际发送的作者请求，还是仅生产序列化/假 transport 捕获。后者可以核其中语义与字节保留，但不能登记“真实作者已接收”。本草案不为补这一项新增作者 API，送达验收与新确认材料的具体关系由 root 在冻结卡明示。

本次只评所提供的单包及所标 stage。facts 阶段只从原始材料建立清单；report 阶段评全部指定文字与关系，并逐项匹配自己的封存事实。其他包、整轮冻结、调用预算、全包屏障和最终过门由运行者负责，材料上的 DRAFT/历史状态不是本包拒评理由。只使用已提供资料，不打开未列文件、其他评者答案或开发历史。

返回 `judge_id, packet_id, stage, complete, findings` JSON。report 的 `fact_matches` 每项明确使用输出键 `sealed_fact_id`，原样对应本人输入 `necessary_facts.fact_id`；每个 ID 恰有一项。状态只用 `matched / missing / disputed`；部分覆盖记 `missing` 并说明已覆盖部分。证据不足而判 `unsupported/unanswerable` 也是已完成判断；没有实际审读或判断才记 `unreviewed`。全部指定语义及本人事实匹配完成才 `complete=true`，与支持率高低无关；未评范围明确列出，不能用格式完整代替理解完整。

数值与媒体材料生成器只抽取上述 `JUDGE_BEGIN/JUDGE_END` 标记内条款，文字直接来自本协议。其余实验管理规则由 root 执行，完整协议及 SHA 仍冻结存档；不把整轮启动职责交给单包评委。此投递边界不删除应评原文、原量、必要事实或共享定义，也不修改历史请求。

## 冻结的材料与容量方案

完整原数组、NPZ和密采图保留不变；两位评阅者使用相同的显式 `related_v2` 视图。单回合保留诊断相关量的完整1..T曲线，float32以最短可回转小数字符串列式表示并逐值校验原字节；不抽掉时间点，也不依据自动报告阳性选量。Stair 恢复足部平面速度、参考点净空的完整直接列，其余可重建重复表示列出操作数与公式；两任务均供应现有独立导出器的有限中立算术索引，不传与生产结果比较的核验票。原始归档不删；facts 原始/related/媒体路径统一投影必要终局字段，不携带额外诊断标签。未投递的关节等量明确列为 `not_supplied`，不声称已经审阅。底层原始导出仍使用提供窗口峰值样本的 `related_v1` 采集表示，投递视图版本与原始档案版本分开。

组级包保留全池成员、终局、匹配属性、全部相关条件/事件的直接算术操作数，用于分母、常见/不常见过程、相容对照与报告范围复核。它不承诺从摘要检查未选回合任意未知足部过程；开放过程召回由24个完整相关轨迹单位评阅。Push对所有scope统一补窗口速度第一次最大步的完整pose/planar_motion，不能拿各列分别极值拼成同一步姿态。

旧开发36个事实请求已通过DeepSeek官方离线分词器的容量估算；该估算对SOL只是代理。本机默认上下文272000、可配置上限872000、有效比例95%，与API公开1.05M不能混用。正式SOL固定独立CLI的单次512000窗口、450000自动压缩阈值；两次旧真实执行已证明该载体运行并保留usage，均未完成语义覆盖，不能称容量或能力通过。仅进程局部配置，不修改全局设置。事实与报告请求统一预留32768输出空间；CLI没有据此硬限制输出，实际用量另记。预检输入代理上限360000，另留系统/工具32768、输出32768、代理差异/余量8192，合计433728，小于450000及95%有效窗口486400。这是发送前的保守估算而非跨模型误差的数学保证；实际事件流压缩或未评完仍失败。报告必须加入自身完整事实原答、全部被评切片及原量后逐包复核，不能据facts长度推定report可放行。不裁掉难段、不静默换载体。

下一轮 CLI 与 DeepSeek 保留相同材料正文及原始图片字节。CLI 使用完整消息的无损 JSON 载体，原消息角色和所有块位置保留；仅把内联 PNG 换成原位置的具名文件引用，评阅者按块顺序实际查看全部原图，不再用前置附件重排材料。CLI stdin 是一个 user 输入，不冒称与 HTTP system/user 角色的执行语义完全相同。每次独立临时 home 只复用本机授权认证，关闭记忆、历史恢复和额外技能/插件注入；原答、实际图像访问、模型/effort、usage 和压缩事件分别存证，认证不进入工件。配置值不冒称服务端证明，应用层不重试与提供方内部传输重试分别记录。正式使用前用一个固定旧图文包做运行检查，不计语义验收票；新确认中不据答案改载体。内部缩放、服务端 fingerprint 不可得时如实缺失；CLI 实际提供 usage 时照录，发票金额仍未知。模型能力由本阶段各轴验收，不由载体参数代替。

## 采集卡的冻结项目

1. **来源与选择**：真正未用的 Stair/Push cohort、checkpoint/源代码/协议/seed binding、24回合及缺类规则、预选双 env 和媒体成功/失败/哈希选取、窗口/相机/S0、numeric 与媒体两套覆盖口径；不得用旧卡 release。
