# P3-NEW 正式双评协议

2026-09-29，用户明确授权：“一个用deepseek另一个如果可以你调用GPT6-SOL或Astra就行（maybe 子agent，但严禁作弊）”。本协议先于新确认资料的采集、揭示和评分；不是补写已完成实验。

## 角色与真实限制

2026-09-30 载体更新（2026-10-01 用户再次确认）：验证以全新 GPT-6.1-SOL 为主，DeepSeek 只保留小部分真实 API 可行性检查；生产作者仍按 DeepSeek 的实际输入与容量验收。开发探针按其事前卡执行；旧 GPT6-SOL 原记录不改名。下一轮正式确认采用以下事前分配，替代下文初版“两家各评全量”的要求，旧冻结轮不变：

- 40 个单位仍各有两个独立评阅上下文。A 路全部使用全新 GPT-6.1-SOL；B 路 8 个单位用 DeepSeek，其余 32 个单位另开全新 GPT-6.1-SOL，禁止继承 A 路上下文或答案。
- DeepSeek 的 8 个单位为全部 4 个媒体包、每任务 1 个 episode 和 1 个 focus。后两类按匿名 packet ID 排序取各任务首项，规则在新采集前固定，不能按报告质量或模型结果选例。成功/失败媒体仍按既定原始终局及哈希规则产生，缺类不补选。facts/report 沿用同一角色，意味着正常完成最多16次 DeepSeek 阶段请求，不是8次；失败不重试。
- 24 episode、12 focus、4 media 的全体分母、先完成全包 facts 再揭示任一 report、原句分母、支持/召回/定位阈值和分歧处置均不变。两任务分开报告；另披露 8 个跨家族单位与 32 个同家族双上下文单位的覆盖及分歧。后者有相关误差，不能称全部跨家族独立；全部4个视觉单位仍有DeepSeek异家族核查。
- 实际新确认前冻结匿名角色表、模型/推理配置、输入与协议SHA。子 agent 每次 `fork_turns=none`；CLI 每次使用独立临时 home、新会话且无 resume。两种载体均只读白名单并封存原答；报告阶段只传回本角色自己的 facts。此次是用户授权的未来验收载体调整，不据旧结果换票，也不构成新确认放行。

GPT 角色使用全新 GPT-6.1-SOL 上下文：`fork_turns=none` 子agent，或主计划v1.4.16允许的事前冻结独立CLI临时会话。CLI关闭memory注入、无resume、仅本进程配置，不改全局设置。实际载体在新资料运行前固定；若模型确实不可用，可在卡中预先登记替代载体，不得看到评分后换模型或载体择优。参与本阶段开发、模板修改、已有复核或审计的上下文不担任正式评阅者。

两位评阅者独立作答，家族关系按上述固定分配报告。视觉始终有GPT与DeepSeek两家，观察者可能与其中一家相同；不能声称视觉三角色都家族独立。历史初版采用DeepSeek与GPT6-SOL全量双家族，旧资料中该配置及结果原样保留。

API 保存实际请求、回答、model、fingerprint 与 usage。子 agent 保存任务 id、明确指定的模型/推理配置、输入材料 hash、完整原答、工具访问记录及开始/结束时间；平台未提供的服务端 fingerprint、实际 token 或费用记 unavailable，绝不自行补值，也不记作零费用。子 agent 与主代理共享文件系统，**不能宣称有操作系统级隔离**；采用新上下文、材料白名单和可审计访问限制。

## 先封存，再独立作答

1. 采集卡先冻结来源、选择/揭示顺序、问题束、句子切分、容差、阈值和分歧处置。旧001/022与R.0-b只作校准，不计正式样本。不能用确认结果选评委、改评分口径或挑样本。
2. 向两方发送相同的匿名材料。保留理解事实所需的任务定义、单位、时间和身体；隐藏历史门判定、旧评分、另一评委回答、开发者想通过的结论和匿名映射表。材料清单与顺序在调用前封存。
3. 原始事实阶段只提供原始曲线/数组、测量定义、同步媒体与五束问题，**不提供自动过程报告**。双方必要事实清单分别封存并记 hash 后，才进入报告支持、必要事实召回与定位评分阶段。不能按报告实际写了什么反向缩小必要事实分母。
4. GPT 子 agent 仅可读取分配的材料目录及明确白名单文件；不读本线程、memory、主计划结果、其他评分文件、任意仓库报告或开发代码，不上网搜索答案，不与其他评阅者通信。保留其工具访问记录；越界则该份评分作污染记录，不能继续当作盲评分使用。DeepSeek 每阶段是无其他会话历史的新请求。

## 不允许的“修到通过”

- 两方原答在比较前分别保存，失败调用和不完整回答同样保留。禁止把另一方意见或目标分数塞回让模型改票；禁止挑一个更有利的回答替换原答。
- 对算术、测量定义和源码行为的核对先于主观分歧裁决，给出可重复的证据。需要复核时按预登记错误类别覆盖全部同类项，不能由知道映射的一方只指定卡门槛的几项。
- 仍不一致的项保留双方理由，按主计划计不支持；系统错误与评阅分歧分别报告。不得把两位模型达成一致称为物理真值。
- 按全部冻结样本、全部输出主张与独立必要事实分母汇总。没有输出、证据缺失、媒体不清楚、遗漏或模型未完成按冻结口径处理，不删除、不用零事实数换满分。
- 按主计划 v1.4.5 一次性评阅 24 回合。确认结果触发规则、选择、压缩、模板、提示或判分主规则修正时，整包转开发，保留原失败或 INCONCLUSIVE，另冻结真正未用的新 cohort；同池换 ID 或相同 checkpoint/namespace 重跑不能当成未揭示储备，不能在已知答案上继续刷 PASS。

本协议初版调整评阅载体和家族要求；v1.4.14再按[职责修订](./REVIEW_RESPONSIBILITY_REVISION_ZH.md)分开独立程序全量复算与双模型语义评阅，保留原始对象/locator，新增确定性一致性100%要求、程序票不进入模型分子。新旧方法分母不同，不能直接比较或回判旧结果。保留事实支持 ≥95%、召回/定位 ≥90%、视觉全部观察句支持 ≥90%、越权0、两任务分开判定和原始证据先行的要求。当前还没有正式双评成绩。
