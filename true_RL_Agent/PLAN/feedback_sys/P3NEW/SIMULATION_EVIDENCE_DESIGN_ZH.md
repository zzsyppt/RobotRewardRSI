# 用仿真证据理解过程，而非只给视频写说明

2026-09-30 更新。依据用户关于多视角和仿真额外信息的指示形成。本文是开发方向与边界决定，**不是多视角已实现或验收通过的声明**；历史请求、评分和冻结材料不变。

## 核心判断

我们的输入不是只有一段视频。每个控制步都有可能取得姿态、速度、身体位置、接触、外部扰动与任务状态；相机也由我们控制。应先用这些可核查记录建立过程骨架，再用少量同源画面补足形态、遮挡和未命名的动作。最终反馈服务于作者修改策略，必须能沿一句话找到时间、身体、来源和缺口。

这是一条值得建设的路线，不是已经证明优于视频理解方法的研究结论。我们尚未用实验确认多视角或额外字段带来多少增益，不能据此宣称已有算法优势。

## 我们可以利用的条件与实际收益

这里的比较对象是仅获得既有视频的理解流程，不是说视频研究都忽略其他模态。

| 需要回答的问题 | 仅有视频时的主要限制 | 本项目可利用的条件 |
|---|---|---|
| 身体是否真的移动、倾斜了多少 | 像素运动混有相机运动、透视与遮挡 | 世界系/任务参考系的姿态和位移记录；随动相机不影响测量定义 |
| 是贴近表面，还是存在测得的接触 | 画面邻近不等于承力 | 已配置且实际记录的接触量；仍区分法向合量、对象对与具体接触点 |
| 动作怎样演变 | 稀疏截图漏掉中间变化 | 数值覆盖的控制步时间线，配合少数变化前后图像；两者各自声明覆盖范围 |
| 一侧身体看不清 | 固定素材无法补另一侧 | 同一状态的互补机位；仍需承认两个视角都遮挡的部位 |
| 一个现象是否与失败相关 | 单条失败视频缺比较基础 | 同任务、同条件的成功反例及全体分母；常见姿态不能自动当失败特征 |
| 解释是否真是原因 | 观察先后无法排除其他解释 | 后续可按作者预测做受控干预；本阶段不自动开展因果实验 |

优势首先是**证据可核查、问题可定位、无需重复从像素估计已有物理量**。这不是已验证的模型准确率、训练收益或研究领先性。继续验收的是描述是否忠实、过程是否遗漏以及输入是否可辨，不重新恢复“过程信息有没有价值”的 A/T 前置门。

## 当前真正拥有的基础

- Stair `numeric_capture.py` 已保存 base 世界位置/四元数、关节位置、支撑体位置/速度、支撑与禁触接触力及其历史；地形原点和类型有记录。测量定义、历史槽时钟和参考点限制仍按现行合同解释。
- Push `numeric_capture.py` 已保存高度、roll/pitch、速度、漂移、有符号平面运动、条件和扰动窗口。档案明确 `contact_status=not_collected`；不能从“仿真本来有这些值”跳到“历史档案已有足部接触、全身姿态和动作时序”。
- `native_video.py` 普通录像仍为随 root 平移的 viewport，每 run 录一个 env。新增有界快照模式已能在指定控制步切换两个机位、保存原生 PNG、逐图 `view_id` 及渲染前后状态/时钟；观察者 v2 也已贯通逐图引用。**旧开发 r3 已完成真实逐步双机位采集，r4 有限双环境采集在全部有效数值与终局上与 r3 逐字节相同；对齐范围及缺口见开发回执。正式语义验收尚未开始。**
- 当前视觉一致性映射仅核少量显示帧量化命题。它不是全身物理验证器，也不能给整个自然语言句子盖真值章。

以上指当前采集版本的能力，不能推广到所有历史档案。两任务当前数值 profile 都是 public_dev 首回合证据；Stair 的 `valid=false` 填充值不是观察，接触历史只在 v2 中有；Push 的有符号 XY 运动是 v2 增量。读取和报告继续依据实际档案版本、字段与有效范围。

## 过程描述怎样产生

1. **先建立测量时间线。** 任务模块从同 run 的数组计算状态和变化，注明实际单位、身体、参考系和采样范围。能直接计算的量由代码计算，不让视觉模型重复猜高度、速度、力和终止条件。
2. **再组织过程关系。** 保存变化前、变化中、变化后的证据，以及同时发生和缺测关系。时间先后写成时间先后；只有新对照试验才能支持机制因果。数值规则是有限的操作定义，不冒充对所有动作的理解。
3. **让视觉回答剩余的形态问题。** 例如某条可见肢体如何弯曲、身体相对台阶怎样摆放、现有规则没命名的形态。观察者可收到身体名、步号、测量定义和少量同窗 S0，不收结局、分数或拟验证的失败解释。它输出的“画面所见”仍须被图像本身支持，不能把读到的数值改写成看见了接触。
4. **按来源合并，保留冲突。** 任务报告可以并列写“接触力记录显示……”“侧视图可见……”“另一视角遮挡……”。二者都支持时增强描述的可核查性；冲突先查时间、坐标、参考点、历史槽和遮挡，不靠模型投票覆盖原始数据。
5. **作者收到简洁证据包。** 默认是主要过程、相容成功反例、范围/冲突，以及少量可定位引用。它可以提出修改与可证伪预测；不能把过程摘要当成已证实的修复方案。

数值全窗与视觉显示帧分别标范围：完整控制步数组可以支持该采样时钟内的过程统计，三张截图只能支持这三张图可见的形态，不能互相冒充覆盖。失败及规则阴性窗口之外保留独立覆盖抽样，避免已有规则决定了系统只能看见已知问题。

例如，未来某段档案若支持“右后支撑力低于任务阈值后，躯干倾斜持续增大，随后高度降低”，即使没有正式动作名称，也可以按这三个事实及时间关系描述。视觉再补充实际可见的腿姿。不得自动命名为“打滑导致侧翻”：接触判据、接触面相对运动和因果证据是不同问题。这里是表达示例，不是本轮新发现。

## 多视角如何用，才不是单纯增加图片

目标是互补：一个机位保留全身、地面和任务几何；另一个从不同方向补足关键肢体与前后/左右关系。机位依任务几何在开发资料上确定，不按新确认集的成功/失败或模型回答挑选。Stair 沿 +x 上升，向上坡侧放相机可能让高处台阶遮住身体；当前 r2 原帧已出现严重前景遮挡，不能仅提高分辨率解决。

多机位必须观察**同一 run、同一 episode、同一控制步、同一次 reset 前状态**，保存 view_id、相机参数、像素尺寸和 step 映射。可以在状态不推进时渲染多个视角，但必须验证没有额外推进物理、没有拿到上一机位的缓存帧；不同重放的画面不能拼成“同步双视角”。先使用两个互补机位，不在本阶段搭建相机搜索器、神经重建或全量深度/分割平台。

`view_id` 必须贯穿每张输入图、观察引用和最终句子的证据，不仅写进录像元数据。观察引用绑定 `(episode, step, view_id)`，跨视角结论保留两侧引用。观察者 v2 已让一个回合窗口包含多个视角，并拒绝重复的 step/view 对；同一步的两机位不能被描述成时间变化。数值一致性只核对观察明确引用的采样步，未引用的极值不能替句子补证据。

原帧和最终发送图都检查：主体完整、环境参照保留、关键部位实际可辨、无遮挡造成的假全貌、步标签正确。禁止靠均衡、非等比拉伸或把小图放大来伪造细节。自然遮挡允许存在，但两个视角都看不清的内容仍记不可见。

## 未见过的行为与额外仿真信息

未知行为先用“身体 + 可测变化 + 时间关系 + 形态补充”组合表达，保留没有命名的部分；不为每种姿态堆一个硬编码检测器。模型建议的新名称继续进入候选台账，经后续可测定义和反例核查才能晋升。

额外采集遵守需求驱动：先列出具体无法回答的问题，再找最少字段。Push 若要可靠描述脚的离地/重新支撑，优先评估足部位置和接触力是否值得补入；若只描述根部扰动响应，现有字段可能足够。动作/关节力矩、接触点、深度、分割只在现有证据无法区分一个重要解释时再考虑，不能为了“仿真全知”全量落盘。

例如，要区分“仍在尝试前进却没有位移”与“动作输出已很小”，优先考虑同窗命令、动作及必要的执行器量；RGB本身不足以确定策略输出。要区分“脚经过表面附近”与“存在测得的接触”，优先用任务已记录的足部轨迹和接触量；要确认哪条腿被遮住，再考虑另一机位或分割。以上是补采的选择依据，不声称当前评估档案已有全部动作、力矩或对象接触对。任务结局、扰动窗口和奖励分项可在相应授权的任务诊断层组织，但不因此塞入盲视觉观察者输入。

已测量也不等于没有误差：接触传感器聚合、参考点位置和仿真几何近似必须保留。诊断可以利用已授权的公开评估状态；这不会扩大策略观测、奖励 ABI 或 sealed 权限，作者不得把诊断中可见但策略不可用的变量直接写进策略。

观察者的 S0 另由任务在采集前冻结字段白名单及其单位、身体、参考系和来源，不传结局、分数、解释标签或跨窗聚合值。当前任务已定义 Stair 的 root-up、相对地形原点 x/z，以及 Push 的 root 高度和相对 reset 的世界系 x/y；公用层校验标量与任务提供的定义完全一致，不负责决定任务可以用什么量。缺原点、字段或有效采样时保持缺失，不补零。输入合同通过不代表自然语言视觉解释正确。

高层语义按三档使用，不追求一步到位给每段动作命名：①测量事实，如“高度下降、根部倾斜增加”；②有定义的过程，如满足任务操作定义的“支撑中断后姿态变化”，注明阈值与时窗；③候选解释，如“可能支撑不足”，明确仍需额外证据。新形态先组合第一档事实与可见外形；缺某个行为名称并不妨碍给作者可靠过程证据。只有第二档具备测量定义和反例检查后才进入任务词表，第三档不靠重复出现自动晋升。

额外传感字段的解释以具体采集版本为准。[Isaac Lab Camera 文档](https://isaac-sim.github.io/IsaacLab/main/source/overview/core-concepts/sensors/camera.html#annotators)区分图像平面深度和到相机距离，并提供分割能力；[ContactSensorData 文档](https://isaac-sim.github.io/IsaacLab/main/source/api/lab/isaaclab.sensors.html#isaaclab.sensors.ContactSensorData)区分法向合力与按对象过滤的接触量；[MuJoCo 接触文档](https://mujoco.readthedocs.io/en/stable/programming/simulation.html#contacts)说明单接触力/力矩采用接触坐标系。可借鉴这些明确的测量定义，但不把文档中可用的字段当成本仓库已采到的字段。深度与分割仅在具体遮挡/部件问题不能由现有姿态和 RGB 解决时再考虑。

## 成本、上下文与本阶段边界

用户后续明确取消训练/采集耗时预算，以效果优先。原始采集与模型输入分开：可以在首回合每个控制步保存同状态双视角原图，流式落盘保留完整后段，再按诊断问题选择模型所需的帧。原始档案不受“每报告 24 图”的限制；该限制只约束实际送给模型的工作集。旧 GPUh 上限不再截断采集，实际资源和失败仍留账；运行 timeout 用于识别异常挂起，不作为省采集时间的手段。

原始数据和多视角媒体留在外部档案，作者工作集不扩大。尽量先用廉价数值判断，再发送最有必要的少量图。双视角同样消耗原有每报告 24 图/96 格、4 回合、像素、字节和费用上限，不能按机位或调用重置预算。究竟保留几个回合、几个时间点，在新采集前按画质和必要时间覆盖共同冻结；不能机械地把所有帧缩小一半换取第二机位。

本阶段落实的方向是：已有数值主线继续；单机位画质缺陷先修正；有界双视角须先做同状态/同图字节的工程验证，再决定可发布的视觉 profile；正式验收分别计算测量主张、视觉主张及融合后的来源忠实性。若资源只支持部分能力，如实标未完成，不把纯数值通过写成全系统通过。N.5 新确认资料尚未揭示，任何采集或输入合同修订均先冻结；原有精度、覆盖、越权与费用上限不下调。

后续可利用仿真做受控干预，检验作者提出的机制预测；那属于真实闭环和后续实验范围。本阶段不为解释一张图新增训练、任意改物理参数或把重放相似当成因果证据。

## 开发观察后的合同收敛（v3）

两次原生 Stair 开发调用暴露的是职责边界问题，不应靠逐例提示补丁解决。模型保留身体、图像引用、形态描述、空间可见性和“状态/变化”关系；公用层从引用确定首末步、实际引用步以及这些步之间的间隔。稀疏引用不要求模型把清楚可见的身体写成遮挡。反之，空间清晰也不意味着中间控制步都被看见。`cited_step_gaps` 仅指引用间隔，不能据此断言输入包未提供那些帧。

量化命题由可选的 `{id, asserted}` 表达，任务层核对所引步的真值及声明极性。例如“根部竖轴没有负值”应声明对应命题 false，而不是携带一个暗指成立的标签。缺数据继续不可核。数值核对只支持这个有限命题，不能验证“站稳”“翻滚”等整句形态或机制解释。原始文字不改写，所有无效输出留在事实支持分母；机械合格和独立语义合格分别计。

旧 v2 的两次失败及费用保留，未发出的旧 Push 包标明已被合同升级替代。v3 是开发期接口修正，正式 N5 仍未揭示；不得用新校验器把旧失败回写成通过。
