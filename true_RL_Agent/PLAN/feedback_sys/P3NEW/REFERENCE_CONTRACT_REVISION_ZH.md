# 证据定位职责修正

2026-09-30，主计划 v1.4.21。当前源头实现与真实40包离线核验完成；一次实际开发调用仍有4处引用错误，见[结果](./results/reference_anchor_probe_r1/RESULT_ZH.md)。本页不是 N.5 放行或语义通过记录，下一改进须处理编号与实际原值的呈现关系。

后续开发修正：当前新生成清单改用 `p3new.reference_blocks.v2`。同一结构叶的 `anchor_id`、原始 locator、完整 value 相邻出现，数组/时间列保持完整且只呈现一次；材料头保留身份与重建数据 hash，解析器无损还原原 envelope。目录本身及编号算法仍为 v1，报告原文可保留额外精确 inventory 锚点而不复制原值；原图标签与 PNG 相邻、字节/顺序保持。runner 使用 coverage 内同一编码/指令，不另设传输或评分层。42项针对性测试通过，真实40包 v2 核验另留新目录；下文 v1 的40包与一次真实调用结果均是历史证据，不能挪作 v2 能力通过。另见[过程输入审查](./results/reference_anchor_probe_r1/PROCESS_INPUT_AUDIT_ZH.md)：定位修正不能替代可用性表达、原始终局与诊断标签分离、过程分析职责的源头修正。

## 为什么改

R2 第一个正式 facts 的19个无效引用，来自五类真实的路径拼接错误。对应测量和定义都已提供，校验器正确拒绝。详细证据保留在[R2记录](./results/n5_confirmation_execution_r2/README_ZH.md)，原答及失败不修改。

让模型反复抄写材料哈希与深层地址，并没有增加行为理解能力。现在把完整地址的生成和解析交给程序，模型负责选择证据以及说明证据与命题的关系。定位成功仍不代表命题正确；定义不能代替实例、同值不能代替同来源、复合关系不能只引其中一部分。

## 最小架构

现有 `run_confirmation_review.build` 完成材料SHA验证和包装后，`confirmation_review_coverage.build_reference_catalog` 从实际可见内容机械生成唯一目录。新材料清单显式带 `reference_contract=p3new.reference_anchors.v1`，不改变原始采集格式。生产诊断模块不依赖这些 PLAN 内验收工具。

- 普通 JSON 按 `/data` 内字典两层划分结构块；遇到数组、字符串或标量停止，不为每个时间点生成编号。编号取完整 locator 的确定性哈希，字典排序、材料添加不会使旧编号换义。没有“正确/必要/失败机制”等人为答案标签。
- 数值列、部位和单位原文保持。模型引用 `{anchor_id}`，需要精确字段时附 `within_anchor_pointer`。块内指针只允许实际存在的 RFC 6901 对象或数组位置。CSV时间列仍是字符串，步号和区间另行明确，不能把字符串当数组下标访问。
- 每张原图有自己的编号；原图字节、顺序、时刻、相机和同轨数值不变。图片编号只证明引用哪张图，不证明可见性、接触或因果。
- 报告文字直接复用既有 inventory_id 和 locator。报告非文本字段保留结构块定位能力；如果结构块与文字条款位置重合，只保留 inventory 项。报告覆盖仍按解析后的精确条款位置检查。
- 顶层答案绑定本请求的完整目录SHA。新引用不能混入旧三元组、猜测路径或自行提供另一材料；严格解析的结果另存 `resolved_references`，原答案不补写。
- facts 封存同时绑定原目录文件。report 准备验证目录SHA、原始材料与每个旧编号都未变，再加入新报告条款；原事实答案和原目录身份不重写。旧无目录请求仍按冻结的旧规则解析，不能套新规则追认为通过。

这仍是一包一次请求，没有增加代理、数据库、搜索语言、自动纠错或新的评分层。来源身份、可定位性、语义支持、必要过程覆盖继续分开。

## 依据与适用范围

[OpenAI 的引用格式工程说明](https://developers.openai.com/api/docs/guides/citation-formatting)建议稳定来源ID与适当大小的可检查证据块，块级定位可减少行级定位负担。[Anthropic 的引用接口](https://platform.claude.com/docs/en/build-with-claude/citations)允许显式内容块，并以标准位置表示引用。本项目只借鉴“程序管理位置、模型选择证据”的职责，不接入其API，也不把文本引用保证推广为机器人视觉语义保证。

本地 Codex `codex-rs/utils/stream-parser/src/citation.rs` 只为引用标签解析与文本分离提供参考，它不是本项目的证据真值或语义验证器。
