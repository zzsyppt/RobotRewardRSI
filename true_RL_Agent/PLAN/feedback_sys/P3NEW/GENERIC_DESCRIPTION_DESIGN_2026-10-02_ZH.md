# 不训练模型，把轨迹写成高层失败描述：一套不绑定任务的做法

2026-10-02。设计意见加试验结果，接在[架构审计](./ARCHITECTURE_AUDIT_2026-10-02_ZH.md)之后。没有改源码、主计划和历史记录；试验用的是服务器上封存的 R4 档案，只读、仅 CPU。脚本在 [audit_20261002/generic_poc/](./audit_20261002/generic_poc/)。

## 结论

1. **“把怎么失败准确说成高层语义”确实是关键一环。** 作者要做两步推断：先弄清发生了什么，再决定改哪条奖励逻辑。第一步靠模型读底层数字做不好，研究和我们自己的记录都是这个结论。要加两个限定：准确比“高”重要，名字只能是建立在已测事实上的假说；它对训练结果有没有帮助，仍要由真实闭环回答。
2. **做法一句话：抽象交给代码，模型只负责命名和成句，每句话都能被程序复核。** 把数字变成意义靠三把尺子：离任务判据还有多远、和成功回合同阶段比、和上一代比。任务和机器人各自只提供一个很薄的适配器，其余代码不出现任何任务名词。
3. **我在现有档案上试了。** 同一份核心代码、不写任何任务规则：
   - Stair 的翻倒和停滞能自动分出来并说清楚，误报约 5% 到 8%。
   - 最大的那类失败（行进中躯干接触），“和成功回合比”的尺子说不出东西，因为它在终止前和成功回合没有可分辨的差别。换成“离判据还有多远”的尺子，配一个通用几何量（躯干碰撞体各采样点到地形的间隙），就说清了：终止时躯干前下缘离台阶面约 2 cm，78 个里 55 个是左前角；成功回合里 22% 也曾贴近到 2.5 cm 以内，height_ood 层是 42/58。
   - Push 上同一套代码不看结局标签就把摔倒和没摔倒分开了，并给出“成功回合恢复之后也反复超速”这一条。

## 1. 为什么重要，以及两个限定

**模型不擅长从原始数列读出发生了什么。**

- [Merrill 等（EMNLP Findings 2024）](https://aclanthology.org/2024.findings-emnlp.201/)专门测了语言模型对时间序列的零样本推理，结论是明显不足。[Zhou 和 Yu（ICLR 2025）](https://proceedings.iclr.cc/paper_files/paper/2025/hash/05774fb74e863308c4b460c9f49f6918-Abstract-Conference.html)的结论是模型对数值序列的理解有限，画成图比写成数字好。
- 我们自己的记录：P3-R 里人工整理的密集数值让作者的硬错误从每项 0.62 升到 2.00；评阅模型读完整曲线时把 125/39 数成 127/37；作者在推理里猜“小腿还是大腿撞到立面”，而实际唯一会触发终止的部位是躯干。

**奖励设计这条线上，近期工作把“只给奖励统计”当成瓶颈。**

- [Eureka](https://arxiv.org/abs/2310.12931) 的反思只用各奖励分项的训练统计。它自己演示过：人看完行为后用一句话反馈，就能把策略往想要的步态上带。
- [RDA（Lee 等，2026-06）](https://arxiv.org/abs/2606.01672)直接指出不同的失败在奖励统计上“数值上无法区分”。它在两个任务的消融里加入轨迹级视觉分析后，意图对齐度从 0.31 升到 0.82。它同时承认视觉模型的细粒度判断不可靠、成本高。
- [Wang 等（2026-05）](https://arxiv.org/abs/2605.28918)把奖励生成当成调试：只给指标重新提示会明显变差，给一套失败类型的分类词表能补回大部分。它也提醒，在稠密奖励的运动任务上，基于成败的诊断会误判。
- [LAPP（Jian 等，2025）](https://arxiv.org/abs/2504.15472)让模型直接比较两条数值轨迹。它能用的前提是：状态变量由人挑过，只要一个偏好标签不要解释，每对轨迹问 15 次取众数，并按 15% 的随机错误率来设计。这和“一次读懂一条轨迹并说出原因”不是一回事。

**两个限定。**

- 准确优先于高层。作者会锚定在一个听起来合理的名字上。所以名字必须能还原成已测事实，而且标明它是概括，不是测量。
- 重要不等于已经被证明有效。它对训练结果的帮助，只能由 3-live 之后的真实闭环来回答。

## 2. 总体做法

```
记录 ──► 通用特征 ──► 三把尺子 ──► 事件与失败形态 ──► 命名与成句 ──► 报告
(状态、接触、   (身体关系、     (离判据多远；    (持续越界、停滞、     (模型提出；
 奖励分项)      接触、几何间隙)   与成功同阶段比；   终止时刻；按终止      程序逐句复核)
                               与上一代比)       原因分组后归类)
                                                      │
                               代表回合的连拍 ──► 视觉模型给整体概括、查漏
```

这其实是数据到文本领域的标准结构。[Reiter（2007）](https://ehudreiter.com/2022/07/22/an-architecture-for-data-to-text-systems/)把它分成四步：信号分析、数据解释、内容规划、成句。按这个结构做的 BabyTalk 系统给新生儿监护的多路生理信号写过[护士交班摘要](https://pmc.ncbi.nlm.nih.gov/articles/PMC3168319/)。它的要点和我们的教训一致：先在数据上找出模式和事件，再决定说什么，最后才是措辞。

| 层 | 做什么 | 谁提供 | 用不用模型 |
|---|---|---|---|
| 记录 | 每步存状态、各 link 位姿和接触、动作、奖励分项、终止标志 | 通用 | 不用 |
| 通用特征 | 由机器人模型和地形查询算出连续量 | 通用，机器人给部位角色，任务给地形查询 | 不用 |
| 三把尺子 | 把连续量变成“越界多少、持续多久、离判据多远” | 通用，任务给阶段变量和判据 | 不用 |
| 事件与形态 | 每回合的事件表；全体失败按终止原因再按事件模式分组；归不进去的单列 | 通用 | 不用 |
| 命名与成句 | 给每类起名、写两三句话；每句对应一个可执行的判定 | 通用 | 用，输入是事件表和统计，不是数组 |
| 复核 | 判定在全体回合上跑，数字由程序算 | 通用 | 不用 |
| 视觉 | 看代表回合的连拍，说整体形态，指出事实层没提到的东西 | 通用 | 用 |

## 3. 每一层怎么做

### 3.1 记录什么

和具体任务无关的一份清单：根部位姿和速度；关节位置和速度，连同各自的限位；每个 link 的世界位姿；每个 link 受到的接触力；动作；每一步各奖励分项的值；终止和成功判据的逐步真假值；任务事件，例如外部扰动的时刻和方向。

Stair 现有档案已经有其中大部分，缺的是每步奖励分项。Push 现有档案只有根部标量，这份清单里它缺 link 位姿、关节、接触和航向。

### 3.2 通用特征

特征只由“机器人模型加仿真状态加地形查询”定义，不出现任务名词。

- **身体关系。** 这一类借自人体动作描述的规则方法：[PoseScript](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136660340.pdf)、[Kinematic Phrases](https://arxiv.org/abs/2310.04189) 和 [MotionScript](https://arxiv.org/abs/2312.12634) 都是先算部位之间的角度、距离、相对位置、朝向及其变化，再按规则成句，不需要训练。换到机器人上，部位清单和归一化尺度从机器人模型取：躯干朝向（往前后左右哪边倾）、各端点相对躯干的前后左右上下、肢体伸展比例、关节离限位多远、左右差。
- **接触与支撑。** 哪些 link 在受力、支撑点个数、每只脚的着地时间占比和换脚节奏、受载时的滑移速度、非足端的接触。每条腿的着地时间占比就是 MAP-Elites 用来区分步态的行为描述量。
- **稳定性。** 质心投影和支撑多边形的关系、capture point（Pratt 等 2006）是否落在支撑范围内。后者回答“这时必须迈步了吗”，对人形受扰恢复是成熟的工程量，需要足端位置才能算。
- **几何间隙。** 每个 link 的碰撞体取若干采样点，算它们到地形表面的间隙，并记下是哪个点最近。平地、台阶、任意高度场都适用。
- **进度与节奏。** 阶段变量的推进速度，在 0.1 s、0.5 s、2 s 几个时间尺度上各算一遍；以及“距上次推进过了多久”。
- **出力。** 动作幅度和变化率、力矩是否顶到上限。

### 3.3 三把尺子

连续量本身不是语义，需要参照才知道“这算不算异常”。三个参照都不靠手写阈值。

- **规格尺：离任务判据还有多远。** 每条终止或成功判据都配一条余量曲线，并记下是哪个部位、哪个量最接近越界。这是信号时序逻辑里“鲁棒度”的思路。它能说两件别的尺子说不了的事：失败时是什么碰了线；成功回合平时离线有多近。
- **成功尺：和成功回合在同一阶段比。** 按任务的阶段变量对齐，用成功回合在每个阶段的分位带当作正常范围，再用另一部分成功回合校准，使成功回合被误报的比例固定在约 5%。[FAIL-Detect（RSS 2025）](https://arxiv.org/abs/2503.08558)用的就是这类随时间变化、有统计保证的阈值。成功回合太少时，退到上一代或参考策略的成功回合，并明说参照不足。
- **父代尺：和上一代策略比。** 同样的分位带，用父代的回合来建，回答“行为变了什么”。

### 3.4 事件、失败形态、未归类

- **事件。** 持续越界的一段记成一个事件：哪个量、往哪边、何时开始、持续多久、最大偏离多少。再加离散事件：接触的建立和消失、扰动、终止。
- **每回合的事件表。** 按时间排，二三十行以内。它是给模型看的“发生了什么”，不是给作者的成品。
- **失败形态。** 先按终止原因分，这是每个任务都有的；再在每个原因内部按事件模式聚类，取每类最居中的回合当代表。规模太小的类和离群回合单列为“未归类”，附它们各自的事件表。
- **安静的失败。** 终止前没有任何量离开成功范围的失败，直接这样报告，并给出规格尺上的余量和成功回合的贴近程度。

机器人学里已有先例：[Gupta、Ciftci、Bansal](https://arxiv.org/abs/2506.06570) 从大量失败日志里无监督地归纳出失败分类并用自然语言命名，在室内导航上用它指导补数据，失败率从 46% 降到 18%，均匀补数据只降到 34%。他们是先让视觉模型逐条解释再聚类；我们在仿真里有全部状态，可以把“逐条解释”换成确定性的事件表，更便宜也更准。

### 3.5 命名与成句：先提出，再复核

- 给模型的输入：某一类的统计表、代表回合的事件表、机器人部位和任务的简短词汇表。
- 模型的输出：一个短名字，两三句描述。每一句都要附一个可以在特征表上执行的判定。
- 程序拿这些判定在全体回合上跑：它选中的回合是不是这一类，成功回合里有多少也满足，句子里的数字是不是对的。不过关的句子丢掉。
- 模型从头到尾不读原始数组，报告里的每个数都由程序算。

这是“提出再验证”的通用套路：[D5](https://arxiv.org/abs/2302.14233) 和 [VisDiff](https://arxiv.org/abs/2312.02974) 用它来描述两组文本或图像的差别，先由模型提出候选说法，再在全量数据上逐条验证；[Code-as-Monitor（CVPR 2025）](https://arxiv.org/abs/2412.04455)把机器人的失败检测写成由模型生成、由程序执行的约束代码。泛化能力来自这里：换一个任务，模型写新的判定，核对方式不变。

### 3.6 视觉放在哪

在仿真里，画面不含状态里没有的信息。视觉模型的用处是两件事：看代表回合的连拍，给一句整体概括，供命名参考；指出画面里有而事件表里没有的东西，作为补特征的线索。它不负责测量部位。[AHA（ICLR 2025）](https://arxiv.org/abs/2410.00371)的评测显示现成的视觉模型在失败推理上明显不足，要专门训练才行；LAPP 也是因此选了数值日志而不是视频。

### 3.7 和奖励逻辑接上

作者最终要改的是奖励。每类失败再给一张小表：终止前一两秒里，各奖励分项的逐步取值相对成功回合同阶段是高还是低。哪些分项对这类失败有反应、哪些完全没有反应，一目了然。这是按奖励分项做解释的老办法（Juozapaitis 等 2019），只需要在评估时把每步分项记下来。

## 4. 任务和机器人各自只需要提供什么

| 提供方 | 内容 |
|---|---|
| 任务 | 阶段变量，例如前进进度或“距上次扰动的时间”；终止和成功判据，能算余量的给余量函数；地形或环境的高度查询；条件标签，例如难度分层；任务事件 |
| 机器人 | 部位角色：躯干、足端、手、不许接触的部位；碰撞体采样点，可由机器人模型自动生成；关节限位和默认姿态；质量 |

其余代码不出现任务名词。试验里的核心文件 `generic_describe.py` 就是按这个约束写的。

## 5. 在现有档案上的试验

所有数字是我这次算的。Stair 用 864 回合，Push 用 192 回合，核心代码相同。

| 试验 | 结果 |
|---|---|
| Stair 成功尺：36 个通用特征，用第 1 轮的成功回合建带，第 2 轮校准，第 3 轮检验 | 检验用的成功回合，每个“特征加方向”被标记的比例在 3% 到 8%；失败回合被标记的特征数中位 12，成功回合中位 0 |
| Stair 翻倒类（56） | 全部被标记，最后 2 秒内中位 29 个特征越界；自动分组里基本自成一类 |
| Stair 停滞超时类（39） | 只用“距上次推进过了多久”这一个由阶段变量导出的量，97% 到 100% 被标记，成功回合误报 8%。不加这个量时，逐步速度几乎标不出来，因为成功回合也会短暂停顿 |
| Stair 行进中接触类（78） | 31% 的回合在最后 2 秒没有任何特征越界，其余也没有一致的越界特征。结论是“终止前与成功回合不可分辨” |
| 同一类，换规格尺加几何间隙 | 终止时躯干采样点的最小间隙中位 0.020 m；最近点是左前下角 55 个、右前下角 11 个、底部中心 8 个；间隙在最后 0.1 s 内从约 0.08 m 掉到 0.02 m；此时 0.5 s 平均前进速度中位 0.47 m/s |
| 成功回合在同一把尺上 | 全程最小间隙中位 0.040 m，5% 的回合小于 0.015 m；22% 的成功回合曾低于 0.025 m。分层看：height_ood 42/58，joint_ood 42/70，tread_ood 31/93，两个 id 层合计 3/216 |
| 成功尺顺带发现的事实 | 一个翻倒回合（r2.e68）在终止前 7.8 秒就偏离了成功回合的横向范围，最远偏出 1.93 m。没有人为它写过规则 |
| Push 成功尺加自动分组 | 不看结局标签，分两类时一类是 67 个 not_recovered 加 4 个摔倒，另一类是 26 个摔倒加 2 个 not_recovered |
| Push 的教训 | 只有 59 个成功回合建带时，不做校准的话 62% 的留出成功回合也会被标记。校准这一步不能省 |

把这些拼起来，Stair 最大的一类失败可以写成：

> 躯干前下缘在爬升中磕到台阶（78/182）。之前没有停顿和倾斜，仍以约 0.5 m/s 前进；终止前 0.1 秒内躯干前下角离台阶面从约 8 cm 掉到 2 cm，多数是左前角。成功回合也常贴得很近：height_ood 层有 42/58 的成功回合曾贴近到 2.5 cm 以内。

这句话里每个数都能由程序重算，而且它指向的修改方向是躯干在台阶上的间隙和俯仰，不是 8 次作者调用里两次选中的“抬高摆动足”。

## 6. 局限

- 成功尺依赖成功回合。成功很少时带子不稳，一个都没有时只能退到父代或参考策略。
- 失败只是正常行为的尾部时，成功尺说不出东西，必须靠规格尺。规格尺要求每条判据有可算的余量；算不了的判据只能报“在哪个时刻、哪个部位触发”。
- 几何间隙这次用的是躯干的长方体近似加 12 个采样点，不是真实碰撞体；“左前角”是这个近似下的说法。
- 自动分组对特征的相关性和量级敏感。这次直接用偏离幅度聚类时，翻倒类分得很好，另两类要先按终止原因分开才分得清。
- 事件表原样很啰嗦，一个翻倒回合有三十多个特征越界。说哪些、不说哪些，需要一步内容选择。
- 先后不等于因果。最早越界的量只是定位线索。
- 命名和成句那一步这次没有实际调用模型，只验证了它之前的各层。
- Push 没有肢体数据，所以它“站不定”时具体在做什么，这套做法现在也答不了。

## 7. 怎么检验没有拟合这两个任务

- **代码约束。** 核心代码里不出现任务名词和机器人名词；新任务只写适配器。
- **第三个任务。** 拿一个没参与设计的任务，例如平地速度跟踪或另一种地形，只写适配器就跑通，并且能分出至少一种失败形态。核心代码需要改动，就算没通过。
- **换机器人。** Go2 和 G1 本来就是两种形态，同一套特征定义要在两者上都成立。
- **识别测试。** 给评阅模型一条代表回合的连拍和四条候选描述，选对率；反过来再做一遍。描述越泛，越选不对。这是“解释—模拟—打分”的做法：能不能凭描述认出数据，是检验描述好坏最直接的办法。
- **留出检验。** 判定和带子在一部分种子上建立，在另一部分种子上核对份额和误报。
