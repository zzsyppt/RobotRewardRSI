# 验收职责收敛：全量复算与过程语义分开

2026-09-30。新确认资料尚未采集。本修订用于主计划 v1.4.14；方法已采纳，独立复算覆盖与新评阅材料仍在实施，**不构成 N.5 放行或验收通过**。旧协议、原始回答与失败记录不回判。

## 已经遇到的实际瓶颈

同一旧 Push 证据的 r12 独立 SOL 观察产生了三条可支持的部位端点描述。实际生产投影保留全部三条原文，默认显示一条，报告 11,308 / 12,288 字节，数值过程不变。这说明继续扩展相机、部位、坐标或观察代理数量，暂时不是主要缺口。描述应停留在证据足够的粒度，不能为了“高层”把手、膝的局部变化命名为整体蹲起或平衡策略。

另一个瓶颈来自我们自己的验收方式。最长 Stair 旧报告实际输入约 173,243 代理 token，静态预算可放下；但一次真实执行发生上下文压缩，返回 `complete=false`，原答达 1,591,979 字节、1,934 条 claim。620 条事件被展开成大量重复算术判词，`/shared` 与 `/source` 仍未评完。原答自报 1,931 条 supported 也不能取得通过；它同时只匹配了自己 24 条必要事实中的 8 条。这些不是有效的正式分数，却清楚说明“容易的字段核对很多”与“过程讲完整了”必须分别看。

原探针按原登记失败收尾，不重试、不改答。参见[执行记录](./results/capacity_report_execution_r1/RESULT_ZH.md)。输入代理计数不等于真实有效上下文，程序遍历不等于模型阅读，模型输出大量 JSON 也不等于语义核验完整。

## 两种职责，三个必须分别报告的结果

| 职责 | 范围 | 判定与边界 |
| --- | --- | --- |
| 独立程序全量复算 | 原始测量按明确定义得到的事件集合、部位、类别、起止/确认步、布尔与 null、计数、极值、稳定驻留、恢复后再失稳、范围和身份引用 | 从原量独立计算，不调用生产 reducer 生成“真值”。不只检查已报告行，还检查遗漏、多报和错误排序。覆盖清单内全部一致；任何未核字段列明，不能宣布本轴完整。 |
| 两家模型独立语义评阅 | 正式词条的含义与限制、全部实际文字及引用、关系和范围、主要过程、未知与冲突、过滤前全部视觉句及不确定性 | 判断测量有没有被扩大解释、并行有没有被写成顺序、局部有没有被写成全身、端点有没有被写成连续动作、相关有没有被写成原因。数字正确不能替整句话通过。 |
| 必要过程覆盖与定位 | 两位评阅者先看原始全程，独立封存五束必要事实；再匹配完整派生、短报告和最终请求 | 不以生产阳性或模板决定必要事实，不按每帧增事实。仍采用必要清单并集、保留争议、遗漏计失败；完整派生与实际送达分别报告。 |

这里的程序职责不只是“数字”：例如 `confirmed=null`、FL/RL 身份、`slip_any` 与同一脚持续打滑的区分，都是可以形式化、也会出错的对象。对应词条为什么只能这样解释、文字是否越过这个边界，仍由模型评。不能让数值脚本顺便宣布“步态正确”“发生碰撞”“原因确定”。

保留所有原对象和 locator，并在采集前冻结检查责任清单。允许同一种形式化定义的重复实例共用一个语义解释检查，但每个实例须独立复算；所有实例中的自然语言和新关系都不能因此免评。没有独立操作数或没有明确公式的项，不能为了省 token 被划进程序已核区。

**成绩不混算。** 确定性一致性要求覆盖内 100% 一致；语义支持率仍为 ≥95%，必要过程召回与定位仍为 ≥90%；视觉原始全部句子的画面支持仍为 ≥90%、越权为 0。两任务、完整派生/短报告/最终请求分开。程序通过不作为两个模型的票，也不作为语义支持分子。语义分母改变为实际解释与关系，因此新方法与旧“全部标量逐命题双评”的分数不可直接比较；旧轮次不能套新方法重写成通过。

## 本轮只做必要的工程

先复用既有原量、独立重算脚本和完整报告，补齐上述责任清单的真实覆盖。新增入口只用于实验验收，放在 P3NEW；生产模块继续不依赖 PLAN。不引入评测框架、数据库、分片调度、多轮辩论或新的摘要模型。

输入仍保留相关量完整 1..T 曲线、完整派生、独立封存事实及实际显示的全部原图；本次不以“职责划分”为由删时间点、只给规则阳性段或发送生产过程摘要冒充原量。先消除输出端对同类算术的成千次复述，再按最终真实材料核验执行容量。原量中未知的新关系仍应由评阅者先于报告发现。

程序辅助计算可以使用，但访问记录须区分“文件可用”“CPU 全量处理”“模型实际看到的原量/曲线与图像”。两家获得同字节证据，不要求假装拥有相同工具或相同内部处理过程；差异须事前登记。当前未新增工具式 API、多请求拼接或自动压缩方案。原探针发生压缩的事实不因本修订消失；正式前仍须解决完整评阅的可执行性，不能把压缩后未核范围隐藏掉。

## 观察者载体的真实边界

观察者允许 API 或桌面独立 agent，正式采集前按任务固定，不能看到确认结果后择优。

- API 留实际请求、回复、模型/推理配置、fingerprint 与 usage；按既有合同核对开发与确认的服务端版本。
- 桌面 agent 使用全新无开发上下文的角色，冻结可观察的模型/推理配置、任务指令、文字与原图 hash、读图记录和原答；无法获得的服务端 fingerprint、精确 token、费用及内部缩放写 unavailable。只声称相同可观察配置，不声称同 HTTP 字节或精确服务端版本。
- 当前开发依据分别是 Stair 的 r10 与 Push 的 r12；正式卡拟沿各自载体，仍需冻结最后输入与配置。两家正式评阅者为 DeepSeek 与全新 SOL；其中一家可与观察者同家族，相关误差明确披露，评阅者不能继承观察者或开发上下文。

这只消除“已允许桌面评委、却要求桌面观察者提供不存在的 API 回执”的合同矛盾。模型评阅不是物理真值；r12 的 3/3 是一个旧案例的开发判断，不能作为新确认的合格率。

## 研究与工程依据，以及不作出的推论

[RULER（COLM 2024）](https://arxiv.org/abs/2404.06654)把检索、跨段追踪与汇总分开，显示声明上下文长度不能替代任务上的有效利用能力。本项目据此区分静态可放入与实际能评完；论文没有测过本轮模型，不能拿其旧模型结果预测本轮准确率。

[Inspect 的评分设计](https://inspect.aisi.org.uk/standard-scorers.html)区分确定性与模型评分；[评分策略](https://inspect.aisi.org.uk/scoring-policy.html)进一步区分被测输出错误与评阅工具失败。本项目借鉴职责与失败归属，保留评阅未完成；不迁移整个框架，也不采用删除未评样本后宣布通过的汇总方式。

[SoM](https://arxiv.org/html/2310.11441v2)支持适当标记帮助区域指代，但并未证明给任意模型加坐标就能理解机器人过程。因此暂不增加标记图。我们的优势仍是同状态多视角与可复算仿真量：测量组织过程，图像补形态，独立核对限制措辞，短报告向作者交付必要信息。

## 采集准备与评阅验收分别管理

v1.4.17 在新确认资料产生前修订此顺序。旧长包的几次实际执行没有完成，原失败不改判，也不追加同例模型尝试。其暴露的奖励 ABI、单包职责与匹配接口已在材料源头修正；这些是有具体依据的开发改动，不是正式资格。让旧模型回答完整成为采集的无限前置，没有增加资料独立性。

1. **采集前冻结。** 冻结最终生产源码、任务与测量定义、原始 cohort/seed、选例/缺类/选窗、字段与核验责任、完整材料表示、观察者/模块核对者/独立评委角色、阈值、失败处置、调用与存储预算。独立复算已有旧资料及错误变异检查，范围与未核部分如实登记。资源和实际命令检查完成才运行；静态预检不算采集成功。
2. **采集后先检查资料，再封存 facts。** 实际加载、1..T/同状态/末帧、画质、真实终局、最终文件长度只能由新运行核实。依冻结规则构造完整材料；每包在发送前按实际字节和该评者自己的完整事实原答核容量。两家全部事实封存后才进入任何报告评阅。所有共享定义仍在原包完整评阅，本轮不新增任务级定义分包或跨请求汇总。
3. **评阅完成才判资格。** 实际模型阅读、语义覆盖、完整事实匹配与各轴成绩仍须验收；任何压缩、漏评、超限、零事实或引用缺口保留未完成，不删除难包。若必须根据新资料修改规则、提示、表示或拆分，整包转开发，另冻未用 cohort。采集完成不能被称为语义通过。

这是两个依赖门的拆开，保真阈值、24回合/12焦点/4媒体单位、事实先行和确认集修正纪律均不降低。P3-NEW 保持 `IN_PROGRESS`；没有通过完整验收，不进入 3-live、P4 或新训练。
