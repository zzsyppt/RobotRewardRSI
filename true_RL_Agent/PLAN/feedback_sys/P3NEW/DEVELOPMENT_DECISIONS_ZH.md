# 开发期边界修订

2026-09-29。本记录在新确认采集、观察者调用与作者烟测前形成；初始实施卡和 development_start.json 保留原件。

1. **描述性词条的对照不应靠改名绕过。** 原主计划描述合同允许附成功侧比例，而严格项一度完全禁止。实际 Push 开发数据中，速度条件曾违反为失败14/14对成功13/13，明确给出这组非区分性对照有助于防止作者误认主因。故保留 S2 的显式例外：仍标 descriptive=true，携带两侧范围、分子分母与 `discriminating=false`，文字明确“不具区分力”。不能换一个谓词名称或抹掉描述性标志假装通过。公用 lint 只检查这份结构与显示合同，不定义物理区分阈值；任务词条卡负责意义。主计划相应条款同步澄清。
2. **完整派生单独成工件，phase 保留引用。** Stair 实测完整旧测量派生约26.7 MB，新语义元数据约0.19 MB。把完整副本塞入每个phase-summary会使重放反复加载大对象。因此写入phase目录的 `behavior_full.json`，task_evidence仅保存文件相对名、sha256和size_bytes；沿用原phase封存哈希，不另建存储服务。作者只读有界behavior投影。此处替代实施讨论中临时采用的inline提议。
3. **差分必须包含行为。** S4至少陈述一个可比较的过程量及两侧n/N、规则版本与配对范围，不能只给成功率变化来冒充行为差分。父本版本不兼容或配对不足则按实际缺口表达。
4. **专项抽样与联合覆盖分别计数。** 残差/缺对照专项按冻结哈希选 `min(k+u,4)` 个回合，独立于层×结果基线；允许重叠，既不要求再找四个基线外样本，也不把基线已选的其他残差回合从联合覆盖中扣掉。严格项4澄清为专项数与联合覆盖分别核对，避免把覆盖更多误判成超过专项数。未联合选取者仍逐回合保留。
5. **观察原话与量化命题分开。** 不用关键词匹配把“几乎不动”自动翻译为净位移小。媒体可公开任务登记的测量定义，观察者可选填 `numeric_claim`；任务核对同源L0的显示步骤，结果只支持或反驳该量化命题，不给整句视觉盖真值章。首版不做前/后倾映射；相对环境原点高度不任意称为身体离地高度；窗内未显示的异常不能证明画面看到了它。未知形态保留为仅视觉，不强迫选择命题。主计划§3.4的宽泛映射同步修正。
6. **视觉文字预算先收敛。** 每回合至多3条，原话≤200字符，不确定性≤40字符；完整原文全留档。默认报告先保留一条有界视觉原话及全体观察/遗漏统计（冲突优先，其次可核命题，再仅视觉，稳定原顺序裁决）；不截断原句，不通过过滤改变N.3全部观察分母。若一条仍无法容纳，应精简重复模板，不能删反例与残差或扩8/12KiB上限。此限制在任何真实观察者调用前确定。

## 仿真测量与互补视角

依据用户后续关于取景、全身可见性与仿真额外信息的指示，主计划v1.4.3明确采用测量时间线、过程关系、互补视觉、带来源报告的顺序，详见[设计与研究对比](./SIMULATION_EVIDENCE_DESIGN_ZH.md)。本次不改变 US$15 / 2 GPUh 总额及各预算分配，也不重新启动作者 A/T 价值比较。

- 先做有界同状态双视角原生快照与任务当前已有的少量 S0 字段；深度/分割/更多接触量按具体未解问题补采，不搭建全量传感平台。
- 相机证据以最终 capture manifest 的实际 samples、step/view 和图像 hash 为准；请求过某一步不等于实际有图。新读取函数保持原图字节和标签，任务仍负责绑定 run/episode/数值档案以及检查采样时点。
- 独立有名的 root 位姿/速度字段替代版本相关的 `root_state_w` 切片；四元数排列、世界系及 link/COM 参考点写明。
- [时序审计](./SAMPLING_ALIGNMENT_AUDIT_ZH.md)发现 Push velocity/v2 在数值采样与旧 step 后截图之间还有 interval 注入。源头收敛到任务已有的 pre-reset 媒体回调，两种扰动机制共用，不以切换到 force 协议回避错位。历史媒体及评分保持原覆盖解释。
- CPU 接线检查与实际双视角/NPZ 对齐、模型最终输入可辨性分开登记；后者尚未完成，不凭文档或单测宣布 N.3/N.5 通过。

## 质量优先：用户解除采集耗时上限

用户在双视角开发 r1 超时后明确要求“无需考虑训练采集用时等预算，追求更好的效果”。据此撤销后续采集的 2 GPUh 总额、正式/开发分配及按剩余 GPUh 缩短 timeout 的做法；上述记录和冻结卡保留为历史，不能再作为提前结束采集的理由。新运行按实际规模留足完成时间，仍检查进程是否前进、保存实际用量及失败。API 调用卡和模型上下文边界独立管理，不通过无限调用刷验收。

已证实的采集缺口同时从源头修正：少数固定步会遗漏未知过程后段；Stair 旧 wrapper 在 env.step 后取图，终止步已经 reset，只保留到 T−1。Stair 的任务成功还可能早于 Gym done，且 tracker 在 CPU 分块后才得知 T，因此不猜测末帧，也不重放补造“同状态”媒体。采用任务自己的 pre-reset 接点，并允许逐控制步原生双视角落盘、在真实任务结局 T 裁出首回合；原始图流式保存，避免全回合 RGB 驻留内存。报告和观察者仍按问题选择有限帧，显式记录未送达范围。工程和真实渲染/数值对齐分别验收。

双视角开发 r1 Stair 的 eval 在 340 秒 timeout，phase lease 341.901514827 秒，加 probe 0.199489564 秒；按双卡容量为 0.190056114 GPUh。仅有两组快照与未完成 NPZ chunks，无最终 numeric manifest/summary，不作为完整封存样本。与旧机位开发合计 0.755761603 GPUh。Push r1 未启动。后续使用新源码封存、新输出目录和新采集卡，不覆盖本次失败。

## 确认集隔离的实际边界

在N.5新资料尚未采集前检查现有材料构建：旧 `confirmation_raw_material.py` 导出完整 raw_pool，完整 behavior_full 也包含全池过程，五束问题需要组级事实。因此采用“同池第一批发现问题后，换ID调用未揭示储备”的表述不诚实，且若为此新造多批次隔离平台会扩大复杂度。主计划v1.4.5改为一次24回合整体独立评阅（两任务各12），保留双方原始事实先封存、后看报告；任何据确认资料的系统修正使整包转开发，重新冻结真正未用cohort。原阈值不降，历史失败保留，重复测量不算新资料。选择算法在采集前冻结，依原始结局机械得出的成员在报告揭示前封存，不按报告表现挑例。

顺带修正主计划现状表的过期描述：Push新base seed已由生产composition/cohort/计划绑定并经合成CPU测试，尚待真实合格G1来源的新卡preflight与回执验证；不把开发r3使用的旧seed当作新cohort采集。

## 原始媒体覆盖与实际输入容量分开

主计划v1.4.6允许同一次rollout预选两个env、三个seed，共六个原始媒体回合；模型每报告仍最多四回合/24图/96子帧，按冻结终局分层与哈希选择，所有未发送资料留覆盖记录。重复完整cohort再拼媒体会破坏archive/source binding，因此采用有限多env同步录制，公用层仅处理索引/相机/文件，任务拥有各env真实T；接口工程与真实切换仍须验收。原始成功/失败缺类不靠换env重跑冒充新样本。

N.4视觉烟测明确采用两任务各一份同源旧开发重放包。此前四个文本案例已完成，新增两次视觉首包仍在8episode范围内；新画面/数值不得挂到旧full，原始phase/full保持原字节。只使用实际观察者输出，不合成冲突或父子差分；未暴露项如实记NOT_EXERCISED。历史调用和费用累计，不复开预算。这是读法烟测，不是A/T比较；N.3开发级输入/传输核查先做，N.5独立语义门随后，避免互相等待。

另纠正媒体必须来自N.2已选episode交集的假设：N.2目录依原始终局形成，采集前固定的两个env未必进入目录；强制交集会使有限真实媒体几乎无法使用，扩大到全env渲染则无必要。媒体改为独立预登记覆盖层，复用任务窗口定义，分别记数值专项覆盖、媒体覆盖与两者交集。生产attachment已经按完整档案核source/episode，不需要增加新gate或公共任务语义。
