# Phase 2 实施与验收卡

2026-09-23，起点 `b24ddfe9e54c7cc93318a4c6a2675eb9fb799d20`。用户明确要求完整 P2：Stair、Push 基础采集及训练早／中／晚采样。依据主计划 v1.2.5、P0 范围卡与 P1 审计，不以 Stair 的 P2-min 代替整个阶段。本卡的目标、容量与不变性门槛在新模拟器验收结果产生前登记；实现细节按实际接口调整，验收门槛不因结果不利而降低。

## 目标与边界

把 runner 已观察到、解释行为所必需的数值过程保存下来，使离线工具能从档案重算终局、已有统计与过程条件；先提供可信输入，不在本阶段宣称已交付高层解释、视觉诊断或搜索收益。任务拥有字段、身体映射、时间定义和复算；共享层只处理有界数值块、内容 hash 和最后发布的目录。生产 src/scripts 与测试不得读取 PLAN。

同一新运行的档案必须在新 phase／训练回执封存前完成并绑定。旧摘要含义保持，旧回执不回填。公开过程仅来自 public-dev；accept/sealed 不进入作者工作集。数值 complete 与媒体未采集分开。候选权限、奖励计算、任务终局、训练预算和接受规则不变。

## 实施顺序与交付

1. **收敛 P1 小项。** 核实旧 width-one 的零填充来源，把缺少正步数与声明项数的零调用保留为 unknown。去除只为 P1 审计中间字典格式设计的重压缩兼容；保留实际旧9列和当前短状态。历史审计样本仍保留，不能声称它们不存在。
2. **合法祖先准入。** 复用 task 已验证的 evaluation-only successor 链及训练合同，传递可验证的准入依据，让 fca 的 v1 训练 manifest 进入当前 v3 评估。核对权重、训练 receipt、源 manifest、policy I/O、机器人 binding 和训练 origin；不能改历史 manifest 或仅放宽 hash 名单。
3. **最小公共存储与任务档案。** 有界分块数值文件，原 dtype、坐标系、字段覆盖和缺失状态明确；每块 hash，最后原子发布 manifest，再绑定既有 receipt。无需数据库、MCAP、后台服务或通用事件词表。损坏、不完整、重复发布只用与实际失败相关的少量验收。
4. **Stair 评估过程。** 复用 pre-reset 原始证据和现有 decoder／tracker，保存带符号姿态所需四元数、base/支撑位置、支撑速度与接触力向量、forbidden 接触力、关节位置、termination/reset 时序及身体映射。保存完整首 episode 的有效覆盖，不将 reset 后自动开始的第二回合混入；静态几何／协议／映射只存一次。分块处理代替整 seed 的 Python 历史堆积。首个问题仍是“禁触前出现了什么可测事件，成功组是否也出现”；可选全 body 力在确有必要时再开，不新增传感器。
5. **Push 基础过程。** 保存当前评估实际使用的姿态、高度、速度、漂移、逐步稳定子条件及扰动时序。velocity 按 event、force 按最后 pulse 结束后的 sequence 定义恢复窗口；保存并发失守、dwell 重置、恢复与终局再失稳及删失，不采集当前不存在的脚部接触。
6. **训练采样。** 在既有训练执行／奖励统计边界按事前固定窗口保存早、中、晚样本；记录真正经过的迭代／步数、term版本／来源、实际贡献、采样分母及未到达／未采样。完整训练仍由原 receipt 决定成功，短验证运行不能冒充完成训练；不以评估回放代替训练证据。
7. **独立回读与真实验收。** 从持久档案重算，核对新回执绑定、覆盖和容量，再做真实 capture on/off 对照。继承 P1 的作者投影与预算回归；档案存在不等于已提供给作者，默认 prompt 不复制原始时序。

## 事前验收门槛

- 先以 CPU 反例验证身份／缺失语义、正常块读取、损坏／未发布不可消费、重复发布不覆盖；测试目标是这些真实不变量，不扩建攻击矩阵。
- Stair 首批固定 fca6a59c… parent 与 bcd8de3a… Gen8-A，在同一当前 v3、同一完整 public-dev cohort 重评，每个策略 864 个首回合。覆盖成功、禁触和其他终局；保存全部有效控制步和其真实覆盖，终止步必须是 pre-reset。
- 从持久证据复算每个 episode 的终局、进度、既有 ever/max/dwell/持续统计，离散结果完全相等；原始同 dtype 浮点保存无精度降级，派生浮点比较绝对误差不超过 1e-6。首个问题的事件顺序可定位到控制步，未到达对齐锚点不能被排除出分母。
- Capture on/off 使用相同 source、policy、协议和 seed。首先要求终局及主要统计完全一致；若平台非确定性导致差异，不能直接宣告无影响，须独立重复无 capture 对照识别噪声后审定，不能事后放宽门槛掩盖系统性偏差。
- Push 为每个最终声明支持的协议／形态运行真实案例，包含成功、失败／删失和短回合；从持久数值与事件定义复算稳定条件、dwell 和恢复时序，终局及分母与原结果一致。声明范围不足则补验证或明确该 profile 未完成，不用 Stair 替代。
- 训练采样真实执行到早／中／晚窗口并绑定相应来源与贡献；未到达窗口有明确状态。关闭采样不改变奖励值与训练配置；采样不能形成第二套运行真值。
- 首版每个档案磁盘上限 2 GiB，单次编码原始块上限 64 MiB；采集额外峰值 RSS 上限 512 MiB。每次报告实际数组 dtype、原始／压缩大小、峰值内存和 outer／rollout 耗时。配对真实评估的采集 rollout 额外耗时目标不超过 25%；超过则优化并重验，不靠忽略压缩时间通过。
- 数值档案只能最后发布一次；未发布及损坏不可视为完整。媒体未启用明确标注，不因没有媒体阻断数值 CORE。
- 生产不依赖 PLAN；原摘要重放、公开边界和14 KiB记忆保留回归继续通过。各任务语义不进入公共容器。

沿用 P0 已分配的 8 GPU容量小时、0 模型费用作为本轮初始总上限；包含失败、对照和训练采样验证。先测即时GPU占用和既有 lease，不干扰其他工作。若完整范围接近额度，先报告实际缺口并从总项目预算按既有规则事前重新分配，不用少做验收冒充完成。原权重复用，不启动为生成历史训练样本而进行的补训。

## 执行范围的具体化

运行卡按上述范围落实为：Stair 当前 v3 的 Go2 parent、Go2 Gen8-A、G1 reference 各一组 capture on/off；Push 的 G1/Go2 × velocity v2/force v3 各一组；训练为 Stair/Push × G1/Go2 当前 v3 reference 各一组。评估各自使用完整 public-dev cohort，三组 Stair 每组每侧 864 回合，四组 Push 每组每侧 192 回合。

训练验证使用已有受限执行入口：Stair 每次 16 环境 × 8 控制步 × 1 rollout，Push 每次 16 × 8 × 3。其早／中／晚是这次短运行的预定区间；长训练的同一调度器由 CPU 边界测试覆盖。该验证不替代完整预算训练、不认证策略、不声称学习收益。训练档案只通过现有回执公开投影少量覆盖状态与分母，原始 term 样本留在附件。

真实失败先保留并解释，再冻结新源码、使用新输出目录重验。旧版本成功不得自动迁移为新源码证据；仅当变更不涉及受测运行路径且有逐文件差分记录，才复用先前对应范围的验收。
