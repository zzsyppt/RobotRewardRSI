## 估算改成工作负载内的实用工具

原公式 `ceil(bytes×0.4122757573)+512` 是历史4点最大ratio另加25%余量，五个新输入高估38.1%–58.2%。旧参数文件、重复估计字段和一次性prepare/run脚本已删除；原receipt中的reservation作为当时记录保留，不再重建旧估计模型或把“全部覆盖”当作能力资格。

现在只用历史4点拟合，另外5个不同输入检查误差：

`预计输入token ≈ 0.3735825×用户JSON字节 − 5100.52`

五点最大绝对相对误差 **7.60%**，均为高估；远好于原估计。9点一起拟合可得到约5.7%的残差，但那是拟合集内误差，不能叫独立验证。模型形式是此次看过数据后的工程选择；样本共享源码/历史家族，仍需用后续自然调用usage观察漂移。

适用范围为相同模型/固定system包装、约49–115KB的类似文本输入。负截距不能外推到小输入，图像也不套文本公式。Phase 1接入时用这个局部估计加合理余量，为输出留空间；换模型或输入域后重新校准，按真实usage记费用。取消单独的strict-token资格门，当前约3万token输入没有必要为近百万级上下文建设另一套证明系统。

当前长历史中反馈18,668字节（18.71%）、public_history20,809字节（20.86%）；反馈从43.41%位置开始，候选输出合同在84.98%。minimum-core后历史仍22,095字节、源码12,035字节。下一步应去掉重复、保证当前parent/待解释trial证据有位置，随后再建设全局预算与检索。

相同长输入重复时cache从512增到29,696/29,907 tokens，说明该次前缀缓存可用；缓存省费用但不减少上下文占用。

## 图像传输和实际媒体能力

P0使用既有 `deepseek-v4-flash` 配置，实际回执模型 `deepseek-flash`、fingerprint `aeb56401ca74e127821c4f9126dcb669`。生产作者请求目前仍为文本。

无图/有图配对输入79→657 tokens，增加578；同一原生帧成功传输，回复识别机器人、四条可见腿、网格地面和站立。费用差只适用于这一请求，不能当每图固定价格。

视频来源为P6 pose diagnostic replay，第150帧原样解码，未裁剪/缩放。原包覆盖3个seed各env32的一回合，每个302帧，episode303步，从control step1开始，pre-reset取图；历史终局一致并不能证明逐步轨迹一致。1280×720图中机器人约110×106像素，粗姿态可见，精确脚尖接触、厘米级净空或碰撞面尚不足。

`NativeVideoRecorder.record_step` 当前把RGB副本一直放在 `_frames` 中到finish；302帧仅像素约796.29MiB，600帧约1.545GiB，实际峰值还含其他开销。Phase 6需先改为有界采集/编码并测RSS，再扩展原生视觉。
