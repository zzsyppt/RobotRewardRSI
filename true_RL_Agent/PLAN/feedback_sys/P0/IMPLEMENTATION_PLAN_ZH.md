## 目标和范围

建立可重跑的源码、数据、输入成本、实验来源及运行条件基线，决定下一阶段能做什么。完成 P0 不等于诊断、视觉或收益已经通过。保持任务、协议、reward ABI、初始化、训练和 acceptance 不变；本阶段不训练、不启动 simulator、不修改生产反馈语义，不删除他人的未提交代码。

## 实施分解

1. 固定当前 dirty checkout：记录 HEAD、git 状态及相关源码/配置/测试内容 hash。逐任务核对原始观测→持久证据→公开投影→实际作者输入，并运行对应现有修复的 CPU 回归。
2. 从原始 JSON/回执建立案例与 checkpoint 清单：文件副本、权重身份、训练 attempt、初始化/seed、祖先/session 分列。核对远端实际存在性，不把同次训练的迭代或复制算独立训练。
3. 用生产序列化与请求构建器测量初代、长历史、source followup、repair、minimum-core。历史回执与本轮重建输入分别保留。统计真实 UTF-8 字节、段落占比/顺序、系统消息开销、usage/cache。校准集固定为已有 P5 四类 usage，验证使用不同冻结输入；重复同一输入只测漂移/缓存，不能算独立验证。
4. 复用项目已配置的 DeepSeek 接口做有限真实计量（若凭据/端点不可用，保存失败并收窄资格）。只生成极短答复，不生成/训练新候选。媒体探针单独验证 image block、usage 和可见内容，不接入作者链。保存原生录制覆盖、相机可辨尺度、缓冲估算与回放限制。
5. 汇总资源、最小闭环卡和严格验收。建立产物校验器核对 hash、数量/分母、成本回执和状态。反例先修取证脚本或所有权层，禁止仅改报告结论。

## 验收项目

- 两任务地图覆盖源码/协议/形态、reward-time ABI 与 offline 证据差别；四种可用性可追到具体生产者/消费者和保存产物。已有修复有本轮回归，不靠旧日志判 PASS。
- 五类输入均有可校验原件或可重跑生产构建、来源 hash 和明示真实历史/重建/强制分支身份；有实际 usage 的逐项绑定，缺历史 minimum-core 回执必须明说。系统/用户/HTTP 字节分别统计，不冒称按段字节等于按段 token。
- 独立验证经验估算覆盖已冻结验证样本，并报告最大误差/样本限制；**strict-token profile 允许 INCONCLUSIVE，不能伪称 P0 为它提供了严格证明**。
- 原生媒体有覆盖和来源边界；远端视觉能力按实际探针判定，未实测不算 VISION 通过。CORE 路线可独立继续。
- 案例清单能重算文件/权重/attempt/session 数量，缺失 lineage 不填造；候选选择不得使用 sealed 明细。至少明确一个有资格及余量的开发域，或明确其资格缺口。
- 输出项目总资源封顶、下一阶段上限和最小闭环卡。后续阶段执行仍须各自启动验收卡；本卡没有授权一次性消耗项目全预算。
- 所有必选证据表/回归与校验器成功；失败、未知和延后另列。P0 PASS 只表示“可核查基线和范围建立”，与后续能力资格分开。
