## 两处可复算的关键修正

### 014：评阅者也漏了奖励中的常数

在角速度为0、当前没有注入增量时，候选约在平面速度0.8156 m/s达到-8裁剪。参考完整速度奖励项为约 **+0.1790**，并非评阅理由中的约-0.8；后者近似算了惩罚部分，遗漏参考的+1。按dt=0.02，一步对应约+0.00358和-0.16。

这不使014变为正确建议：其零计数和“only self-generated”两个问题仍然成立。只是不能用错误的算术支持其他批评。

### 042：未来目标不自动构成历史事实误读

代码82行正确写的是 frontier **scores** 0.6255；93行在预期测量中要求 **success above** 0.6255。该目标高于实际成功率0.5093是允许的。目标数字与旧score相同，足以提示澄清指标，却不足以证明作者声称旧success为0.6255。

不把该句算硬数字错误，也不代表候选机制可靠。body-frame正向速度的奖励漏洞和梯度因果叙述仍需保留。

同一提案94–95行还有独立的规则理解问题：c0_id/c1_id均不低于0.95，并不能保证实际named-guard-min的0.05回归上限成立。seen-042的public_eval_contract明确还包括j_ood、joint_ood和phase_control，并采用逐seed最小guard再汇总。原评阅已发现此点，后来按H3不计硬错误；该规则误读至少应明确保留，不能把“没有实际改动闸门权限”混同于“对闸门的解释正确”。是否纳入哪类硬错误，应对所有项统一定义。

### Stair r1.e64：支持失败过程，不证明奖励原因

[画面：g64_r1_zoom.png](../review_video_20260924/g64_r1_zoom.png) 显示前身立起，随后向后并伴随侧向翻转。

- 对应frontier L5，426步禁触终止。
- 末段low_progress为369–426；tilt为385–426、394确认；414–426无瞬时脚部支撑；426触发禁触。
- 这支持该回合“低进展→持续倾斜→失去脚部支撑并翻倒→禁触”的末段过程。更早也有倾斜事件，不能把这个片段冒充全程第一次发生。
- 它给放宽俯仰惩罚的提案提供风险证据，但未测试改变奖励后是否仍会走到同一状态，不能直接证伪015的学习假说。

[画面：g156_r1_zoom.png](../review_video_20260924/g156_r1_zoom.png) 显示低身体姿态和反复腿部运动。配套回合height L4、232步禁触，未触发持续tilt；图像不足以精确判定首次接触身体点与台阶面，因此不将“腹部撞台沿位置”当成已独立确认。

### Push：有迈步，不等于迈步的幅度和时机充分

[画面：gp55_r1.png](../review_video_20260924/gp55_r1.png) 是repeated层的env55/source0：有明显脚步调整，后段步距变大并屈膝失稳，111步前倒。这反驳“该回合完全不迈步”，但不反驳“奖励可能限制迈步幅度/时机”。

[画面：gp12_r1_end.png](../review_video_20260924/gp12_r1_end.png) 是low层env12/source0：末段身体保持直立且脚位置变化，412步not_recovered，末速度0.343343 m/s，终局失守条件只有planar_speed。不能把这个low回合推广为medium/repeated的机制结论。

进一步重算完整Push证据：51个not_recovered回合，终点最大|roll|约0.113、最大|pitch|约0.118 rad；但其中 **9个回合**的恢复窗口曾出现roll或pitch条件失守，分布为medium1、high4、repeated4。例如source1/env25的medium回合，roll在79–92步失守。

因此原总报告“未恢复的回合全程直立”应改为“终点姿态基本直立，部分恢复窗曾姿态失守”。不能用终点正常代替整段轨迹描述。姿态失守也不自动证明降低或提高姿态惩罚有效。

## 对本次价值门的影响
