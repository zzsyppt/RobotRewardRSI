> 创建：2026-10-02；本次修订：2026-10-03  
> 版本：v1.1；依据审计记录与源码交叉核查修订。  
> 范围：true_RL_Agent；先离线生成可核查的策略行为卡片，再接入公开反馈。  
> 本次交付：仅修订本计划。没有实现系统，没有调用模型、连接服务器、补采、训练或重新计算审计实验。  
> 核心目标：不额外训练模型，把整代策略的完整数值轨迹转换为有依据的行为描述；逐回合证据支持查询，视觉负责待验证的增益，原因与修复效果另行验证。

## 0. 先读这一页

**第一版应该做成“完整轨迹数值分析器＋策略行为卡片”，而不是要求每个回合先经过视频模型逐段翻译。**

给作者模型看的主要产品是一张卡片，回答：这一代通常怎样运动；失败前发生了哪些过程；这些过程出现在哪些条件、多少回合；相对父代变化在哪里；现有奖励对这些行为实际如何响应。单回合时间线是卡片的可展开证据，只有需要时才生成完整叙述。

~~~text
全队列原始数值记录＋机器人/任务契约
    ↓ 校验对象、时钟、单位、有效性与输入权限
默认测量目录：运动、肢体关系、接触时序、任务进展
    ↓ 原始短事件保留；连续状态和多对象关系分轨组织
逐回合证据账＋可组合的时序查询
    ↓ 全部回合统计；成功/失败/条件分面；父代对照
策略级行为卡片：事实、频率、反例、缺口、奖励响应
    ↓ 任务拥有的模板、主张核查、容量与公开投影
实际作者请求 → 修改候选 → 原协议下独立验证

可选旁路：少量代表例＋无报警随机例的全程视频概览
    → 提出遗漏关系、核查身份/几何 → 查询验证或保留视觉限定观察
~~~

本版决定：

1. **数值分析覆盖全部可用回合、全部有效时段。** 不只取失败窗口；也不要求把每个控制步都翻译成一句话。
2. **默认就会算、会说一些有用的行为量。** 先提供明确的测量目录和允许句式，再保留开放组合入口。
3. **先绝对描述，再比较。** 零成功策略、无父代或参考样本不足时，仍能交付行为与失败过程。
4. **测量、事件、时序组合、卡片统计分别验证。** 模板成句不免除事实核查，模型可选命名也不能提高证据等级。
5. **视觉是独立的可选发现与复核通路。** 先验证它增加了哪些正确且有用的事实，再决定是否扩大；不能只看程序已经报警的片段。
6. **捕获缺口尽早处理，但不阻塞现有 Stair 数值原型。** 先交付可测部分，按新增能力补采，而非承诺一次采完所有状态。
7. **轻量验收先行、强结论另设证据门。** 自动回归＋真实材料抽查支持受限离线试用；跨策略、新任务、新形态和闭环收益分别评估。
8. **事实、机制假说、修改建议和接受决定分开。** 未知可以被准确描述；不能保证未知机制都能被识别。

第一版只需五类职责：证据契约、测量目录、时序组合、队列聚合、卡片及公开投影。复用现有视觉调用和任务报告模块；不引入逐回合多 agent 辩论。

## 1. 产品目标与能力边界

### 1.1 主产品：一张策略行为卡片

面向一个固定策略及其公开评估队列，卡片包括四块：

| 卡片内容 | 首先回答的问题 | 必须保留的限制 |
|---|---|---|
| 总体行为 | 怎样移动、各部位怎样参与、有哪些长期状态与重复结构 | 先全部有效回合，再成功/失败/条件分面；不能只看成功回合 |
| 失败过程 | 终止前出现哪些可核查过程、持续多久、还有没有恢复尝试 | 终止标签由任务评估器提供；过程模式可跨终止类型 |
| 对照变化 | 与成功样本及父代的哪些行为不同 | 明示匹配条件、有效分母、样本不足和比较范围 |
| 奖励响应与可操作性 | 已记录或可精确重算的奖励项怎样响应这些状态；允许修改什么 | 奖励响应不是动作选择原因；缺输入时明确 unavailable |

卡片要能区分两种“最终都超时”的策略：一种仍不断迈步而进度低，另一种长时间少动、某足接触标记持续未触发。区分依据是明确测量，而非更生动的别名。

### 1.2 支撑产品：完整过程证据与按需展开

逐回合保留对象、通道、短事件、持续状态、相互时序、缺测及源引用。失败前情通过全程索引展开，不猜一个万能的“往前五步”。

“完整”有三个具体含义：纳入全部指定回合；处理它们的全部有效记录；关键短事件不被摘要删除。它不等于无损自然语言，也不意味着未知语义全部识别。

### 1.3 不承诺的能力

不保证识别未记录、被遮挡或采样漏掉的事件；不从 A 直接推断实际施力或控制意图；不把相对成功样本的偏离当错误；不把奖励相关性、最早偏离或模型一致当原因。不改变成功标准、接受协议、训练预算和 sealed 边界。

“不额外训练模型”指不训练 captioner、故障分类器或数据拟合诊断模型，不微调、LoRA 或测试时优化模型参数；可使用现成模型推理。版本化的规则、阈值校准、参考分布和少量人工核查仍必要。从数据训练浅层 STL 决策树也是拟合诊断模型，暂不纳入 MVP。

## 2. 技术难点与对应设计

| 难点 | 具体错误 | 必须落实的设计 |
|---|---|---|
| 数据含义不明 | 把策略观测 O 当完整物理状态；把策略输出 A 当实际执行效果 | 通道定义、动作变换、采样相位、单位、参考系和可观测性清单 |
| 对象身份不稳 | 左足高度与右足接触拼成一句话；画面左右当机器人左右 | 稳定 entity_id；机器人角色映射；视觉身份不确定时允许集合或 unknown |
| 不同时间尺度 | 0.1 秒看不到持续行为；整段均值抹掉瞬时接触 | 逐步事实保留；多尺度查询；短事件与长状态并存 |
| 阶段切分依赖理解 | 必须先知道动作语义才能切段，切错后又影响理解 | 原始短事件、持续状态、多对象关系并存；大阶段最后归纳；分块仅在计算需要时使用 |
| 持续与缺席难证明 | 两张图都高位就声称一直抬着；遮挡被当没有落地 | 通道级覆盖契约；缺席只在声明的检测机制和时间范围内成立 |
| 语言强于测量 | 距离很小写成碰撞；没有承载写成悬空；静止写成犹豫 | 受控事实表达；开放语义单独分级；句子不得强于 operands |
| 未知模式与误报冲突 | 固定词表漏新组合；自由命名制造故事 | 默认测量目录＋开放组合候选＋白名单核查；记录不能表达的关系 |
| 压缩丢失关键过程 | 长过程只有结局；短暂接触、恢复尝试被删除 | 细粒度底账与摘要分离；省略可追踪；关键事件索引保留 |
| 选择性找证据 | 多次查询直到出现显著差异或支持既定解释 | 冻结查询预算；反证同时保存；新统计发现独立留出确认 |
| 泛化难标定 | 在举腿例子上成功就宣称识别未知模式 | 冻结核心与规则后留出新组合、新任务、新形态 |
| 原因与改动脱节 | 诊断历史量不能在 reward ABI 中访问 | 诊断事实到可编辑范围、可用 reward 输入的映射；不伪造因果 |

### 2.1 对原有设计文档的取舍

参考：[原始通用描述设计](D:/humanoid_agent/true_RL_Agent/PLAN/feedback_sys/P3NEW/GENERIC_DESCRIPTION_DESIGN_2026-10-02_ZH.md)。

保留：

- 物理关系由程序计算，任务和机器人语义由适配器提供。
- 任务规格、成功参考、父代参考分别报告。
- 报告数字可重算，保留反例和原始证据。
- 新任务、新机器人与真实闭环分别验收。

修正：

- 程序模板先交付卡片；模型可选地命名、组织或独立观察完整回合，不能成为已有事实进入卡片的唯一入口。
- 三把尺子从翻译前置门槛改为下游比较工具；正常行为也需要进入时间线。
- 先按终止标签分组不能作为唯一模式发现路径。
- “每句话都能程序复核”限于语义已定义且可测的事实；开放概括需要不同证据状态。
- 不设全回合固定二三十行的细粒度底账上限；上限只作用于阅读视图。
- 不声称仿真日志天然包含画面中的所有信息：当前实际采集的日志远少于完整仿真状态。
- 近似几何间隙不能定位真实碰撞点；统计未检出不能说明物理上不可区分。
- 每特征误报控制不能自动升级成整回合、多特征、多次查询的联合保证。
- 奖励分项仅反映奖励对状态/行为的响应，不解释策略为何选动作。

原文中的历史 PoC 数字不作为本系统的准确率、泛化性或资格通过证据。本计划没有重跑这些实验。

### 3.4 必须保留的项目内反例

现有 unloaded_low_motion 使用足端接触阈值与足参考点世界速度形成描述，并不包含“身体直立”“足已抬高”或“腿部保持相对姿态”。名称里的unloaded也不能替代接触力通道的实际测量定义。

此前只读查看旧 behavior_full 档案的 r1.e54：身体先翻转，随后前足出现超过 5 秒的低速未承载区间。它能作为开发反例，不能作为盲测未知样本。实现时应绑定旧档案哈希并重新检查原始证据可用性；不把旧派生结果直接当独立真值。

另外需要防止：机器人整体前移时，足相对躯干保持高位，但世界速度并不低。单一世界速度阈值会漏掉这种状态。

    E --> F["主张核查、内容选择、模板成句"]
    F --> G["策略行为卡片"]
    G --> H["任务报告投影与实际作者请求"]
    D --> I["按需展开单回合过程"]
    J["可选：代表例与随机例全程视觉"] --> K["开放关系候选"]
    K --> C
    K --> L["视觉限定观察或未解决项"]

~~~

### 4.1 五类职责

| 职责 | 输入 | 输出 | 第一版实现 |
|---|---|---|---|
| EvidenceAdapter | 原始记录、机器人和任务契约 | 能力清单、统一证据、权限与质量记录 | 程序；通道不够就按描述量降级 |
| MeasurementCatalog | 可用通道、冻结配置 | 有适用性和允许句式的测量结果 | 程序；默认目录见6.5 |
| TemporalComposer | 测量、原始事件、覆盖 | 持续、转变、先后、重叠、重复和未知区间 | 程序；不强求唯一阶段 |
| CohortAggregator | 全队列时序事实、条件、结果及对照 | 回合频率、条件分布、父代变化、代表/反例 | 程序；统计单位及有效分母显式 |
| CardBuilder + TaskProjection | 事实、候选、配置和容量 | 主张核查、卡片、既有任务报告投影 | 先模板；LLM润色或视觉发现可选 |

ClaimResolver 不另建大模块，但**语义、输入、引用、适用性和表述强度校验从第一版就必须存在**。程序产出的量也会被错误命名，模板不天然免检。

确定性测量、短事件与缺口直接进入证据账和聚合器，不经过模型筛选。没有视频或模型服务仍能生成数值卡片；模型提不出某个事实不能使它消失。

### 4.2 适配器拥有的语义

| 拥有方 | 必须提供 | 不应拥有 |
|---|---|---|
| 机器人适配器 | 稳定实体ID、角色、身体轴、资产/关节映射、尺度、真实有效限位、通道语义 | 哪种行为算任务成功；固定失败分类 |
| 任务适配器 | 命令/目标、条件、有效任务时间、成功/终止判据、环境查询、公开投影、允许修改范围 | 将某机器人尺寸写进共享计算 |
| 共享层 | 单位与时钟、通用测量算子、时序组合、覆盖、统计、引用和预算 | 假定四条腿、十二个关节、dt=0.02、世界+x就是前方 |

适配器允许必要的任务进度和身体映射，不能把留出失败的专用识别规则藏入其中并称作泛化。代码没有任务名也不足以证明泛化。

补充约束：

- actor_id 支持多个机器人/实体。不同控制时钟必须有显式映射和对齐误差；无法对齐时不能宣称精确因果先后。

- O、A、仿真状态、任务命令、实际控制结果分别命名。策略看不到的诊断状态不得写成“策略已知”。
- 每个回合独立命名空间；禁止把 reset 后帧拼进终止前过程。
- 缺失、无效、不可导出、数值零为不同状态。
- 全局control_dt不能代替通道级时间定义；动作、接触历史、状态和视频分别保留clock/sample_phase/alignment_map。
- 导数、持续区间和否定查询不得跨reset或未声明的缺测/采样间隙计算。插值可以在明确误差假设下辅助展示连续量，但不能制造“持续未接触”“中间没有落下”的证据。

权限与评测划分是两条独立轴：

- archive_frozen 只表示材料已固定、不可静默替换，不表示它属于 acceptance 的 sealed split。
- benchmark_partition=heldout 表示翻译器资格评测的盲测集，不自动等于任务的 sealed_validation。
- MVP 输入只接纳现有采集契约允许的 public_dev。当前 Stair/Push capture 与行为入口已有该限制，新适配器必须继承。
- 真正的 sealed_validation 不进入作者反馈、模型发现、成功参考拟合、校准池、示例库或代表例选择；聚合成文字也不能解除这一限制。
- 如以后确需在 sealed 材料上独立评测翻译器，应由既有评测协议决定访问与汇总出口，另建隔离评测路径；本计划不开放这样的输入通路。

### 5.2 捕获能力：尽早并行补齐，不阻塞可测部分

P0 就列出每项描述所需通道。P1 同时推进两个分支：用现有 Stair 档案生成数值卡片；为缺失但必要的描述量设计最小补采 profile。旧档不会因新采集器通过验证而自动拥有新增能力。

| profile | 优先补齐 | 解锁的能力与前提 |
|---|---|---|
| 基础物理上下文 | 每环境实际质量、资产和关节映射、有效硬/软限位、随机化值、命令、dt/子步/终止前状态 | 归一化、限位判断、条件匹配；不能用名义URDF替代已随机化环境 |
| 肢体与接触 | 根部和关节状态、足/连杆位姿速度、传感器选择及法向/切向语义、接触历史覆盖 | 时序参与与几何关系；非足端通道按需扩展，明确漏采范围 |
| 动作与执行 | policy_action_raw、缩放/裁剪、目标命令、实际力矩、执行器限幅与动作生效时间 | 动作—结果的时间对照；实际饱和还需与真实限幅规则核验 |
| 奖励响应 | 分项原值、权重、dt/归一化、门控、传感器 air time、first contact、版本及状态生命周期 | 精确重算或原始分项审计；任一关键状态缺失则仅代理分析 |

Stair 运行时能读取部分 qvel、力矩和软限位，不等于现有档案已逐步保存，见 [isaaclab_reward_runtime.py:221](D:/humanoid_agent/true_RL_Agent/src/true_rl_agent/tasks/stair_climbing/isaaclab_reward_runtime.py:221)。拍摄步的全连杆 snapshot 也不等于全部回合的连续记录。Push 的 [contact_status](D:/humanoid_agent/true_RL_Agent/src/true_rl_agent/tasks/push_recovery/numeric_capture.py:121) 仍明确为 not_collected。

实施时先做少量短回合捕获试验，实测字节/控制步、丢帧、仿真耗时和时间对齐；按实际规模估算存储，不把审计的粗估容量当预算保证。字段按描述依赖启用，允许明确保留未实现能力。不要为未来所有可能问题采尽全部仿真内部量。

所有 profile 先验证 pre_reset 数据、命令与执行的时间对应、传感器聚合语义；这些属于后续实施，本文修订没有执行采集。

### 5.3 覆盖必须拆成四种，不能只用一个布尔值

1. **raw coverage**：原始通道实际记录到哪里。
2. **media coverage**：哪些时间有视频、哪些帧成功解码。
3. **model inspection coverage**：模型实际收到哪些帧或片段。
4. **semantic coverage**：哪些必要事实已被识别并有证据。

前三项有程序记录；第四项需要独立定义的必要事实清单与真实材料核查；可用程序与人工共同评估，不能由模型自报，也不能由每步都有阶段标签推出100%。

“全程视频概览”表示选取的观察窗口覆盖整条时间轴，不表示每个中间帧被模型读取。低频采样的局部信息损失必须保留。

### 5.4 证据引用

内部 EvidenceRef 至少包括：回合、通道、实体、时间/步区间、源哈希、提取器版本、测量配置、视频帧或片段索引。

公开作者侧用批准的摘要和不透明引用ID；内部路径、sealed 原始证据不直接暴露。ID 只用于追踪，不代表作者模型能自动打开原始图像。

## 6. 事实与查询内核

### 6.1 第一版最小能力

只实现能由已采通道支持且可独立测试的能力：

- 身体坐标变换、相对位置/朝向、位移、净位移、累计路径、速度和角速度。
- 明确参考面的高度/间隙；近似几何必须带近似标记。
- 接触力阈值事件及区间、已记录的非足端受力；仅在法向方向和阈值足以支撑时才使用承载措辞，物理接触对象未知时不补名。
- 任务进度、有效命令、停滞区间；“应当前进”由任务契约提供。
- 持续状态、转变、重复、先后、重叠、持续至观察结束。
- 数值摘要、极值与短瞬态保留；不能只保留均值。

暂不作为通用硬事实：真实碰撞点、任意地形上的精确稳定裕度、意图、犹豫、卡死机制、力矩饱和、策略因奖励而选择动作。

支撑多边形、capture point 等只能在模型假设、接触/质心数据及适用条件明确后作为可选测量，不能成为所有机器人默认稳定性真值。

### 6.2 可组合的查询，而非任意生成代码

~~~text
Bind(entity, role)
Measure(quantity, entity, frame, interval, applicability)
Compare(quantity, comparator, threshold_spec)
Persist(predicate, interval, coverage_policy, debounce_policy)
Transition(before, after, same_entity, boundary_policy)
NotObserved(event, interval, detector_contract, coverage_policy)
Before / During / Overlap / UntilObservationEnd
Duration / Count / Fraction
~~~

实现为有类型的表达式树与白名单算子。模型只填参数和组合，不提交任意 Python 执行。单位不匹配、实体不匹配、超范围或缺数据都返回显式状态。

同一足端的接触标记持续未触发不需要“相对速度低”；描述“保持姿态”则还需要相对躯干位置/关节变化信息。这两类主张不可共用一个模糊谓词。

### 6.3 时间与否定语义

- 统一用秒与稳定步号映射；采用半开区间，并明确每个样本代表瞬时测量还是整个控制区间的传感聚合。
- 瞬时样本没有权力证明两样本之间完全没有接触。
- 有限采样支持的是“在该检测机制的记录中未观察到事件”。
- 接触 history 是否覆盖子步、使用最大值还是最后值，必须进入 detector_contract。
- 滤波、滞回与抖动容忍的原始转变仍保留；不得把填补缺测当去噪。
- Persist、NotObserved 和时序关系返回 true/false/unknown；缺测不按 false 计算。
- 对区间开头已经存在的状态记录 left_censored；结束仍存在记录 right_censored。
- 事件区间保留 onset_range、confirmation_time 和 end_range；不要把确认时刻当真实开始时刻。
- 将通道对齐误差计入边界范围；两事件的允许范围重叠时，不能强行输出精确Before关系。

### 6.4 阈值来源

每个阈值只能来自以下可追溯类别之一：

- task_spec：任务定义中的明确判据。
- sensor_contract：接触、有效性、噪声和测量精度定义。
- robot_scale_rule：按身体尺度/速度等归一化的通用规则。
- development_calibration：开发/校准集上冻结的算法参数。
- reference_distribution：条件匹配参考分布中的统计阈值。

不同来源不能混同。高于成功分位带说明相对偏离，不自动说明违反任务或构成失败。缺参照时返回 unavailable，不静默换任务条件或用零填充。

### 6.5 必须随第一版交付的默认测量目录

仅有 Measure/Persist 等语法不够。每项 descriptor 必须含 inputs、unit/frame、formula、applicability、threshold_source、validity、aggregation、allowed_text 和 forbidden_inferences，并提供正反例。目录按“通用运动→有适用条件的形态层→任务层”组织，不要求所有机器人启用同一组量。

| 层级/描述量 | 定义与聚合 | 启用条件和允许表达 |
|---|---|---|
| 通用：进度、净位移、路径、跟踪 | 按命令方向/任务投影计算；位移和累计路径分别保存；按回合统计停滞区间及比例 | 任务给出有意义方向/进度；“有运动但净进度低”不同于“静止” |
| 通用：机身姿态与变化 | 身体轴相对重力/命令、角速度、姿态超阈区间 | 四元数和轴映射有效；“倾斜/翻转”不直接等于失稳原因 |
| 关节：姿态范围与限位邻近 | q相对每环境有效上下限的裕量、接近限位时长；按关节角色组织 | 名义URDF只能作名义限位代理；近限位不等于卡死或力矩饱和 |
| 肢体：位置与运动 | 世界速度、躯干相对位置/变化分别算；实际参考点到声明参考面的距离 | 参考点不是整个足底；“平均较靠后”不等于拖地，“接近表面”不等于接触 |
| 足式：接触标记占比 | 指定力通道和阈值形成布尔量；有效时间内每足占比、on/off事件 | 默认叫接触阈值标记；禁止占比直接叫承重份额 |
| 足式：单足未触发区间 | 每足run长度、完整区间/左右截尾分开；分位数及长状态 | 不能叫全身腾空；不能把截尾run当完整摆动时长 |
| 足式：接触组合 | 按角色有序记录各足标记组合的时间占比及转换 | N个足动态生成；全部标记假不能排除躯干或其他连杆接触 |
| 足式：转换同步与周期相位 | onset时间差；可靠周期内相位及圆周集中度；完整周期数与非周期时段 | 周期足够且较稳定才说节律；状态相等率另列，不能冒充落地同步 |
| 受力：模、分量与冲量 | 各通道力模、重力反向分量、分量积分分别存；积分按真实时间权重 | 保留原通道是法向合力还是完整总力的定义；重力反向投影不能改名为接触法向力，台阶侧面法向不等于竖直方向；均值占比只有固定采样间隔等条件下才等于对应积分占比 |
| 受力：非足端与残差 | 已记录部位的受力事件；满足6.6条件才计算物理对账 | 非足端传感触发不能定位接触对象；残差不自动指向小腿承重 |
| 时序：持续、重复、停滞前后 | 单足状态＋机身姿态＋其他部位活动＋任务进展的组合 | 返回完整关系而非只给别名；前提缺失时分项输出 |
| 任务：Stair | 地形区间、台阶相对位置、任务进度、终止契约 | 台阶几何和规则由Stair适配；不进共享硬编码 |
| 任务：Push | 扰动时间/方向、实际可观测根部响应、恢复/再偏离 | 未采肢体/接触时不生成步态、落足或支撑转换结论 |
| 扩展：动作与奖励响应 | 命令、实际执行、奖励分项与行为对齐 | 当前缺归档则unavailable；按5.2补齐后逐项解锁 |

上述表不是所有可能失败的枚举。它是基础可观测量目录，未知模式主要来自这些量的新组合和未解释残差。新物理量确实可能需要新通道或新算子，系统必须承认这个边界。

默认站姿是姿态参照，不是最优行为或“正常”真值。尺度归一化有助于迁移，但不能保证接触阈值、周期数与速度阈值跨机器人直接有效。

### 6.6 物理一致性与残差

物理检查先核对采集语义与适用性，不把任意力的总和强行解释成承重。一般动量对账为：

~~~text
r = [P(t1) - P(t0)] - Integral(F_contact_total + F_external_known + M*g, t0, t1)
~~~

其中 P 是全机器人世界系动量；g 是带方向的重力向量；质量在区间内若变化须另处理；接触项必须包含适用的完整外部接触力，时间积分需了解子步及传感聚合。根部速度不能直接替代全身质心速度。

数据不满足时可提供两种较弱结果：

- 相对某明确子集的足端力代理基准偏低，注明该基准不是机器人重量。
- 某些力/动量项缺失，无法完成对账，列出缺项和可能混淆因素。

即使完整对账残差显著，也应先检查时间错位、单位、力方向、外扰和传感器范围。只有独立接触证据才能归属到具体身体部位。用根部高度变化很小筛“近静止”，不足以自动忽略全身惯性。

### 6.7 从默认量到新模式

第一版提供少量通用组合：高位持续＋未触发接触；低进度＋仍有肢体活动；低进度＋整体低运动；非足端事件前后的姿态变化；相对参照的明显参与不对称。它们输出可核查关系，不硬编码某个失败名字。查询语言能表达某个新组合，不等于系统会自动提出它；少量默认组合不保证发现其他组合，开放发现能力必须另测。

开放入口允许人工或现成模型提出新组合，编译到白名单算子，检查反例，再在所有有能力的回合上重算。当前批次发现的频率是描述性结果；用它选了规则，就不能又将同批数据作为该规则的盲确认。

无法编译或缺测的候选保存为 unresolved，进入后续开发清单。禁止在一次推理中生成并执行新Python检测器。

## 7. 可选视觉：先证明增益，再扩大

### 7.1 视觉仍有价值，但不再是卡片的前置门

完整仿真状态可以决定渲染画面，不意味着当前档案完整，也不意味着默认测量目录覆盖了所有关系。视觉可补充遗漏的空间关系、发现错误映射或提出未预设组合；这些只是可检验的增益假设。

第一轮试验从少量已有完整视频开始，选取不同条件与结果的代表例，再加入独立于数值报警的随机例。选择理由、available/selected/total和没有视频的范围都记录。视觉样本频率不能外推为整个策略发生率。

步态接触与短状态优先用高频数值判断。0.14秒事件可能被4 FPS漏过，但“至少五帧，所以必须35 FPS”不是普适下限；实际需求取决于现象、采样相位、遮挡与模型。不能用某固定FPS保证语义完整。

### 7.2 完整短回合优先试验，分块按需要使用

先试“完整短回合概览＋定向密集片段”。48/96张图是否可行要检查实际provider的图像与token限制，并实测关系识别；容纳得下不等于理解得好。

若回合过长或实测退化，再试重叠分块并传递未结束状态。在相同输入/输出预算下比较，不预设每回合必须八次或十三次调用。两种方式都保留原时间戳和实际媒体receipt；多块关联仍遵守8.3，不填平未观察间隙。

首轮行为发现隐去终止类型及成功/失败标签，提供真实命令但区分“要求”和“观察”。数值事实可用于后续核查；若要评估视觉独立发现能力，另记录它是否已收到这些事实，避免把复制事实算增益。

### 7.3 候选、核查与预算

模型只输出实体候选、实际支持帧、时间范围、普通语言关系、疑问及白名单查询请求。引用必须出现在本次输入receipt中。视觉主张仍按第8节分级，不能凭第二模型赞同变成测量事实。

每个候选初始最多2次补查、每回合最多8次，仅作开发预算起点。运行profile还必须填写：总调用数、单次/总图像数、输入输出token、查询区间时长/记录数/AST节点、重试、墙钟时间及费用上限；首轮、补查、润色和重试共同计费。缺完整预算或provider容量定义时不能启动该profile。

补查根据缺口进行：查更早的全程索引、加密局部片段、补合法视角；根本无通道则返回未知。不能反复扩大窗口以“找到一个解释”。预算耗尽就缩小表述范围并记录partial。

缓存绑定实际序列化请求哈希、媒体及数值依赖、资产映射、开放状态、反证、模型返回版本和权限。前块状态变化必须失效；权限复核不能被缓存命中绕过。

### 7.4 是否进入常规流程的判据

比较“数值模板卡片”和“同卡片＋视觉”的：

- 新增且被独立核查的必要事实、纠正的身份/几何错误。
- 新增错误和unsupported句子，尤其是接触、因果和持续性。
- 对卡片可操作性的贡献，以及每条新增正确事实的成本与延迟。
- 未报警随机例中的新发现，及仍被遗漏的过程。

若没有稳定增益，保留按需人工/视觉复核入口，常规流程继续数值卡片。视觉失败不阻断已合格的数值能力；数值目录漏掉的新关系也不能被宣称“没有发生”。

## 8. 主张核查与行为时间线

### 8.1 单回合及聚合主张结构

~~~yaml
claim_id: ...
kind: measured_relation | visual_description
subject_ids: [...]
relation: ...
interval:
  start_range_s: [...]
  end_range_s: [...]
  left_censored: false
  right_censored: true
operands: [...]
applicability: ...
coverage_ref: ...
evidence_refs: [...]
status: supported_measurement | visual_observation | unresolved | contradicted
review_state: not_required | pending | individually_reviewed
counter_evidence_refs: [...]
render_template_id: ...
candidate_alias: ...
~~~

聚合主张另需 cohort_id、分子/有效分母/unknown数、选择与加权方式、任务条件、比较域和统计配置版本。不能把一条代表回合的证据当整代频率的依据。

上述 status 不是从高到低的真值概率。supported_measurement 只表示在明确测量定义和适用范围下支持，不是物理全知。模型提出的视觉句默认是 visual_observation，必须使用“可见帧中”“视觉上”等与覆盖相符的措辞，不能命名为已认证事实。

只有补得独立测量且语义一致时，才能为其可测部分建立 supported_measurement 主张；其余视觉成分保留原状态。人工逐条审阅可以记录 individually_reviewed 及审阅证据，但不能凭看图把不可见接触或意图变成测量。第二个模型重复同一说法、模型一致率或该方法在样本上通过评测，都不构成当前单条主张的真值认证。

因果解释使用另一个 Hypothesis 对象，不能通过修改 claim.status 变成事实。

合法组合固定如下，schema必须拒绝其余组合：

| kind | 可用status | 约束 |
|---|---|---|
| measured_relation | supported_measurement / unresolved / contradicted | 需要合法算子、有效operands、适用条件与覆盖；不能只因程序执行成功就supported |
| visual_description | visual_observation / unresolved / contradicted | 视觉句保持限定措辞；人工review也不把它变成传感器事实 |
| Hypothesis（独立对象） | proposed / under_test / intervention_supported / rejected | 必须另附可区分证据与实验范围，不进入事实precision分子 |

从视觉候选发现可测关系时，建立新的measured_relation并用derived_from关联候选；不覆盖原视觉记录和潜在差异。Hypothesis即使有干预支持，也只对具体实验条件有效，不写成无条件普遍原因。

### 8.2 语言生成规则

- 测量事实中的对象、数字、时长、比较域和时序词由程序确定。
- 第一版用模板和明确排序规则成句。可选模型只组织已核实关系或提出候选别名；额外关系仍须重新核查。
- 别名可以是“前足高位维持”，但不能替换支撑它的具体事实。
- 无法映射到合法事实语义的部分保留为unresolved candidate；确有实际视觉输入receipt与支持帧时才可列为visual_description，机制解释另存Hypothesis。数值输入经LLM命名产生的新词不能自动获得视觉证据等级；不能因没有算子就静默丢掉候选。
- 新增算子须进入单独开发版本并重新验证，不能在一次推理中悄悄扩充正式语义。
- 开放视觉描述的方法质量由独立样本盲评建立；单条运行结果仍保留视觉证据等级，结构检查或第二模型一致仅作为辅助。

严格防止以下替换：

| 有证据的说法 | 不允许自动升级为 |
|---|---|
| 未检测到达到阈值的足端接触力 | 完全未接触 |
| 足参考点相对躯干较高 | 整条腿主动抬起 |
| 净位移较小 | 没有运动 |
| 几何采样点间隙较小 | 该点发生碰撞 |
| 动作命令较大 | 实际输出力矩饱和 |
| 一段时间没有恢复进度 | 策略拒绝前进 |
| 奖励项没有明显变化 | 该奖励造成了失败 |

### 8.3 跨块续接条件

合并必须同时满足：

- 同一实体或已验证的实体对应关系。
- 同一谓词语义、参考系、阈值版本及适用条件。
- 时间区间相邻/重叠且所需通道覆盖充分。
- 中间没有足以结束状态的反证事件。
- 重叠区域的矛盾已用证据解决，且解决记录可回查。

未解决冲突可以在时间线上保留多个候选分支或unknown区间，但不能满足合并条件，也不能拼成更长的确定持续状态。

禁止按文本相似度直接合并。文字相似可以召回候选，不能做最终判据。

行为时间线按实体多轨存储，再建立 Before/During/Overlap 等关系。同一时刻可存在“左前足高位”“其余足运动”“身体减速”，不强制单一阶段标签。

区分两个存储产物：

- state_interval：连续性由相应测量契约及有效覆盖支持，可在该契约精度内使用持续措辞。
- visual_observation_track：保存实际支持帧、可见性、遮挡和未知间隙。多个片段可关联为同一行为候选，但“没有结束反证”不足以填平未观察时隙，只能说“在这些可见片段中保持相似状态”。

关联视觉track与合并连续state是两种操作；混用应在schema和测试中被拒绝。

### 8.4 一个必须通过的组合测试

以下是示意行为，不是本项目已观测事实：

~~~text
0–1.2 s：机器人向目标方向移动。
1.2–1.5 s：身体基本直立时，左前足参考点相对躯干升高。
1.5–5.0 s：该足参考点维持相对高位；有效记录中未再次检测到达到阈值的足端接触力。
2.0–5.0 s：其他足有运动；机体前进逐渐停滞。
5.0 s：任务记录超时。
~~~

输出的关键句可以是：

> 左前足参考点相对躯干升高后，在后续记录中保持较高位置；该区间未再次检测到达到阈值的足端接触力。其他足仍有运动，机体前进逐渐停滞，最终任务超时。现有证据尚不能确定上述现象的机制。

若另外具备经过验证的连续承载测量契约，才允许更自然的“未恢复承重”；若只有稀疏视觉，就缩小为可见片段描述。这里的示范句不能脱离其测量条件作为通用模板。

至少配套以下反例：

- 身体先翻倒，再出现前足高位和不承重。
- 左右前足交替摆动，被误看成同一足持续抬起。
- 中间短暂重新承重，粗视频采样未捕获。
- 足轻触但不承重。
- 世界坐标足端在移动，但相对躯干保持姿态。
- 地面高度变化造成 clearance 上升，足并未相对身体抬起。
- 记录在高位状态中开始或结束。
- 合法越障/恢复也出现高位持续，不能因此判定失败。
- 视觉遮挡或关节/接触缺测。
- 下肢被其他物体约束，但没有对应接触对象信息。

此案例属于已知开发案例，不能计入“未知模式发现成功”。

## 9. 策略行为卡片：第一版的核心交付

### 9.1 聚合顺序和有效分母

先逐回合计算，再跨回合聚合。默认回合等权，报告中位数/分位数与回合频率；需要任务评估的条件权重时由任务契约明确提供。将所有控制步拼接计算的占比另标为“按有效记录时长加权”，不能混成回合平均。

所有模式频率记录：

~~~text
满足模式回合数 / 可判断该模式的回合数
并列：总回合数、unknown数、未处理数、条件、时间范围、选择/加权规则
~~~

各描述量的有效分母可不同；缺某足通道不必丢弃整回合的根部信息。unknown不是阴性，早终止也不是之后“没有出现”。持续时长的截尾保留；不得把失败短回合与成功长回合的全程均值不加说明直接比较。

“全部有效回合”是底盘；成功/失败/条件是分面。零成功时仍描述现有行为，成功对照标缺失。终止类型可作展示入口，但相同过程模式可跨多个终止类型。多模式可以重叠；分子相加超过总回合数时解释为非互斥，不能伪装分解比例。

### 9.2 卡片内容与压缩策略

| 内容 | 必需字段 | 选择方法 |
|---|---|---|
| 身份、范围与能力 | 策略/档案版本，条件，回合数，缺测，数值/视觉范围 | 内部保留完整溯源，作者只收批准的公开范围 |
| 总体行为 | 位移/路径/进度、姿态、肢体参与与长期状态中适用项 | 先全队列绝对描述，再分面；不以异常分数决定是否存在 |
| 失败过程 | 主要可核查模式、先后/持续、频率、恢复与未归类比例 | 保留高频模式和关键罕见事件；终止名不替代过程 |
| 对照与反例 | 匹配成功/父代差异、相同过程却不同结果的反例 | 无有效对照明确缺失，不强制给显著结论 |
| 奖励响应/可操作性 | 真分项或代理标记，输入缺口，允许组件与候选验证 | 缺数据可以为空，但必须有原因 |

“必要事实”定义为会影响行为判断、排除错误归因或评价修改候选的事实，不要求事先证明它一定改变某条reward或提高训练结果。

压缩前冻结内容选择规则：结果和范围必留；主要失败过程、关键短事件、核心反例与重要缺口设保留槽；其他事实按出现范围、行为差异和信息增益排序。保存被省略的事实ID及原因。不允许只保留一个“拖腿/齐跳”别名。

不要求每种机器人的所有目录项都进入作者卡片。完整测量存在内部，摘要优先呈现有区分力的关系；当两策略无法从可测行为区分时如实输出，而非编造差异。

### 9.3 一个真实审计线索的安全表达

审计保存输出可引导原型，不能直接标成新系统验证通过：

> 在该历史策略的成功回合采样中，左后足的接触阈值标记占比低于其余足；其接触合力模占比约15.3%。一组超时回合出现低进度、低运动及某后足接触标记持续未触发。足参考点接近投影高度场，但现有代理不足以断言脚底贴地、拖地或执行器卡死。

正式卡片还必须给每一句绑定对应条件、时间范围、有效分母和原始源引用；上述不同子集不能省略范围后合成“一直用三条腿走”。探针中的18/39超时等频率须先核对公式、缺测、聚合和源档，才作为正式输出。

真实奖励 [feet_air_time](D:/humanoid_agent/true_RL_Agent/src/true_rl_agent/tasks/stair_climbing/reference_programs/go2_stair_official_flat_derived_v1/training_code/components.py:40) 使用 support_last_air_time、support_first_contact 及速度命令门控；[运行时](D:/humanoid_agent/true_RL_Agent/src/true_rl_agent/tasks/stair_climbing/isaaclab_reward_runtime.py:323) 读取传感器计时。代理未触发时段与0.5秒门槛的对照可报告为“值得核查的奖励响应线索”，不能写成已重算的真实分项。

### 9.4 三种参照与父代变化

| 参照 | 回答 | 边界 |
|---|---|---|
| 任务规格 | 未达到什么要求 | 判据不是原因，定义由任务拥有 |
| 成功参考 | 与哪些成功过程不同/相同 | 参考外不必然失败；分布内不保证正常 |
| 父代参考 | 行为在什么条件下变化 | 不是自动改善，也不是改动因果证明 |

优先匹配命令、场景/扰动、资产及随机化、评估契约、有效时间范围；相同seed不自动保证相同物理随机化或相同外扰，必须核对实现和实际参数。同一比较使用相同描述器版本。条件不匹配只作明确限定的描述，不静默池化或用零补空。

按任务阶段比较仅在阶段由可靠外部变量定义时启用；否则使用共同时间窗、事件对齐或明确的整回合量。比较成功子集时另报成功组成变化，避免“只剩容易成功的回合”导致假改善。

优先展示绝对值、差值、样本量和分布。若要报告异常保证或统计显著，另外冻结参考拟合、校准、查询与多重比较方案：比如预先定义检验族的Holm校正，或在适用假设下控制FDR。FDR不等于每回合无误报概率；不能把单特征5%阈值解释成全部特征联合5%。

### 9.5 早期验证作者到底收到了什么

沿现有 TaskPromptAdapter → PublicContextBuilder → build_prompt_payload → provider request 投递。**P1就完成本地序列化检查，不等待视觉和大规模资格评估。** 本地检查可使用固定公开样例，不调用模型。

当前公共报告有六个句子区和一个 actionability 区，见 [共享契约](D:/humanoid_agent/true_RL_Agent/src/true_rl_agent/evaluation/process_report.py)。新版卡片先映射到已有任务模板：

| 现有区 | 卡片映射 |
|---|---|
| results | 结果、总回合数及有效范围 |
| process | 总体行为与主要失败过程 |
| counterexample | 成功反例、相同过程不同结局及错误归因反例 |
| visual | 仅符合现有准入语义的内容；否则按规则填缺失 |
| gaps | 未采能力、未核实机制、未处理/省略范围 |
| parent_diff | 可比父代差异，或比较不可用原因 |
| actionability | 任务批准的组件与运行时输入、需检验的候选关系 |

当前任务报告容量是 Stair 8192 bytes、Push 12 KiB，分别见 [Stair](D:/humanoid_agent/true_RL_Agent/src/true_rl_agent/tasks/stair_climbing/process_report.py:22) 与 [Push](D:/humanoid_agent/true_RL_Agent/src/true_rl_agent/tasks/push_recovery/process_report.py:21)。它们不是整个作者请求的总预算。检查中文UTF-8序列化后的字节数，同时遵守总payload和authoring预算；不额外附一次卡片造成重复。

现有严格顶层、section及句子{id,text}契约不能直接接收generic timeline。先复用现有字段；需要新语义时明确task-owned schema版本迁移、兼容与容量验证。visual_observation不得为通过旧“supported”准入而改名；未接线的视觉候选保留内部。

必须检查最终序列化文本：stable statement ID能从卡片追到任务投影和实际请求，数字、范围、反例、缺口保留，内部路径及sealed衍生材料不泄漏。full artifact、图像路径与typed slots本身不会自动被作者读取。

### 9.6 原因与修改建议的边界

~~~text
diagnostic_fact
  → relevant_allowed_components
  → available_runtime_inputs
  → competing_hypotheses
  → predicted_observable_change
  → original evaluation and acceptance protocol
~~~

reward ABI可能没有诊断所用历史窗口。作者不能为表达诊断而越权修改runner、采集器或状态生命周期。建议必须区分可立刻用现有输入实现、需要另行扩展输入和证据不足。

奖励分项可解释“奖励如何响应这段已发生行为”；不能解释“策略为什么选择该动作”。即使增加某奖励后改善，也需要检查其他行为变化、固定评估与竞争解释，不能在翻译器内自证根因。

## 10. 最小产物、复放与降级

### 10.1 四个常规产物

~~~text

  manifest.json
  evidence.jsonl
  policy_card.json
  policy_card_zh.md
~~~

- manifest：输入哈希、版本、能力与权限、队列选择、配置、成本和处理状态。
- evidence.jsonl：typed records，统一保存测量、事件、状态区间、候选/核查主张、引用、查询与可选媒体receipt；record_type区分，不强拆十几份空文件。
- policy_card.json：聚合槽、有效分母、主张引用、重要反例、缺口、公开投影审计副本和序列化请求摘要。
- policy_card_zh.md：由结构化卡片生成的阅读视图；按需展开单回合时间线，不另外建设常驻长文生成器。

大数组和媒体只保存不可变引用。确有检索/性能需求时再分片，保持稳定ID。评估阶段另产evaluation_report；临时开发脚本不进入正式依赖。

### 10.2 每项能力分别降级

机器协议分别记录 modality_scope、processing_completeness、limitation_codes 和descriptor applicability。例如“全队列根部数值完成、接触缺失、视觉只查看3个回合”是合法状态，不能折成笼统的全部完成或全部失败。

允许 numeric_only、visual_only、local_only、partial 等阅读标签，但不能让“数值全程处理”代替“视觉全程检查”。时间映射整体损坏则拒绝时序拼接；单个描述量缺测只关闭该量。所有区间断裂和超预算对用户可见。

展示的覆盖率分开报告输入、媒体、模型检查和必要事实召回。数据缺失不是正常，空文本不是高准确率。

## 13. 轻量验收与可升级的强证据

### 13.1 四级验收，不把论文级门槛当原型门槛

| 级别 | 首批可执行方案 | 允许声明 |
|---|---|---|
| E0 工程回归 | 独立核对关键公式；单位/左右/时钟/短事件/缺测/截尾/权限/投影夹具与变形测试 | 实现符合已定义契约；不自动证明自然语义正确 |
| E1 当前策略真实离线核查 | 全队列计算；预先按条件与结果抽约12–20回合，加全部关键反例；核查最终卡片全部句子 | 对这批材料和启用描述量可用；不宣称误报率低于5% |
| E2 跨策略核查 | 冻结测量和成句配置；先选3–5个可重放且有差异的训练lineage/策略族，至少一个未用于调规则 | 被测策略族与条件内的迁移证据；样本不足时只报告案例 |
| E3 新域与闭环 | 新组合、新任务/形态按允许适配测试；旧反馈/新卡片固定预算对照 | 新域描述能力与闭环效用分别声明 |

12–20、3–5是工程起点，不是统计充分量；视频有多少不决定所有数值描述的样本上限。E1可由一名审阅者起步，检查原始数组/曲线、独立计算和可用视频。存在分歧或要发表强语义结论时再加入独立标注与裁定，不强制所有开发样本两人盲标。

### 13.2 E0与E1的实际放行门

- 100%输出事实有可解析引用、适用性、正确实体/单位及有效范围；聚合数字可以从逐回合记录独立重算。
- 测量公式与关键反例通过；短事件不被平滑删除，缺测不变阴性，截尾不伪装完整时长。
- 核查最终卡片所有句子；发现关键假事实或unsupported确定断言必须修复或隔离对应描述量，不带问题放行。
- 必要事实清单在看系统文字前建立；检查重要过程、短事件、持续状态及核心反例有没有漏掉。
- 模型不可用、全失败、无父代、字段缺失时仍能输出有用的受限卡片。
- 现有任务schema、中文字节容量、公开过滤与实际序列化输出检查通过。

该门说明已检查材料达到要求，不是总体错误率保证。“样本内没有发现关键错误”必须同时给核查样本数与范围。

### 13.3 构造测试和独立重算能证明什么

构造式测试负责单位、时间变换、实体映射、缺测、短事件、接触转换、边界及不可能状态等确定定义。变形测试需要任务/环境的真实对称性：镜像机器人却不镜像非对称障碍与命令，不应要求输出不变；世界旋转要同步变换相关方向与参考系。

至少留一组真实资产/通道锚点，防止适配器与模板共同把左右写反但变形测试仍通过。独立实现从相同原始通道重算可验证数值；不必另有视频才有效。但复用同一错误定义无法验证“拖腿/齐跳”等词义。

对干预回放分别保存：

~~~text
injected_intervention  # 实际改了什么
realized_behavior      # 执行后独立检查发生了什么
task_outcome           # 任务评价结果
~~~

锁关节、降摩擦或加质量不自动产生预期行为，也不自动导致失败。需要无效果样本、成功补偿、竞争机制和负对照；从干预标签直接生成“拖腿失败”真值不合格。已反复调过的生成器只能证明生成器内回归，新的组合/强度/生成机制另留验证。

这些测试不替代真实材料的语义核查与遗漏检查。不能用同一检测器的输出充当新检测器的全部“真值”。

### 13.4 材料用途和统计单位

材料用途分开记录：

- development/regression：按内容调整过目录、阈值、名称或选择规则，可永久复用作回归。
- descriptive_audit：支持当前队列描述性结论，不承担未见分布保证。
- prospective_confirmation：配置冻结后才检查，用于确认特定能力声明。

只查文件容量、元数据、可用性不必一概视为语义泄漏；按行为或输出调过规则的材料则不能再作盲确认。修复软件错误可以在旧集回归；若随后声称强泛化，再用预留材料或后来产生的新策略确认。并非每次修改都必须报废全部旧集。

需要统计参考时另外标记reference_fit与calibration用途并冻结选择流程；没有这类参考的模板原型不强求四份数据。相同回合重渲染/裁剪不能跨确认划分。权限轴仍遵守5.1，heldout不等于sealed。

**统计单位由问题决定。** 同一固定策略、规定条件下的独立随机回合，可以估计该条件下的回合错误率；跨策略泛化需按训练lineage/策略族留出。条件网格内相同seed是否共享随机性需要核查，不能武断按行独立，也不能武断说只有策略是唯一单位。帧和句子不能冒充独立回合；同一训练过程的多个checkpoint不能冒充独立策略族。

### 13.5 指标保留，但分清当前试用与强声明

常规报告至少包含：原子事实支持率、必要事实召回、关键错误/unsupported、身份/时序正确性、短事件与长状态的遗漏、unknown是否恰当、聚合算术、最终投递保真度、成本和覆盖。

所有事实断言都进入支持率分母；缺证据的确定断言记unsupported，不计正确，不从分母删除。恰当unknown不计物理事实正确数；空输出precision=N/A，并受召回约束。拆句与必要事实手册先固定，不按系统输出反向挑容易的真值。

新增卡片指标：每个聚合数字的分子/分母/加权/条件是否正确；主要模式是否被遗漏；代表例是否真代表所述范围；省略是否改变结论。数字算对但误导性概括仍算错误。

若后续要宣称“高准确率与泛化”，可冻结以下研究目标，而非作为P1前置门：

| 强声明目标 | 示例门槛与报告 |
|---|---|
| 事实精确率 | 点估计≥0.95，合适独立单位/来源组下的95%下界≥0.90 |
| 必要事实召回 | 点估计≥0.85，95%下界≥0.75；短事件/持续状态另报 |
| 关键错误风险 | 指明是回合风险还是整张卡片风险；95%单侧上界≤0.05 |
| 新组合 | 主体、组成关系、持续/先后均正确才算命中；正例命中率单侧下界≥0.80，匹配负例误报上界≤0.05 |
| 边界 | 分事件容差冻结，同时报告区间宽度与命中，不能无限放宽 |

数值门槛是拟定目标，需在确认集打开前确定。不能用总体得分给样本很少的新任务或罕见模式背书。

若独立同分布近似适用，零错误时关键错误概率的95%单侧精确上界为：

~~~text
1 - 0.05^(1/n)
~~~

要上界≤5%，至少约59个独立单位。这里单位必须对应声明：59个同策略回合不能证明59张跨策略卡片的可靠性，更不能证明新形态。零错误不得用普通bootstrap的零上界报通过。相关材料需采用适当分组/层级分析，或预先每独立组抽一单位并限定推论范围；证据不足就收窄结论。

### 13.6 泛化与未知失败的诚实回答

| 情形 | 预期能力 | 验证方式 |
|---|---|---|
| 已有原语的新时序/跨实体组合 | 候选已提出或被预算内搜索触及，且证据充分时，可核查并描述组成关系 | 分开记录候选提出率与给定候选后的核查准确性；冻结目录后留出语义组合，含相同终态/直方图但不同顺序的反例 |
| 名称未知但现象可测 | 可给关系描述和候选别名，不强制分类 | 评主体、过程、持续性，不以是否猜中名称评成功 |
| 已有通道中缺省目录遗漏的关系 | 可选视觉/人工/模型提出候选，经白名单验证后补充 | 报真实新增正确事实；当前批次发现与独立确认分开 |
| 通道、几何或实体身份缺失 | 只能部分描述或unknown | 检查缺口识别，不能惩罚诚实unknown并逼它编造 |
| 新任务/形态 | 核心可复用，映射和适用性需要重新验证 | 只允许声明的适配，记录核心/目录变化，不藏失败特例 |

“持续举前腿但不放下”能否描述，取决于同一前足的相对高度、身体姿态、接触检测与时间覆盖；不能只靠低速未承载。第8.4的开发例及其反例必须通过，但它已被讨论，不能算未知模式发现证据。

### 13.7 验证反馈有用，而不只验证文字漂亮

先做低成本问题核查：作者能否从实际收到的卡片区分“仍在迈步但无进展”和“长时间少动”、说出支持数字与不确定性、提出在允许输入内可实现的候选改动。引用了某句不是使用证据，没显式引用也不证明没使用；需要检查决策和改动内容。

策略辨认题仅作辅测，隐藏身份/编号和可泄露答案的结果信息，用相同条件、相近结局但不同过程的困难对照；允许“可测行为无法区分”。不能靠成功率或政策ID猜对就算描述充分。

最后在固定authoring与训练/评估预算下比较：现有反馈、数值卡片、数值卡片＋可选视觉。成功率与J_primary分开，未完成记缺失；过程是否按预测改变、描述准确性与闭环效果分别报告。只在解决明确疑问时增加消融，避免把试验矩阵无限扩大。

| [PoseScript/PoseFix代码](https://github.com/naver/posescript) | 静态关系与两姿态差异的规则表示 | 单姿态/成对差异不等于完整时序；同仓库训练模型与规则管线要区分 |
| [ProTracer论文](https://arxiv.org/abs/2609.21369)、[代码](https://github.com/Chang-AIML/ProTracer) | 状态变化辅助分段、逐段传感器叙述、observe/caption/diagnose分离 | 机械臂和夹爪词汇；净位移小不等于没运动；世界+x不能通用解释为身体前方；2026预印本不证明足式迁移 |
| [REFLECT论文](https://proceedings.mlr.press/v229/liu23g.html)、[代码](https://github.com/real-stanford/reflect) | 传感、事件、子目标分层组织；从摘要展开细节 | 已有计划/子目标、模拟真值感知；不能证明任意视频自动分期或低层控制诊断已解决 |
| [Vid2Seq论文](https://arxiv.org/abs/2302.14115)、[VidChapters代码](https://github.com/antoyang/VidChapters) | 时间段＋文本的输出结构、现成权重和离线视频基线 | 方法本体经过训练；使用已有权重才可免项目新增训练；一般视频/语音章节不等于机器人行为阶段 |
| [Suzuki等机器人描述研究](https://arxiv.org/html/2512.20876v1) | 图像＋关节/末端状态→局部描述→整体描述 | 22条、两个Robosuite操作任务；细粒度与文字相似度分段仍有问题；本轮未核实官方代码 |
| [VideoAgent](https://arxiv.org/abs/2403.10517) | 现成模型按问题补取信息 | 视频问答结果不等于机器人完整翻译准确率，稀疏取帧不能证明事件未发生 |
| [Generic Event Boundary Detection](https://openaccess.thecvf.com/content/ICCV2021/html/Shou_Generic_Event_Boundary_Detection_A_Benchmark_for_Event_Segmentation_ICCV_2021_paper.html) | 事件边界粒度与不确定性意识 | 视觉变化点不等于任务阶段真值 |

优先借实现思想和经过核实的基础模块，不整仓引入。采用源码前检查许可、依赖、维护状态、输入假设和版本；本轮未安装或运行上述工程。

### 14.1 本次审计新增核实的来源

| 来源 | 采用的设计思想 | 不支持的结论 |
|---|---|---|
| [Walk These Ways，§3.1](https://arxiv.org/html/2212.03238) | 接触相位、频率、摆动高度、机身姿态可形成行为描述维度 | 论文通过这些参数控制步态，没有验证任意轨迹到步态名称的逆分类器；三足同步不能直接认证pronk |
| [Cully等，Main Behavioral descriptor](https://arxiv.org/html/1407.3501) | 每腿接触时间占比是简洁、可聚合的行为描述量 | duty factor丢失相位和顺序；相同占比可以对应不同动作，不能单独代表完整步态 |
| [FActScore，§3.1与Limitations](https://arxiv.org/html/2305.14251) | 拆成原子主张，逐项核对来源 | 来源支持率不等于物理真值，也不测召回；自动估计器有错误且经过人工评估，不能推出无需真实语义审查 |
| [AHA，§3.1–3.2](https://arxiv.org/html/2410.00371) | 用已知扰动构造挑战案例，分开检查任务结果 | 预设故障类、模板、关键帧扰动和模型微调不是免训练未知失败保证；注入是什么不等于执行后出现什么 |

补充核实：[ProTracer表I/II](https://arxiv.org/html/2609.21369) 的失败类型与起点指标支持对视觉表现保持实测态度；它们不等于本计划的原子事实精确率，不能由其分类率直接证明“视觉事实精确率不可能达到95%”。其消融配置也不能随意简化为只删除某一种文字字段。

研究支撑的是组件选择与已知局限。本计划的足式数值卡片、未知组合能力和闭环收益仍需项目内评估。

## 15. 主要风险与处理

| 风险 | 可观察信号 | 处理 |
|---|---|---|
| 可选VLM过度使用任务常识 | 把要求当实现、忽略失败过程 | 首轮隐去结局标签；分开命令与观察；困难反例盲测 |
| 对象身份错配 | 视觉FL与数值FR矛盾 | 用稳定映射或相机投影核对；不明则降级到集合/未知 |
| 卡片摘要漏早期偏离 | 相同终态但描述分不清轨迹 | 保留时间线、关键事件索引；测必要事实召回 |
| 分块时重复并丢长状态 | 多次“抬起”而无持续区间 | open-state续接、重叠区核验、截断标记 |
| 代码事实被过度命名 | force、clearance被换成touch/collision | 受控语义映射与负例；不把schema validation当真值 |
| 预算不足形成盲区 | 请求窗口与实际receipt不一致 | 覆盖对账、partial状态、成本上限和缓存 |
| 参考样本太少 | 回退跨条件或误报飙升 | unavailable出口、显式回退版本、独立校准 |
| 目录或新任务靠手工特例通过 | 适配器含失败专用规则 | 审计适配器变更；严格区分迁移与新增能力 |
| 文档与实际作者输入脱节 | full报告很好但prompt只剩别名 | 以最终序列化请求验收，检查限制和反例保留 |
| 诊断误导改奖励 | 改动依赖不存在的历史输入或假原因 | runtime输入映射、竞争假说、固定协议验证 |
