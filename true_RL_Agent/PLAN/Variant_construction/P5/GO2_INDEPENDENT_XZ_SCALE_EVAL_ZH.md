## 结论

可以按两条独立轴缩放，但不应把两个比例混成一个统一尺寸系数：

- 竖直形态基准取根部到支撑端的默认净高度比：`0.422776 / 0.717680 = 0.589087`。
- 前向形态基准取腿链可达长度代理比：`0.4259998 / 0.6283703 = 0.677944`。
- 机器人层只提供上述形态事实；任务层用无量纲难度倍率决定考卷难度。有效比例为 `s_z = m_z × d_z`、`s_x = m_x × d_x`。

只按纯形态比例 `s_z=0.589087, s_x=0.677944` 时，现有 checkpoint 的三 seed `public_dev` 得分为 `J=0.8110`，但 `F_c1` 与 `F_c2` 仍均为 `1.0`，改进方向仍主要集中在标量 OOD。

本轮仅基于现有 checkpoint 的 eval，推荐后续协议讨论采用的困难度候选为：

```text
m_z = 0.589087        m_x = 0.677944
d_z = 1.324083        d_x = 1.0
s_z = 0.780000        s_x = 0.677944
```

该点在 `public_dev` 与一次性 `public_accept` 确认上分别得到 `J=0.7519` 与 `J=0.7670`，`J_ID=0.7847/0.7932`，没有换卷反转。它比现行只缩竖直方案保留更多 OOD 改进空间，同时 ID 没有塌陷。

这不是产品配置变更，也不是新 reference 资格化。本报告不采用任何新训练结果，没有 LLM/API 请求，也没有改动冻结 V2。曾误启动两次探索性重训，收到“只做现有 checkpoint eval”的边界后立即终止；未完成产物与临时训练脚本已删除，正式 checkpoint 未受影响。若以后采用，应新开协议版本，不能回写 V2。

## 形态依据与语义归属

| 量 | G1-37 | Go2-12 | Go2 / G1 |
| --- | ---: | ---: | ---: |
| 默认根部到支撑端中心净高度 | 0.717680 m | 0.422776 m | **0.589087** |
| 左右腿/四腿链长均值代理 | 0.628370 m | 0.426000 m | **0.677944** |

腿链代理由冻结运行时形态事实中的相邻刚体中心距离求和：G1 为 `hip_pitch → knee → ankle_roll`，Go2 为 `thigh → calf → foot`。它是前后可达尺度的低成本代理，不声称等于完整关节限位下的精确 FK 工作空间。

边界应保持为：

- RobotProfile：只声明 `m_z`、`m_x` 的形态测量及测量口径。
- Stair 任务协议：声明 `d_z`、`d_x`、训练/评测分布与成功语义。
- 竖直轴缩放台阶高度与 C2 起伏幅值；前向轴只缩放踏深及随实际几何派生的 progress goal。
- 不缩放横向宽度、世界尺寸、起始平台、顶部平台目标偏移与地板厚度，避免把落脚间距和侧向空间、出生上下文、顶部停留空间混成一个变量。

## 评测设计

所有运行均使用同一个现有 checkpoint、同一个 Go2 V2 `first_valid_top_arrival_latched` 成功语义、相同配对 seed 规则与相同 episode 时限。现行 checkpoint 的训练分布是 `s_z=0.589087, s_x=1.0`；因此这些结果只回答“现有策略对评测几何的响应”，不回答新训练分布重训后的表现。

筛选顺序：

1. `public_dev` 单 seed 运行 `4 × 4` 粗网格：`s_z∈{0.62,0.70,0.78,0.86}`，`s_x∈{0.70,0.80,0.90,1.00}`。
2. 固定形态前向比例 `s_x=0.677944`，对四个竖直点跑完整 3 seeds。
3. 依据 `public_dev` 预先选择 `0.78/0.677944`，只对该点运行一次 5-seed `public_accept`；未使用 sealed，也没有继续用 `public_accept` 调比例。

现行 V2 的跨机器人绝对锚点逻辑保持不变；`public_dev.c0_id_01` 未被派生缩放。控制时限完全不变，progress anchor 随真实踏深重新派生。

## 对 RSI 验收的解释

不能只因为 reference 总分高就人为压低它。当前 acceptance 的 headroom 规则会随 reference 降低而提高所需绝对增量：若把 `0.7670` 当新 reference，`0.2×(1−best)` 约为 `0.0466`；当前 `0.9344` 对应约 `0.0131`。因此本轮选择依据是“多个 OOD family 是否有分辨力且 ID 是否守住”，不是单纯追求低总分。

当前证据支持的最窄结论是：`0.78/0.677944` 比只缩竖直更适合做有改进余量的 eval 候选；是否正式升级协议仍需单独决策，不应在本轮修改 acceptance、训练分布或冻结 V2。
