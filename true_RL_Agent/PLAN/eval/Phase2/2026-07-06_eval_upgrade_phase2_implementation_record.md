# Eval Upgrade Phase2 Implementation Record

**Date:** 2026-07-06

**Scope:** Complete Phase2 checkpoint byte-level safety evidence and public-safe eval evidence projection without weakening Phase0/Phase1 boundaries.

## Result

Phase2 is implemented.

The eval path now requires a byte-level checkpoint safety report before a public eval result can be accepted. The report is generated by trusted eval code before `runner.load()`, validated by runner-owned code, cross-checked against the `EvalJobSpec` checkpoint hash, and projected only as public-safe structured evidence.

## Implemented Boundary

- Public eval summaries must include top-level `checkpoint_safety_report`.
- `SubprocessRunner` rejects summaries when the report is missing, failing, malformed, or not for the exact `EvalJobSpec.checkpoint.checksum`.
- `sealed_validation_gate` remains fail-closed and must also report `checkpoint_safety_status == "pass"`.
- Checkpoint report fields are normalized and public-safe: hashes, status, boolean existence/load flags, small error class/summary, and reason.
- Metrics cannot smuggle reserved safety fields; `checkpoint_safety_report`, `checkpoint_safety_status`, and `evidence_manifest` are only accepted at the runner-owned top-level summary boundary.
- The shared evidence artifact manifest is hash-only and task-agnostic. It supports future JSON/image/video/audio-style artifacts by `kind`, `mime_type`, `sha256`, `byte_size`, `visibility`, `producer`, and `public_projection_ref`, while rejecting raw payloads, paths, URLs, and URIs.

## Multimodal Extension Decision

Phase2 deliberately does not add raw multimodal feedback to public prompt or eval result surfaces.

The extension point is `EvidenceArtifact`: future multimodal feedback should first become trusted-runner-owned artifacts with normalized metadata, stable hash, byte size, MIME type, visibility, and a public projection reference. Public prompt layers may consume a bounded projection or summary later, but must not consume local paths, remote URLs, raw base64/data URIs, or task-private payloads directly.

This keeps the common layer modality-aware but task-agnostic. Task-specific semantics such as push/fall/motion labels still belong in task adapters and public metrics, not in runner or safety primitives.

## Post-Review Hardening

Review findings after the initial Phase2 implementation identified three real boundary issues, all fixed in the same Phase2 scope:

- Eval checkpoint binding now updates both the checkpoint URI/path and `--checkpoint-sha256` after training returns the actual runner-sealed checkpoint. This prevents true eval from building a safety report against the old planned hash.
- Checkpoint report expected-hash verification is centralized in `validate_checkpoint_safety_report(..., expected_checkpoint_hash=...)`. `SubprocessRunner` and `build_trusted_eval_seal()` now call the same helper instead of maintaining separate partial checks.
- Evidence artifact manifest validation now checks required fields before constructing `EvidenceArtifact`, so malformed manifests fail with `ValueError` and runner ingestion wraps them as `RunnerExecutionError` instead of leaking raw `KeyError`.
- Evidence artifact byte sizes now accept only non-boolean integers or decimal integer strings. Invalid values such as `None`, lists, objects, booleans, floats, and non-integer strings fail as `ValueError` in both direct `EvidenceArtifact` construction and manifest ingestion, so `SubprocessRunner` can continue wrapping validator failures uniformly.
